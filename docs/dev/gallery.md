# 图库（2026-10-17）

> 用户要的：一个通用的图库。模型模块能配默认的 embedding 模型；图库有 HTTP 接口和 MCP，能上传、比对、检索；字段是图片、文本（必须是 JSON）、标签（必须是数组）。页面打开就是满屏的图片，能上传图片以图搜图、按标签找、按 JSON 字段找，能在页面上传图。
> 接口怎么调见 `docs/dev/api.md` 第 13 节。这份写为什么这么做、实测数据和限制。

## 1. 用户定的（2026-10-17）

| 问题 | 定的 |
|---|---|
| embedding 模型 | 能在模型页换；先用推荐的 `google/gemini-embedding-2` |
| 向量存哪 | 数据库镜像换成带 pgvector 的（「反正是容器」） |
| 「比对」 | 1 对 1：两张图给相似度，按阈值判断是不是同一张 / 同款；「检索」是 1 对多 |
| JSON 怎么检索 | 接口三种都支持（包含匹配、字段条件、关键词）；页面一个输入框：写 JSON 按包含匹配，写普通文字按关键词 |
| 外部调用 | v1 就要，外部可以写（API 密钥） |
| 权限 | 都能看、搜、传；改、删只有上传的人和主管；agent 能改不能删 |
| 几个图库 | 一个，用标签分组 |

其余按当时的建议：传图后马上算向量；换模型后台全部重算；一模一样的文件不重复存；页面上图片墙 + 右边抽屉。

## 2. 结构

```text
页面（tRPC gallery.*，传图和上传一张图来搜走 HTTP）
HTTP 接口 /api/gallery/*  ──┐
MCP /api/gallery/mcp       ──┼──> gallery/service.ts ──> gallery_images（文本 jsonb、标签 text[]）
agent 的「图库」工具组      ──┘          │                 gallery_embeddings（vector(1024)，按模型分开）
                                         │                 files（原图、缩略图，kind = gallery / gallery_thumb）
                                         └──> gallery/embed.ts ──> OpenRouter POST /embeddings
后台补算（API 进程，gallery/background.ts）：换了模型、传图时模型调用失败
```

- 代码在 `apps/server/src/gallery/`：`service.ts`（全部业务逻辑）、`embed.ts`（调模型）、`images.ts`（sharp：认格式、缩略图、给模型的图、读图片引用）、`routes.ts`（HTTP）、`mcp.ts`、`tools.ts`（agent 工具组）、`background.ts`、`errors.ts`。schema 在 `packages/shared/src/gallery.ts`，四种入口共用一份校验。
- 平台通用：代码里没有任何业务概念。文本里放什么、标签怎么起，都是用的人自己定。

## 3. 几个做法

- **向量统一 1024 维**：OpenRouter 上能处理图片的 3 个 embedding 模型都支持 `dimensions=1024`（实测），换模型表结构不变，HNSW 索引不用重建。返回的维数不对就报错，让人换模型。
- **检索 = 先筛再排**：标签用 GIN（`@>` / `&&`），JSON 包含匹配用 jsonb_path_ops GIN；向量用 HNSW 余弦索引，带筛选条件时开 `hnsw.iterative_scan = relaxed_order`（pgvector 0.8 起），结果按分数重新排一遍。
- **给模型的图统一预处理**：转正、长边 1024、透明处垫白、JPEG 90。存图和搜图都过这一道，同一张图不管原来什么格式、多大，向量尽量一样。
- **换模型**：新旧向量并存（主键 `(image_id, model_id)`）。检索、比对用「向量最全」的那个模型（`searchModel`），新模型没算完之前一直用旧的；新模型一张不落都算完了才删旧向量。后台一批 8 张，失败的隔 10 分钟再试，多进程用事务级 advisory lock。
- **去重**：sha256 唯一。重复传返回已有的那条，不改它的文本和标签（要改用 PATCH / `gallery_update`）。同时传同一张时唯一索引挡住后一个，删掉它刚存的文件。
- **传图时模型挂了**：图照样存下来（`embedded: false`），原因记在 `embed_error`，统计和页面上看得到，后台重试。
- **文件**：原图和缩略图是 `files` 里的行，不挂到 session 上（不然会出现在那次运行的附件和产物里），删图时一起删。

## 4. 阈值标定（2026-10-17，真模型）

15 张 Wikimedia Commons 的照片（猫、小猫、几种狗、苹果、番茄、橙子、香蕉、一串香蕉、几种杯子、自行车、向日葵），前 8 张各做 7 种变体，预处理和线上一样。余弦相似度：

| | gemini-embedding-2 | voyage-multimodal-3.5 |
|---|---|---|
| 同一张 · 缩到三分之一 | 最低 0.964 / 平均 0.973 | 最低 0.724 / 平均 0.863 |
| 同一张 · JPEG 质量 40 | 0.898 / 0.960 | 0.866 / 0.979 |
| 同一张 · 裁掉 5% 边 | 0.983 / 0.987 | 0.953 / 0.976 |
| 同一张 · 调亮 15% | 0.982 / 0.990 | 0.980 / 0.990 |
| 同一张 · 大字水印 | 0.844 / 0.913 | 0.796 / 0.897 |
| 同一张 · 只留中间 70% | 0.945 / 0.971 | 0.818 / 0.906 |
| 同一张 · 左右镜像 | 0.956 / 0.984 | 0.863 / 0.973 |
| 同类不同图（猫和小猫、香蕉和一串香蕉……） | 0.678 / 0.795，最高 0.904 | 0.337 / 0.535，最高 0.834 |
| 完全不同 | 0.579 / 0.689，最高 0.815 | 0.038 / 0.229，最高 0.640 |

- 定的默认阈值（`gallerySameThreshold`）：gemini 0.9、voyage 0.8，没标定过的模型 0.9。调用时可以自己传 `threshold`。
- **限制**：embedding 是「语义像不像」，不是「是不是同一个文件」。轻微改动（改大小、重压缩、小裁边、调亮、镜像）gemini 都 ≥ 0.945，稳；改得很重（大水印 + 裁掉 15% 边 + JPEG 70）实测 0.83，排第一但到不了 0.9，而同类不同图最高能到 0.90。所以这种情况只看阈值分不开，要看排名（第一名和第二名差多少）或者人看一眼。
- `nvidia/llama-nemotron-embed-vl-1b-v2:free`：免费版两次都在一批 8 张图时 60 秒超时（上游 504），不建议当默认模型。
- gemini 的分数整体偏高（完全不同的图也有 0.6～0.7），页面上的百分比不要按「70% = 七成像」理解，看排序。

真模型端到端（同一天）：按描述找「一只猫」「黄色的水果」「一杯咖啡」「a dog lying on the grass」「自行车」第一名都对；JSON 条件、标签 + 描述组合都对；MCP 用 `@ai-sdk/mcp` 的 HTTP 客户端列工具、检索、用网址比对都通；agent（claude-haiku-5.5）用「图库」工具组以图搜图、比对、传图都通，一次运行 $0.002。

## 6. 部署和升级

- 数据库镜像换成 `docker.io/pgvector/pgvector:0.8.7-pg18-trixie`：Postgres 18.6、Debian 13，和原来的 `postgres:18` 同一版本、同一个系统，**数据卷直接能用**。`scripts/pod.sh up` 会按 `deploy/pod.yaml` 重建 pod，用上新镜像；服务器的 Quadlet（`deploy/quadlet/heyagent.yaml`）同样已经改好。迁移 0014 里建 `vector` 扩展。
- 开发库：`scripts/dev-db.sh up` 发现容器用的是旧镜像，会删掉旧容器、用新镜像重建（数据卷保留）。**没换镜像的开发库跑迁移 0014 会失败**（`extension "vector" is not available`）。
- 升级前建的环境：API 启动时发现一个 embedding 模型都没有，会刷新一次 OpenRouter 的模型列表（公开接口，不花钱），把图库的模型设成 gemini-embedding-2。
- 新依赖：`sharp` 0.35.5（缩略图、预处理；Linux x64 用预编译的 libvips，不用装系统包）、`@modelcontextprotocol/server` 2.3.1（MCP 服务端，只依赖 zod）。
- 规模：向量走 HNSW 近似索引，按设计能撑到很多张，但大规模没有实测过（开发时只测了几十张）。原图存在文件卷里，和其他文件一起备份。
