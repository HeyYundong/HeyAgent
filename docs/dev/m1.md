# M1：session 引擎 + 工具 + 控制台写操作（开发说明）

## 先读

- `docs/v1-plan.md`：重点看 2.0、2.2、2.3.1、2.3.5、2.3.7、2.4、2.5。

## 背景（用户 2026-10-17 的要求）

- 要一个真正能跑的 agent 平台，不要演示数据，也不要演示案例。
- 任务、记忆、技能、规则、工具等全部由用户自己在控制台里配。
- 正式环境从空白开始：只有一个管理员账号和系统自带的东西。
- 原型的演示数据只留给测试用（`pnpm db:seed`），正式环境不灌。

## M1 做完后应该能做到

1. 控制台里所有配置都能新建、修改、删除或停用：任务、记忆、技能、规则、工具（HTTP 接口、MCP 服务器、密钥）、浏览器配置、模型、人加的待办、用户、全局设置。
2. 任务真的能跑：
   - agent 用 OpenRouter 上的模型执行；能调内置工具、HTTP 工具和 MCP 工具；
   - 要等时挂起，等到了继续**同一个 session**；
   - 支持定时（cron）、人加的待办、要人办的事、通知、附件和产物、花费统计和上限；
   - 服务重启不丢进度。
3. 不在 M1 做的：
   - 浏览器执行（M2，只把工具接口留好）；
   - 规则的翻译和执行、检查点自动同步、三方验收（M3，引擎里把 4 个阶段的钩子留好）。

## P1：引擎（后端）

### 1. worker 进程

- 入口 `apps/server/src/worker.ts`：连数据库、启动 pg-boss、注册各类任务、优雅退出。
- 队列：
  - `session.run`：执行或继续一个 session。用 `singletonKey = sessionId` 保证同一个 session 同时只有一个在跑。
  - `session.wake`：到点叫醒。
  - `session.remind`：兜底期限到了，提醒负责人。
  - `todo.fire`：人加的待办到点。
  - 任务的 cron：按任务 id 注册 schedule，时区 `Asia/Shanghai`。
- API 进程也要能发任务（启动时初始化 pg-boss，但不注册 worker）。

### 2. `engine/api.ts` 的真实实现

- `startSession`：
  - 新建 session（状态「执行中」）；
  - 把任务当时的配置做成快照存进 session（步骤、目标、检查点、选用的记忆、技能、工具、规则、模型），任务以后再改，不影响已经开始的运行；
  - 按任务的检查点建好 `checkpoints` 行；
  - 关联附件；
  - 排进 `session.run`。
- `syncTaskSchedule`：任务启用并且有 cron 就注册或更新 schedule；停用、删除、去掉 cron 就取消。
- `syncTodo`：待办的定时、cron、事件（加兜底期限）同步成相应的任务或等待。
  - 待办触发时：如果它的任务有挂起中的 session，就用待办标题作为「等到了什么」继续这个 session；否则用待办标题作为附加说明，新开一次运行。

### 3. agent 循环 `engine/loop.ts`

- 读 session 的快照和完整消息历史，拼系统提示：任务、目标、步骤、检查点、选用的记忆、技能目录（只有名字和一句话）、工具说明。
- 调模型，然后循环：
  - 工具定义**不带 execute**，模型提出调用后交给工具网关；
  - 每次模型调用、每次工具调用都写 `session_events` 和 `session_messages`，然后 NOTIFY；
  - 直到模型给出最终答复、某个工具让 session 挂起、触发上限，或者出错。
- 模型给出最终答复 = 说做完了。M1 直接标「已完成」，但要留出 M3 验收的入口（`engine/hooks.ts` 的 `onFinish`）。
- **4 个阶段的钩子** `engine/hooks.ts`：运行开始、调工具前、调工具后、说做完了。
  - M1 只做两件内置的检查：工具必须在本任务允许的范围里；参数必须通过 schema 校验。
  - 留好接口，M3 往里加规则。
- 上限，都存在 `settings` 表里：
  - 单个 session 的花费上限，默认 2 美元；
  - 最多步数，默认 100；
  - 超过时不报错，生成一件「要人办的事」：「花费到了上限，要不要继续」，session 挂起等人。
- 出错：模型或网络错误重试 3 次（退避）；还不行就标「失败」，写清原因。
- 单个 pg-boss 任务不要跑太久：一次跑超过 30 分钟就主动排一个新的 `session.run`，自己退出。
- 大块的工具输出：给模型的只放截断后的内容加文件引用，全文存成文件。

### 4. 模型层 `engine/model.ts`

- 用 OpenRouter provider。key 从 `model_providers` 和 `secrets` 解密得到：P2 负责模型页的写入，P1 负责读。
- 外面包一层很薄的接口，方便以后换线路或直连厂商。
- **用量和花费**：每次调用记下 token 和花费（OpenRouter 返回的 cost，具体怎么开启以 provider 文档为准），累计到 session。
- Anthropic 的模型要开 prompt caching。
- 默认不传 temperature、top_p。
- Ollama 先不接：内网没有。provider 种类保留，调用时报「未配置」。

### 5. 工具网关和工具

**内置工具**，全部通用，代码里不出现业务。

| 名字 | 做什么 |
|---|---|
| `checkpoint.mark` | 勾检查点，或标为跳过；跳过必须写理由 |
| `session.wait` | `until`（时间）、`event`（事件名）至少给一个。只等事件时自动加兜底期限：`settings` 里的天数，默认 7 天 |
| `ask.human` | 生成一件要人办的事（问题、类型、给谁：默认任务负责人、可选项），session 进入「等人处理」 |
| `skill.load` | 读出本任务选用的技能的 SKILL.md 全文 |
| `memory.propose` | 提议一条记忆，状态是「待审核」 |
| `skill.propose` | 提议修改某个技能，生成一条待审核的修改建议 |
| `notify.staff` | 站内通知负责人或指定的人，并按设置推送到 webhook 通知渠道 |
| `file.save` | 产出文件（csv、md、json、txt 等文本格式），挂到这个 session 上，界面里能看能下载 |
| `file.read` | 读附件：文本直接返回内容，图片按多模态内容交给模型 |

- `checkpoint.mark`、`session.wait`、`ask.human` 每个任务都自带，其余按任务选用。
- 内置工具的说明和输入 schema 写在代码里。启动时把它们同步进 `tools` 表，`source = builtin`，不能删、不能改。

**HTTP 工具**
- 照工具配置里的模板发请求：`{参数}` 由模型填，`{{名字}}` 执行时从 `secrets` 解密替换，模型永远看不到原文。
- 返回内容里如果出现密钥原文，换成 `[已隐藏]`。
- 有超时和返回大小上限。

**MCP 工具**
- 用 `@ai-sdk/mcp` 连配置好的服务器：stdio 命令（环境变量里的 `{{名字}}` 从 secrets 替换），或者 HTTP 地址加请求头。
- 本任务选用的工具才给模型。
- session 内复用连接，挂起和结束时断开。
- 在 `engine-router.ts` 里提供「连接并读取工具」接口，给工具页用。

### 6. 挂起和继续 `engine/waits.ts`

照方案 2.3.5：
- **挂起**：在同一个事务里做三件事：session 改状态、写一条 `session_waits`、排定时任务。
- **继续**：到点、事件到了、人处理完、人点「立即继续」，都走同一个入口。入口用「只有还是等待中才改」的条件更新，谁先到谁生效。
- **兜底期限**：到期只提醒负责人，不自动继续。
- **继续时**：从库里读回消息，追加一条「等到了什么」，接着跑。同一个 session id。

### 7. 其他

- **通知**：新建 `notifications` 表（给谁、标题、内容、链接、已读时间）。
  - webhook 渠道从 `settings` 的 `notify.channels` 读：`[{ id, name, kind: "feishu" | "wecom" | "webhook", urlSecretName, enabled }]`。
  - 飞书、企业微信按它们群机器人的文本消息格式发；`webhook` 发通用 JSON。
  - P2 负责设置页的写入。
- **文件**：
  - 存储接口加本地磁盘实现，目录从 `HEYAGENT_FILES_DIR` 读；
  - 上传：Hono 路由 `POST /api/files`，要求登录，有大小上限；
  - 下载：`GET /api/files/:id`，要求登录；
  - `files` 表加 `task_id`：任务附件跨运行一直有效，session 附件和产物只属于这次运行。
- **外部事件**：
  - `POST /api/events`，用 `settings` 里的令牌鉴权，内容 `{ event, data }`，按事件名匹配等待中的 session 和待办；
  - 控制台也能手动触发：engine 接口 `fireEvent`。
- **审计**：处理要人办的事、立即运行、取消这类操作写 `audit_events`。
- **engine-router 的接口**：
  - `runNow`（任务 id、附件 id）、`cancel`、`resumeNow`、`resolveHumanItem`（批准 / 拒绝 / 已处理，加备注；处理完就继续对应的 session）、`fireEvent`；
  - 附件：`attachToTask`、`detachFromTask`；`sessionFiles`（附件和产物列表）；
  - `listMcpServerTools`；
  - 通知：`notifications.list`、`notifications.markRead`；
  - 权限都用 shared 的 `can()`。
- **worker 镜像**：`deploy/worker.Containerfile`，以 `localhost/heyagent-browser-base:m0` 为底（M2 要用 Chrome），装上 server 的代码，入口是 worker。用 `podman build` 实际构建一次。

### P1 验收

- `pnpm typecheck`、`pnpm lint`、`pnpm test` 全过。
- 引擎测试用假模型，至少覆盖下面这些场景：
  1. 调内置工具再结束；
  2. 调 HTTP 工具：密钥被替换，返回里的密钥被隐藏；
  3. MCP 工具：起一个本地测试 MCP 服务器；
  4. `session.wait` 挂起，到点叫醒后继续的是同一个 session，消息历史完整；
  5. 只等事件：事件到了继续；兜底期限到了只提醒、不继续；
  6. `ask.human`：处理完继续；
  7. 时间和事件同时等：先到先继续，后到的不起作用；
  8. 超过花费上限转人工；
  9. worker 进程中途被杀掉，重启后继续；
  10. cron 触发新 session；
  11. 待办触发：继续挂起中的 session，没有挂起的就新开运行；
  12. `file.save` 和 `file.read`。
- 用真模型（`anthropic/claude-haiku-5.5`）跑一次端到端：建任务 → 立即运行 → 调一个内置工具 → `session.wait` 1 分钟 → 继续 → 完成。汇报里写花了多少钱。
- worker 镜像能构建。

## P2：配置读写（后端 + 前端）

### 1. 写接口

在 `router.ts` 现有的命名空间里加 mutation。输入用 zod 校验（schema 写在 `shared/config.ts`），权限用 `can()`，每次写都记 `audit_events`。

| 对象 | 要做的写操作 |
|---|---|
| 任务 | 新建、修改、启停、删除。有运行记录的不能删，只能停用，提示写清楚。保存后调 `syncTaskSchedule`。「目标」必填（原型已定）。执行模型和验收模型不许是同一家：用 shared 的 `sameFamily`，任务没单独选时按默认模型判断 |
| 记忆 | 新建、修改、批准、拒绝、归档、删除 |
| 技能 | 新建、改 SKILL.md（每次保存出一个新版本，写进 `skill_versions`）、发布、停用；agent 提的修改建议：批准（生成新版本）、拒绝 |
| 规则 | 新建、修改、删除：名称、触发条件（一句话）、命中后怎么办、会调用的工具。翻译成程序能判断的条件是 M3 的事，M1 只存文字 |
| HTTP 工具 | 新建、修改、删除；粘贴 cURL 导入（原型 `tools/curl.ts`、`secrets.ts` 的逻辑）。**服务端也要检查**：URL、请求头、请求体里出现明文密钥就拒绝保存，提示改成 `{{名字}}` |
| 密钥 | 新建、改值、删除；值只加密存，任何接口都不返回原文 |
| MCP 服务器 | 新建、修改、删除（stdio 命令加参数加环境变量，或 HTTP 地址加请求头，密钥一律用 `{{名字}}`）。「连接并读取工具」由 P3 接 P1 的接口 |
| 浏览器 | Chrome 配置（代理，密码进 secrets）、平台账号（平台、账号、并发上限、登录探测网址）的新建、修改、删除。M2 才真正用 |
| 模型 | OpenRouter 的地址和 key（进 secrets）；从 OpenRouter 公开的 `/api/v1/models` 刷新模型列表（名字、上下文、价格、能不能看图、能不能调工具）；三个角色的默认模型（验收不许和执行同一家）；测试连接 |
| 人加的待办 | 新建、修改、删除；保存后调 `syncTodo` |
| 用户 | 管理员专用：列表、新建（邮箱、名字、职位、角色、初始密码）、修改、停用和启用、重置密码。用 better-auth admin 插件的服务端接口 |
| 自己 | 改自己的密码 |
| 全局设置 | 管理员专用：session 花费上限、最多步数、事件兜底天数、外部事件令牌、通知渠道（`notify.channels`，webhook 地址进 secrets） |

**删除**：照原型，「没人用的规则或工具删除时不弹确认，toast 里可以撤销」。正在被使用的不能删，提示被哪些任务用着。

### 2. 空白正式环境的初始化

- 写成 `apps/server/src/bootstrap/`，API 启动时执行，可以重复执行。
- 没有任何用户时，建管理员 `admin@heyagent.local`：
  - 随机生成初始密码，写进 `HEYAGENT_ADMIN_PASSWORD_FILE` 指向的文件（开发时是 `.dev/admin-password`，权限 600）；
  - 不打印到日志。
- 写入设置的默认值。
- 环境变量里有 `OPENROUTER_API_KEY` 并且还没配过 OpenRouter 时：
  - 建 OpenRouter 服务，key 加密存进 secrets；
  - 刷新模型列表；
  - 默认模型：执行 `anthropic/claude-sonnet-5.5`，规划 `anthropic/claude-opus-5.5`，验收 `google/gemini-3.8-flash`。
