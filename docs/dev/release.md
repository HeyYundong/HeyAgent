# 上线准备（开发说明）

## 先读

- `docs/dev/conventions.md`
- `docs/v1-plan.md` 2.5（部署）、6.2 第 11 条（主密钥）、第 18 条（v1 先用 HTTP）
- `scripts/pod.sh`、`deploy/pod.yaml`
- `docs/dev/api.md`

## 目标

- 把开发机上验证过的整套服务，变成**能在正式服务器上长期运行、能备份恢复、能升级**的部署。
- 写好给管理员看的运维说明，和给用户看的使用说明。
- 最后留下一个干净的空白环境。

## 1. 正式服务器的部署（Podman 4.4 以上 + Quadlet）

- **目标环境**：Ubuntu 24.04，自带 Podman 4.9；一个普通用户 rootless 运行；`loginctl enable-linger`，保证没人登录时服务也在跑。
- **`deploy/quadlet/`**：用 Quadlet 管理那份 pod 描述，可以用 `.kube` 单元引用 kube YAML，加上需要的卷。要求：
  - 开机自启，挂了自动重启；
  - 端口默认 8080（普通用户不能占 80；要用 80 由管理员自己改系统设置，写进运维说明）。
- **密钥用 Podman secret**（4.x 的 `kube play` 支持 Kubernetes Secret 引用 Podman secret）：主密钥、OpenRouter key、数据库密码、登录签名密钥。不放 configmap，不写在命令行参数里。
- **`scripts/server-install.sh`**：服务器上第一次安装用，脚本**可以重复执行**。依次做这些事：
  1. 检查 Podman 版本，必须在 4.4 以上；
  2. 构建镜像；
  3. 创建 secret：从交互输入或一个临时文件读，用完提示删掉这个文件；主密钥没有就生成，并提示马上离线备份；
  4. 装好 Quadlet 文件，`systemctl --user daemon-reload` 后启动；
  5. 等健康检查通过，提示管理员初始密码在哪里。
- **`scripts/deploy.sh`**：升级用。拉代码 → 构建镜像（保留上一版的 tag）→ 重启服务（api 启动时会自动迁移）→ 健康检查；失败时提示怎么退回上一版。
- **开发机验证不了 Quadlet**（Podman 3.4.4 太旧）。照 Podman 官方文档写，能在开发机上验证的部分要验证：kube YAML 的语法、脚本逻辑。
- **开发机照旧用 `scripts/pod.sh`**。

## 2. 备份和恢复

- **`scripts/backup.sh`**：
  - 数据库用 `pg_dump` 的 custom 格式；
  - 文件卷打成 tar；
  - 都放进备份目录（默认 `~/heyagent-backups`，可配置），保留 14 天；
  - **主密钥不进这个目录**：它要离线保管，否则备份一泄露，密文就都能解开。
- **定时备份**：`deploy/systemd/heyagent-backup.service` 和 `.timer`，systemd 用户定时器，每天凌晨 3 点。
- **`scripts/restore.sh`**：从某一次备份恢复到一个**新的空环境**，需要同一把主密钥。
- **恢复演练**：在开发机上真跑一遍：
  1. 往空白环境里建点数据；
  2. 备份；
  3. 在另一套临时 pod 或临时库上恢复；
  4. 核对用户、任务、密钥（能解密）、文件都在；
  5. 清理临时环境。

## 3. 主密钥轮换

- `pnpm kek:rotate`（或者脚本）做两件事：
  1. 往 KEK 文件里加一把新版本的密钥；
  2. 把库里所有密文的 DEK 用新密钥重新包一遍（`lib/crypto.ts` 的 `rewrap`）。数据本身不重新加密。
- 旧密钥要等确认全部换完才能删。
- 写测试，在开发机上演练一次。

## 4. 文档

- **`docs/ops.md`**：运维说明，给管理员看的，中文，照用户的写作风格，要短、直接，包括：
  - 服务器要求；
  - 第一次安装；
  - 管理员初始密码在哪、怎么改；
  - 怎么建同事的账号；
  - 怎么配 OpenRouter（以及换 key）；
  - 升级、备份、恢复、主密钥轮换；
  - 看日志、常见问题；
  - 安全提醒：只在内网开放；v1 用 HTTP；开发时用过的 OpenRouter key 在聊天里出现过，正式用前换一个新的并设额度上限。
- **`docs/guide.md`**：使用说明，给配置的人看的。
  - 讲清楚怎么在控制台里搭一个 agent 任务：任务（一句话、步骤、等待、检查点、目标）、记忆、技能（SKILL.md）、规则（一句话写，系统翻译后确认）、工具（HTTP 接口 / cURL 导入 / 密钥、MCP、内置、浏览器）、浏览器配置（Chrome、代理、平台和域名、账号、打开 Chrome 登录）、模型、待办、session；
  - 每样东西写「是什么、在哪配、注意什么」；
  - **不写任何业务示例**，用通用的说法，例如「要调的接口」「要登录的网站」。

## 5. 最后的验收和交付

- 在主目录用 `scripts/pod.sh reset` 再 `up`，留下空白环境。管理员密码在主目录 `.dev/admin-password`。
- typecheck、lint、build、test、真浏览器测试全过。
- 在空白环境上走一遍「第一次使用」：管理员登录 → 改密码 → 建一个员工账号。只核对页面能用，不留数据；做完再重置一次。
