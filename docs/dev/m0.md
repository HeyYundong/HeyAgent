# M0：地基 + 风险实测（开发说明）

先读：`docs/dev/conventions.md`（约定，必须遵守）、`docs/v1-plan.md`（方案，重点 2.1、2.4、2.3.6、第 3 节）、`docs/ui-rules.md`（做前端时）。

M0 的目标（方案第 4 节）：
- 仓库建好；按方案 2.4 建表，原型的假数据灌进库里；
- 账号登录，分主管和员工两种角色；
- 控制台改成读真实数据，这一步先只读；
- 用 Podman 在开发机上起整套；
- 实测浏览器方案里最没把握的远程画面。

M0 分 3 个包。包 1 和包 2 同时做，包 3 等包 1 做完再开始。

**契约**：原型页面现在读的是 `design/prototype/src/mock/shared.ts` 和各页面的 `pages/*/data.ts`。这些类型的字段名和含义就是前后端的契约。后端照着它返回数据，前端改造时就只是把「读 mock」换成「调接口」。原型的类型和字段已经和用户对齐过，不要随意改名、改含义。确实要改的，写进汇报。

## 包 1：后端地基

负责：仓库根目录的配置、`packages/shared`、`apps/server`、`scripts/dev-db.sh`、`scripts/dev-kek.sh`、`deploy/api.Containerfile`、`docs/dev/m0-api.md`。**不要碰** `apps/web`、`spikes/`、`deploy/browser-base.Containerfile`。

1. **仓库根目录**
   - pnpm workspace（`apps/*`、`packages/*`），根目录 `package.json` 的脚本：`dev`、`build`、`typecheck`、`lint`、`test`、`db:migrate`、`db:seed`。
   - `tsconfig.base.json`、prettier 配置（沿用原型的）。
   - `.gitignore`：`node_modules`、`dist`、`.env`、`.dev/`、`design/`、各类缓存。
   - `.env.example`。
2. **`packages/shared`（包名 `@heyagent/shared`）**
   - 把 `mock/shared.ts` 和各 `pages/*/data.ts` 里的领域类型改写成 zod schema，用 `z.infer` 导出 TS 类型。中文标签（如 `runStatusLabel`）一并带过来。
   - 纯函数一起搬过来，改成「数据作为参数传入」：`modelFamily`、`sameFamily`、`triggerText`、看板分列（`boardCards`）、`needsMeCount`、`toolIdsOfTask`、`tasksUsing`、`lib/checkpoint.ts` 的检查点识别等。
   - **不搬** mock 数据数组。
   - 写单元测试，其中要有 `modelFamily("ollama/llama3.3:70b")` 认成 Meta、`ollama/qwen3:32b` 认成阿里通义这两条回归。
3. **数据库（Drizzle + PostgreSQL 18）**
   - 建表：方案 2.4 列的全部表，再加 better-auth 自己要的表。表结构要照顾到 M1～M4：
     - `sessions` 有 `parent_session_id`；
     - `session_events` 按 `(session_id, seq)` 只追加；
     - `session_messages` 先建好；
     - `session_waits`、`account_leases` 照方案 2.3.5；
     - `secrets`、`browser_vaults`、模型服务的 API key 只存密文；
     - 规则的「翻译后的触发条件」先留成可空的 jsonb；
     - 任务和记忆、技能、工具、规则之间用关联表。
   - 主键用原型那样可读的文本 id（`T-1024`、`R-1024-1`、`m-009`……），因为界面上直接显示这些 id；新 id 的生成规则写清楚，M1 再用。
   - 时间一律 `timestamptz`。
   - 迁移用 drizzle-kit 生成 SQL 文件并提交；`pnpm db:migrate` 执行。
4. **种子数据（`pnpm db:seed`）**
   - 把原型的假数据灌进库，包括 `mock/shared.ts` 和各页面 `data.ts` 里页面要显示的内容（技能的 SKILL.md、记忆的证据、接口的请求模板等）。**`pages/learn/` 不灌**，它是讲解页，前端自己留一份演示数据。
   - 时间转换成以灌数据那一刻为基准的绝对时间，保持原型里「几分钟前、昨天」的相对关系。
   - 可以重复执行：每次先清掉演示数据再灌。
   - **模型数据按方案 2.3.4 的 B 路线改**，内网没有 Ollama：
     - OpenRouter 的模型：`anthropic/claude-opus-5.5`（$4 / $20）、`anthropic/claude-sonnet-5.5`（$2 / $10）、`anthropic/claude-haiku-5.5`（$0.10 / $0.50）、`google/gemini-3.8-flash`（$0.83 / $4.12，能看图）、`qwen/qwen3.8-flash`（$0.15 / $0.47，能看图）。价格单位是每百万 token，2026-10-17 从 OpenRouter 模型列表取的。
     - id 沿用原型的写法，例如 `openrouter/anthropic/claude-sonnet-5.5`。
     - 默认模型：执行 `claude-sonnet-5.5`，规划 `claude-opus-5.5`，验收 `google/gemini-3.8-flash`。
     - Ollama 服务保留一条，状态是「未配置」：地址为空，没有模型。原型任务里用 `ollama/qwen3:32b` 验收的，改成 gemini-3.8-flash。
   - 密钥和登录态用假值，经第 7 步的加密函数加密后再存。
   - 用户：原型 `staff` 里的 5 个人。邮箱用拼音，例如 `linzhou@heyagent.local`。密码取 `SEED_PASSWORD`（`.env.example` 里给开发默认值）。`isAdmin` 对应主管角色。
5. **API（Hono + tRPC，端口 3100）**
   - 路由：`/api/trpc/*`、`/api/auth/*`（better-auth）、`/api/health`。
   - **逐个看原型的每个页面文件**，列出它读了哪些数据，保证每样都有接口能拿到。全部只读，都要求登录。
   - 把「页面 → 接口 → 返回形状」写成 `docs/dev/m0-api.md`，包 3 照着改前端。
   - 返回里密钥只给掩码，登录态只给状态，绝不返回原文。为这一条写测试。
   - 实时推送：tRPC 订阅走 SSE，用 `tracked(id)` 支持断线续传。数据源是 PostgreSQL 的 `LISTEN/NOTIFY`，频道 `heyagent_changes`，内容是 `{ table, id }`。再给一个开发用命令 `pnpm dev:notify <table> <id>`，方便演示。
6. **登录和权限**
   - better-auth 1.7.10：邮箱 + 密码，加 admin 插件。关闭公开注册，账号只能由管理员建；配置项名字以安装的版本里的类型定义为准，别凭印象写。
   - 权限函数 `can(user, action, resource)`：员工能看全部，只能操作自己负责的或分给自己的；主管全部能操作。M0 没有写操作，但函数和测试先做好。
7. **加密** `apps/server/src/lib/crypto.ts`
   - 方案第 3 节的信封加密：每条数据一个随机 DEK，用 AES-256-GCM 加密；DEK 再由 KEK 包起来；AAD 绑定 `表名:行id:版本号`；KEK 带版本号，以后可以轮换。
   - KEK 从 `HEYAGENT_KEK_FILE` 指向的文件读。`scripts/dev-kek.sh` 生成 `.dev/kek`。
   - 写测试：能解回原文；换行 id 或改版本号后解不开；KEK 不对时解不开。
8. **开发数据库** `scripts/dev-db.sh up|down|reset|psql`
   - rootless Podman 起 `docker.io/library/postgres:18`，命名卷 `heyagent-pgdata`，只绑 `127.0.0.1:5432`。
   - 建 `heyagent` 和 `heyagent_test` 两个库。
9. **镜像** `deploy/api.Containerfile`
   - 多阶段：pnpm 装依赖、构建 shared 和 server；运行阶段用 Node 24。
   - 启动时先执行迁移。
   - 用 `podman build` 实际构建一次。

**验收（汇报里贴命令和关键输出）**：
- 空库上 `scripts/dev-db.sh up && pnpm db:migrate && pnpm db:seed` 成功；再执行一次 seed 也成功。
- 库里任务、session、记忆、技能、规则、工具的数量和原型 mock 一致（模型按上面改过的为准）。
- `pnpm typecheck`、`pnpm lint`、`pnpm test` 全过。
- 起 API 后，用 curl 以林舟、王悦分别登录，调几个 tRPC 查询能拿到数据；不登录调用返回 401。
- `podman build -f deploy/api.Containerfile .` 成功。

## 包 2：浏览器基础镜像 + 远程画面实测

负责：`deploy/browser-base.Containerfile`、`spikes/browser/`（单独的 `package.json`，不进 pnpm workspace；需要忽略的文件写在 `spikes/browser/.gitignore` 里）、报告 `docs/research/m0-browser-spike.md`。**不要碰**仓库根目录的配置、`apps/`、`packages/`。

背景见 `docs/research/browser-stack-2026-10.md`。它的结论是在开发机上用无界面模式代替跑的，这次要在容器里用**有界面 Chrome + Xvfb** 实测。

1. **镜像** `deploy/browser-base.Containerfile`
   - 基础：Ubuntu 24.04。
   - Google Chrome 正式版（从 dl.google.com 下载 .deb）、Xvfb、`fonts-noto-cjk`、`fonts-noto-color-emoji`、`tzdata`。
   - gost v3：从 GitHub release 下载固定版本的二进制，并校验 checksum。
   - Node 24、`@playwright/mcp@0.0.83`、`playwright-core@1.64.1`。
   - 用非 root 用户运行。
   - 用 rootless Podman 3.4.4 实际构建，记下镜像大小。
2. **在容器里实测**（脚本放在 `spikes/browser/`，能重复跑）
   - **启动**：有界面 Chrome 跑在 Xvfb 里，启动参数照报告第 4 步。CDP 只绑 127.0.0.1。
   - **sandbox**：在 rootless Podman 下 Chrome 的 sandbox 能不能开，需要哪些参数（`--shm-size`、`--init`、seccomp 配置）。优先保留 sandbox，`--no-sandbox` 只作为最后手段，结论写清楚。
   - **指纹**：UA 里没有 `HeadlessChrome`；`navigator.webdriver` 为 false；时区、语言按参数生效；中文网页截图里的字正常。
   - **远程画面**（重点）：
     - 测有界面 Chrome 在 Xvfb 里 CDP screencast 的帧率、单帧大小、CPU 占用；
     - 鼠标、滚轮、键盘转发；
     - `Input.insertText` 输入中文；
     - 新标签页跟随（`context.on("page")`）；
     - JS 弹框（alert、confirm）的处理；
     - 拖动滑块：自己写一个本地测试页，有输入框、滑块（拖动类）、会开新标签的链接、会弹 alert 的按钮。
   - **Playwright MCP**：0.0.83 用 `--cdp-endpoint` 连同一个 Chrome，能导航、能拿到快照；默认工具里的 `browser_run_code_unsafe` 要在报告里标出来，提醒 agent 侧屏蔽。
   - **gost**：用本地起的带认证 SOCKS5 测试服务器当上游，测「Chrome → 本机无认证端口 → gost → 带认证上游」能通，上游收到的是域名，也就是 DNS 没有在本地解析。还没有真实代理。
   - **资源**：同时开 1、3、5 个有界面 Chrome（打开维基百科长页面）时的内存（PSS）和 CPU。
3. **给用户手动试的远程画面页**
   - 端口 5190，监听 0.0.0.0：控制台式的 canvas 画面 + 鼠标键盘转发 + 隐藏的 textarea 处理中文输入法和粘贴。画面里打开上面那个本地测试页。
   - 提供 `spikes/browser/run-viewer.sh` 一键起、一键停。
   - 测完要停掉，最后的演示由监工来起。
4. **访问范围**：只用本地测试页、example.com、wikipedia.org。不碰任何电商网站，不登录任何账号。

**验收**：
- 镜像能构建；报告 `docs/research/m0-browser-spike.md`（中文）给出每项的实测数字、结论、推荐的启动参数和容器参数，以及和原调研不一致的地方。
- `run-viewer.sh` 能起能停。

## 包 3：控制台接真实数据 + 整套部署（包 1 完成后开始）

负责：`apps/web`、`deploy/web.Containerfile`、`deploy/Caddyfile`、`deploy/pod.yaml`、`scripts/pod.sh`。

1. **建 `apps/web`**
   - 从 `design/prototype` 复制过来（`design/` 本身不改），改用 pnpm，删掉 `package-lock.json`。
   - `npx shadcn@latest info` 必须显示 `base-lyra` 和预设 `buKEvLs`。
2. **组件库自带的报错**
   - `ui/scroll-area.tsx` 有一处没用到的 import，会让 `tsc -b` 失败；`ui/carousel.tsx` 和 `hooks/use-mobile.ts` 过不了 eslint。
   - 页面没用到的组件（目前 scroll-area、carousel 都没用到）直接不带过来。
   - 用到的，先 `npx shadcn@latest add <组件> --diff` 看上游有没有修：修了就 `--overwrite`；没修就在 eslint 配置里忽略 CLI 管理的文件，并写进汇报。**不手改 ui 文件。**
3. **接数据**
   - tRPC 客户端：`@trpc/client` + `@trpc/tanstack-react-query` + `@tanstack/react-query`，版本精确锁定。
   - 照 `docs/dev/m0-api.md` 把所有 `@/mock/shared` 和 `pages/*/data.ts` 的读取换成查询。
   - 页面状态用真实的查询状态驱动，复用原型已有的界面：加载中用原型的骨架屏，出错用出错提示加「重试」（重新查询），没数据用空状态。
4. **去掉演示开关，接上登录**
   - 去掉右上角「演示」菜单。当前用户和角色来自登录，主管和员工的差异照原型。
   - 主题开关保留：默认暗色，按钮可见，D 键切换。
5. **登录页**
   - 用 registry 区块 `login-01`～`login-05` 里最简单的一个，先 `--dry-run`。照 `docs/ui-rules.md` 的区块注意事项：不引入 sonner。
   - 邮箱 + 密码，中文文案，用山羊 logo。
   - 侧边栏的用户菜单里有「退出」。没登录时任何页面都跳到登录页。
6. **只读阶段的写操作**
   - 按钮和对话框保留，原型怎么显示就怎么显示。
   - 真正提交的那一下统一弹 toast：「只读阶段：这个操作下一个里程碑接通」。用一个公共函数实现，不要每处各写一遍。
7. **看懂架构页**：把它用到的原型假数据复制一份到 `apps/web/src/pages/learn/demo-data/`，文件开头注明「演示数据，M4 换成真实数据」。
8. **实时推送**
   - 订阅 `live.onChange`，按 table 让相关查询失效、重新拉取。
   - 演示：用 `pnpm dev:notify` 或者直接改库里某个 session 的状态，页面 1～2 秒内跟着变。
9. **开发服务器**：Vite dev 用 5180 端口，监听 0.0.0.0，`/api` 代理到 `127.0.0.1:3100`。
10. **整套 pod**
    - `deploy/web.Containerfile`：构建前端，用 Caddy 提供静态文件，`/api` 反向代理到 api。
    - `deploy/pod.yaml`：postgres + api + web 三个容器在一个 pod 里。worker 等 M1 再加。pgdata 和文件存储用卷；主密钥用 Podman secret，3.4.4 的 `play kube` 不支持的话退回只读挂载的文件，写进汇报。
    - `scripts/pod.sh up|down|logs|status`：
      - 兼容 `podman play kube`（3.4）和 `podman kube play`（4 以上）；
      - 负责构建镜像，没有主密钥时生成；
      - `HEYAGENT_SEED_DEMO=1` 时灌演示数据。
    - 入口是 8080 端口，内网能访问。

**验收**：
- `pnpm typecheck`、`pnpm lint`、`pnpm build` 全过。
