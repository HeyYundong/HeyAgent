先读：`docs/dev/conventions.md`、`docs/dev/m1.md`（M1 的整体目标和 P1、P2 的分工）、`docs/ui-rules.md`。

## 现状

P1（引擎）和 P2（配置读写）都已经合进分支 `m1-session-engine`，typecheck、lint、build、test 全过（shared 40 个测试，server 91 个）。

| 内容 | 在哪里看 |

| 引擎 | `apps/server/src/engine/**`。对外的接口在 `apps/server/src/trpc/engine-router.ts`，挂在 `appRouter.engine` 下 |

| 外部事件 | `POST /api/events` |

前端里还在弹「只读阶段」提示的地方：

- 要人办的事里的审批、验收、登录这几类。

记忆和技能的审核已经接通。

## 要做的

### 1. 前端接上引擎

- **立即运行**：
  - 任务卡片、抽屉、待办抽屉里的「立即执行」都调 `engine.runNow`。
  - 可以先带附件：先 `POST /api/files` 拿到 id，再把 id 传给 `runNow`。
  - 新建任务对话框里恢复「创建并启动」：先建任务，再 `runNow`。
- **任务附件**：任务抽屉和编辑表单里可以上传、移除。接口是 `engine.taskAttachments`、`attachToTask`、`detachFromTask`。这些附件每次运行都带。
- **session 过程**：
  - 实时显示：事件、检查点、token、花费、失败原因（失败原因在 kind = `error` 的事件里）；
  - 附件和产物的列表，能下载（`engine.sessionFiles`）；
  - 「取消」（`engine.cancel`）；「立即继续」（`engine.resumeNow`，只对「挂起等待」的 session）。
- **要人办的事**：审批、登录、验收争议、「花费到了上限要不要继续」这几类，都接 `engine.resolveHumanItem`，参数是 `how: approve | reject | done` 加备注。处理完，看板上的运行卡要回到「执行中」。
- **通知**：
  - 顶栏加通知按钮，显示未读数（`engine.notifications.list`）；
  - 点开是列表，用 `Popover` 或 `Sheet` 加 `Item`；
  - 点一条跳到它的链接；可以标成已读（`engine.notifications.markRead`）。
- **实时刷新**：在 `liveQueriesByTable` 里补上 `notifications → engine.notifications.list`、`files → engine.sessionFiles` 等，让新通知、新产物自动出现。
- **工具页「连接并读取工具」**：调 `engine.listMcpServerTools`，成功后用 `tools.updateMcpServer({ …, tools })` 存下来；失败就显示原因。
- **待办页**：原型里有手动触发事件的地方，就接 `engine.fireEvent`（仅主管）。
- **删干净**：去掉所有剩下的 `readOnlyToast`，连同这个函数本身。

### 2. 服务端收尾

- **设置键只留一份**：P1 在 `shared/engine.ts` 里定义了 `ENGINE_SETTING_KEYS`，P2 在 `shared/config.ts` 里定义了 `SETTING_KEYS`，字符串一样。统一成一份，两边都引用它。
- **内置工具**：API 启动时（bootstrap 里）也同步一次进 `tools` 表。这样即使 worker 还没起，空白环境的工具页也能看到它们。
- **`settings` 表加实时推送触发器**：照 `0001_triggers.sql` 的写法。P3 是现在唯一改表结构的包，新迁移接着现有编号。
- **测试辅助**：所有重置测试库的地方都把 `pgboss` schema 一起删掉，免得留下旧任务。
- **支持 `OPENROUTER_API_KEY_FILE`**：从文件读 key，pod 里用。仍然兼容原来的 `OPENROUTER_API_KEY`。
- **可选**：把自定义的模块解析条件从 `source` 改成不会和别的包撞名的 `@heyagent/source`，然后看能不能去掉 `allowImportingTsExtensions` 和 vitest 的 `server.deps.inline` 这两个绕路。
  - 原因：第三方包（例如 eventsource-parser）也有叫 `source` 的条件，现在会被解析到它们的 TS 源码。
  - 只在 typecheck、lint、build、test、整套 pod 全部正常时才保留这项改动；不行就不改，写进汇报。
- **接口文档**：写 `docs/dev/api.md`，说明当前全部接口：查询、配置写、engine、文件、事件。写到 M2、M3 的开发者不用翻代码就能对接的程度。

### 3. 整套 pod（rootless Podman 3.4.4）

- **加 worker 容器**：镜像用 `deploy/worker.Containerfile` 构建，tag 为 `localhost/heyagent-worker:m1`。
- **卷和配置**：
  - api 和 worker 挂同一个文件卷，设同一个 `HEYAGENT_FILES_DIR`；
  - 主密钥两个容器都能读，照 M0 的做法：卷里放 0400 的文件；
  - OpenRouter 的 key 用文件传（`OPENROUTER_API_KEY_FILE`），不放进 configmap。`scripts/pod.sh` 从主目录 `.env` 读出来，写进卷，权限 0400，并且不打印。
- **管理员密码**：`HEYAGENT_ADMIN_PASSWORD_FILE` 指向卷里可写的路径。`pod.sh up` 结束后，把它复制到主目录的 `.dev/admin-password`（权限 600），并提示「管理员初始密码在 .dev/admin-password」。不打印密码本身。
- **启动顺序**：api 先迁移、执行 bootstrap；worker 等 api 健康了再开始（自己重试也行）。
- **worker 容器的参数**按 `docs/research/m0-browser-spike.md` 的推荐（`--init`、shm、只留 `SYS_CHROOT`、`no-new-privileges`），换成 kube YAML 里的写法。3.4.4 不支持的，写进汇报。
- **默认不灌演示数据**：`HEYAGENT_SEED_DEMO` 的路径可以留着给开发用，但默认关闭。
- **从空白开始**：现在 8080 的 pod 是 M0 的，库里有演示数据。先 `scripts/pod.sh down`，删掉它的数据卷，再起新的。

### 4. 端到端验收（在 8080 的 pod 上）

- **真模型预算**：只用便宜的模型（`anthropic/claude-haiku-5.5` 为主），最多 5 美元。跑之前执行 `scripts/or-usage.sh check 18`。
- **用 Playwright 脚本照真人的路径走一遍**，冒烟脚本放在 `apps/web/scripts/`：
  1. 管理员用 `.dev/admin-password` 里的密码登录。
  2. 建一个通用任务：「把下面三行数据整理成 CSV，用存文件工具保存」，带一个「产出文件」检查点，执行模型选 Haiku。点「创建并启动」→ 过程里实时出现事件 → 完成 → 产物出现并且能下载。
  3. 建一个用 `session.wait` 等 1 分钟的任务：挂起，到点继续，是同一个 session。
  4. 建一个让 agent 先用 `ask.human` 请示的任务：看板「等人处理」出现卡片 → 负责人批准 → session 继续 → 完成。通知按钮上出现未读数。
  5. 带附件运行：上传一个 txt，任务让 agent 用读附件工具读出内容并写进结果。
  6. 员工账号：别人负责的照旧只能看；自己负责的能运行。
  7. 两个账号全程浏览器控制台没有报错。
- **验收完把 pod 恢复成空白环境**：删卷，重新 `up`，只剩管理员和系统自带的东西，并且一直开着。
- 汇报里写清楚**真模型花了多少钱**。

## 约束

- 只用 Podman，没有 sudo。不要停 5173 的原型，也不要动 `heyagent-pg` 开发数据库容器本身。
- 你的开发库是 `heyagent_p3`，测试库是 `heyagent_p3_test`，API 端口 3103，前端端口 5182。在主目录 `.env` 之外另建 `.env.p3`，或者用环境变量覆盖，**不要改主目录 `.env` 里的 `OPENROUTER_API_KEY`**。
- OpenRouter 的 key 绝不打印，不写进代码、日志、截图，不提交。
- 不 commit，不 push：监工验收后统一提交。
- UI 照 `docs/ui-rules.md`。组件库确实没有的组件，可以按第 6 节组合实现、登记在第 8 节，汇报里说明。
- 做完关掉自己起的 dev server。整套 pod 留着运行。
