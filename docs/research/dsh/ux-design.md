# HeyAgent 用 dsh 自己的界面：信息架构和交互设计（给可点原型）

> 2026-11-06 写。前提：用户已定**不要旧控制台**（React 19 + shadcn 的 16 个页面），改用 DeepSeek Harness（dsh，提交 `8bd07339`）自带的 Web 界面——以会话为中心的 agent 工作台；HeyAgent 的全部功能都保留，做成 dsh 插件。
> 依据：`docs/research/dsh/target-architecture.md`（下称「架构」）、`notes/heyagent-frontend.md`、`notes/heyagent-backend.md`、`notes/dsh-host-ui.md`、`notes/dsh-browser-desktop.md`，`docs/guide.md`（下称「手册」）、`docs/v1-plan.md`，dsh `packages/client/ui-*` 的 README 和少量源码。没有运行任何代码。
> 标注：**[dsh]** = dsh 已有、照用或换皮；**[改]** = dsh 有类似的东西，要换内容或换行为；**[新]** = 我们新写的插件界面；**[未核实]** = 原型之前或开发前要先验证。
> 插件名：界面插件统一叫 `heyagent-ui-*`（dsh 的「client 插件」，跑在浏览器里）；主机侧插件沿用架构第 3 节的 `heyagent-*`。

## 0. 先说三件会影响全局的事

1. **和项目的 UI 强规则冲突。** `CLAUDE.md` 和 `docs/ui-rules.md` 规定所有页面只用 shadcn `buKEvLs`。dsh 界面是 React 18.3 + Cordis + CSS Modules + `--dsw-*` token + 它自己的 `ui-primitives`，文档明文禁止 Tailwind 和组件库（笔记 dsh-host-ui 4.1）。改用 dsh 界面就等于废掉这条规则，换成「只用 dsh 的设计体系」。**这要用户明确拍板并改写 `docs/ui-rules.md`**，本文按「换成 dsh 设计体系」写。dsh 缺的表格、下拉、可搜索下拉、表单、日期选择这几样，由我们的 `heyagent-ui-kit` 按 dsh 风格补（第 5 节第 5 条）。
2. **会改掉架构第 14 节「前端一行不改」。** 用了 dsh 界面以后，api 进程要挂 dsh 的会话读取、静态前端、客户端模块和选中的 `ui-*` 行；多用户认证（补丁 P-02）从第 2 阶段提前到第 1 阶段（dsh 没有登录页，所有浏览器都是同一个 owner）。具体见第 5 节；架构文档要跟着改。
3. **一次运行 = 一个 dsh 会话，界面上统一叫「运行」。** dsh 界面的「会话 / 新会话」文案改成「运行 / 新运行」；dsh 的「工作区」概念不露给用户，左栏按**任务**分组（1.2 节说为什么）。

### 1.2 「dsh 工作区」和「HeyAgent 任务」怎么对

| | dsh 工作区（workspace） | HeyAgent 任务 |
|---|---|---|
| 本质 | 一个注册过的**目录**；会话的工作目录、文件树、「在应用中打开」都跟它走 | 一份**配置模板**（目标、步骤、检查点、工具、浏览器、规则、模型、定时……），每运行一次冻结一份快照 |
| 和会话的关系 | 会话属于某个工作区，左栏按它分组；「新会话」在当前工作区开 | 运行属于某个任务；「立即运行」开这个任务的新运行 |
| 数量 | 个人几个到十几个 | 公司几十到上百个，还在长 |
| 权限 | `remote-access` 有 `workspace` 资源类型 | 负责人能操作、员工看全部 |
| 新建 / 改名 / 删除 | 左栏里选目录、改名、删 | 主管在任务页建，改要过表单，删要看有没有被派活引用 |

**结论：界面上「任务」取代「工作区」的位置（左栏分组、新运行时选的那个东西），但不把任务注册成 dsh 工作区。**

- 取代的理由：两者在界面上扮演同一个角色——「会话的父亲」「新建时先选它」「左栏按它分组」。用户心智里「我跑一下比价任务」就是「在比价这一组里开一个新运行」。dsh 的分组、水位线（每组先显示 5 条、「展开其余」）、状态点、悬停操作、搜索，原样适合任务分组。
- 不注册成工作区的理由：工作区带目录语义，dsh 的文件树、`working-directory`、「在本机打开」、目录选择器、工作区改名 / 删除 / 拖拽排序都会冒出来，每一个都要关；任务的增删改有业务校验，不能让左栏直接改；运行的文件在运行自己的空间里，不在任务目录里。
- 做法：`heyagent-ui-runs` 占 `sidebar.workspaces` 这个座位，画「按任务分组的运行列表」，行样式照抄 `ui-workspace`（同样的行高、状态点、悬停按钮、水位线、搜索框）；数据来自我们的 `sessions` 表。`ui-workspace` 里其他包依赖的 `ctx.uiWorkspace.openSession` 等导航接口由我们的插件提供同名服务，或者保留 `ui-workspace` 只换它的列表渲染——哪种可行要先看源码 **[未核实]**。没有任何任务的运行（临时运行，见下）归在「临时运行」组；助手对话不进这个列表。
- 「工作区树」视图换成「按分类」：任务有分类标签（岗位、业务线）时，左栏可以切成「分类 → 任务 → 运行」三层；没有就两层。

**其余概念：**

| HeyAgent | 在 dsh 界面里是什么 |
|---|---|
| 运行 / session（`R-1024-3`） | 一个 dsh 会话，id 就是运行号（架构 5.3：会话 id = 运行 id） |
| 子运行（`R-1024-3.2`） | dsh「子 agent 会话」的位置：左栏不显示，父运行页头有「子 agent」计数按钮，点开目录、在右栏 tab 里看子运行的对话（照 `ui-subagent`） |
| 派活单（`W-57`） | 不是会话；在派出方运行里是一张工具卡，在被派任务那组里是它开出来的运行的「来源」，详情在右栏「派活单」tab 和「运行」面板的「排队中」 |
| 要人办的事 | 挡运行的：对话里一张卡 + 输入框被处理卡接管（照 `ui-approval` / `ui-user-questions` 的形式）；所有的：「要人办」面板 |
| 检查点 | 对话里的检查点行 + 输入框上方的目标条（照 `ui-goal` 的位置）+ 右栏「概览」 |
| 挂起 / 继续 | 对话里的分隔标记（dsh `Marker` 那种行内分隔）；左栏行上的时钟标记（照 `ui-schedule` 的时钟座位） |
| 定时、人加的待办 | 任务页的「什么时候跑」；dsh 的「自动化任务」页不挂，换成我们的 |
| 临时运行 | 不选任务、直接说要做什么开的运行（1.4 节「新运行」第 3 种），背后是一个每人一份的隐藏任务「临时运行」，配置由主管在设置里定 |

### 1.3 左栏

自上而下：

1. **品牌行** [改]：`sidebar.brand.mark` / `sidebar.brand.name` 换成山羊图标和「HeyAgent」（`heyagent-ui-shell`）。点品牌 = 新运行（dsh 原行为）。
2. **新运行** 按钮 [dsh]：打开主区的「新运行」起始页（1.4）。快捷键沿用 dsh 新会话的。若左栏当前选中的是某任务组，起始页预选这个任务。
3. **面板入口** `sidebar.panellist` [新]，从上到下。dsh 自带「更多」菜单和「固定 / 取消固定」，默认固定前 5 个，其余收进「更多」，每人可以自己钉：

| 顺序 | 入口 | 默认 | 角标 |
|---|---|---|---|
| 1 | 要人办 | 固定 | 等我处理的数（主管算全部），橙色 |
| 2 | 任务 | 固定 | — |
| 3 | 运行 | 固定 | 执行中的数（灰色小字，可关） |
| 4 | 浏览器 | 固定 | 等人处理的 Chrome 数 |
| 5 | 桌面 | 固定 | — |
| 6 | 图库 | 更多 | — |
| 7 | 比物 | 更多 | — |
| 8 | 配置（技能 / 记忆 / 规则 / 工具 / 流程库） | 更多 | 待审核的建议数 |
| 9 | 导入（只主管） | 更多 | — |
| 10 | 帮助（看懂架构 + 使用手册） | 更多 | — |

   dsh 的「插件」「自动化任务」入口不挂。
4. **运行列表** `sidebar.workspaces` [改 → 新]（`heyagent-ui-runs`）：
   - 组 = 任务。组标题：任务名，悬停出「新运行」（+）和「⋯」（打开任务、只看这个任务的运行、停用 / 启用）。组的排序：有执行中 / 等人处理运行的在前，其次最近有运行的；可切「手动排序」（拖组，只存在浏览器里）。
   - 行 = 运行。标题 = 运行的一句话摘要（附加说明、派活单的「要办的事」，或者首轮之后 agent 写的标题），后面小字运行号。行尾 = 状态（替换 dsh 的更新时间）：

| 运行状态 | 行首点 / 图标 | 行尾文字 |
|---|---|---|
| 执行中 `running` | dsh 共享的进行中转圈 | 用时 3:12 |
| 等人处理 `needs_human` | dsh 共享的 warning 橙点 | 待批准 / 待登录 / 待回答 / 待定验收 / 待定上限 / 待重试 |
| 等待中 `waiting` | 时钟（照 `ui-schedule` 时钟标记） | 等到 14:00 / 等事件 / 等 W-57 / 等名额 |
| 验收中 `verifying` | 转圈 | 验收中 |
| 已结束 + 办成 | 对勾 | 办成 |
| 已结束 + 没办成 / 出错 | 叉（出错是红点） | 没办成 / 出错 |
| 已结束 + 复核中 | 文字流光（`TextShimmer`） | 复核中 |
| 排队中的派活单 | 不进左栏 | — |

   - 每组水位线、展开其余、收起照 dsh；默认只显示「值得看的」：执行中、等人处理、等待中的全显示，已结束的显示最近 3 条。
   - 行悬停按钮：置顶（只存在浏览器）、「⋯」：打开、复制运行号、改结果（已结束、负责人和主管）、取消运行（未结束）、在「运行」面板里看。dsh 的改名、分叉（fork）、归档**去掉**（运行号就是名字；分叉没有业务含义；归档换成「隐藏已结束」视图选项）。
   - 顶部区头：搜索（运行号、任务名、摘要、派活单号）、视图选项（分组方式：按任务 / 按分类 / 平铺按时间；显示范围：**我的**（默认，员工）/ 全部（默认，主管）；「显示定时和派活开的运行」开关，默认开；「隐藏已结束」）。
   - 「临时运行」组固定在最后（只有自己的）。
5. **底部** [改]：dsh 的 `sidebar.settings` 行。左边头像 + 名字（点开：修改密码、退出），右边齿轮打开设置。

### 1.4 主区：运行界面（`main[conversation]`）

**新运行起始页**（dsh 叫 Session Intent / hero，输入框居中）[改]：

```text
                      [羊]  要 agent 办什么？
        ┌────────────────────────────────────────────────────┐
        │ 任务：[ 每日比价  T-1042  ▾ ]   负责人 张三  模型 DeepSeek V4.1 │  ← hero.workspace 座位换成「任务选择」
        │ 目标：每天 9 点前拿到 3 家的价格写进表格              │
        │ ┌────────────────────────────────────────────────┐ │
        │ │ 补一句这次要注意的（可以不写）                  │ │  ← 附加说明
        │ │ [附件] [/] [@]                     [模型▾] [运行] │ │
        │ └────────────────────────────────────────────────┘ │
        │ 最近：每日比价 · 1688 搜品 · 周报汇总     全部任务 ▸ │  ← hero.options
        └────────────────────────────────────────────────────┘
```

- 「任务」下拉 = 可搜索列表：先「我负责的」，再「最近运行过的」，再全部；每行任务名、编号、负责人、上次结果。选中后下面出任务摘要（目标、浏览器、桌面、定时）。
- 三种起法：
  1. **普通任务**：输入框是「附加说明」，可带附件（= 旧「带附件运行」）；发送 = 立即运行。
  2. **能被派活的任务**：输入框上方换成「派一张」表单（任务的参数表，必填项标出），说明栏变「要办的事」；发送 = 派一张单（出现在「排队中」，轮到了才开运行），发完起始页提示「W-58 已排队，第 2 位」，不跳转。
  3. **临时运行**：任务下拉第一项「不选任务，直接说」；输入框就是要做的事；用设置里「临时运行」的默认配置（工具、浏览器、模型、上限）。是否开放给员工由主管在设置里定（第 6 节第 2 条）。临时运行结束后收尾卡有「存成任务」。
- 挡住的情况：任务停用 →「运行」灰掉，下面一行写原因；这个任务最近一次运行还没结束 → 显示「R-1024-3 还在执行中，去看看」，不能再开（手册 6.1 的规矩）；员工选了别人负责的任务 → 只能看，「运行」灰掉。
- 模型下拉 [dsh `ui-model-selection` 换数据]：默认是任务选的执行模型；只有主管能换（只对这次运行有效）。
- 斜杠命令：`/任务 <名>` 选任务、`/模型`、`/附件`。dsh 的 `/plan`、`/goal`、`/permission`、`/compact`、技能 `/name` 不挂（技能由任务配置决定，不由人在输入框里调）。

### 1.8 助手放哪

### 1.10 深链接

## 3. 关键流程

约定：「点 X」= 点击界面上文字为 X 的控件；括号里写出现在哪个区。

### 3a 员工从输入框开一次运行、看它干活

1. 员工李四登录，进来默认是「新运行」起始页（主区），左栏运行列表只显示「我的」。
2. 点「任务」下拉（起始页），搜「比价」，选「每日比价 T-1042」。下面出现目标、负责人李四、浏览器「采购 Chrome 1」、模型 DeepSeek V4.1 Flash。
3. 在输入框写「今天只看华东的供应商」，点「附件」上传 `供应商名单.xlsx`（附件栏显示文件名和上传进度）。
4. 点「运行」（或回车）。按钮变「开始中…」；一两秒后：
   - 左栏「每日比价」组顶部多一行「今天只看华东的供应商 R-1024-3」，行首转圈，行尾「排队中」→「0:01」；
   - 主区切到这次运行的运行界面，第一条是开始卡（来源「手动 · 李四」、附加说明、附件 1、折叠的配置）。
5. agent 开始干活（实时，逐字流式）：
   - 「思考 ▸」行在流（dsh 思考预览，默认收起一行）；
   - 工具卡「浏览器 · 打开 https://… 」出现，卡片右侧一张缩略图；
   - 同时右栏自动展开「浏览器」tab，能看到 Chrome 画面在动，agent 光标在点，画面上方小标签「正在搜索：蓝牙耳机」；
   - 检查点行「✓ 第 1 条 打开了 3 家的店铺页」出现，下面目标条从「检查点 0/5」变「1/5」。
6. 李四点目标条上的「检查点 1/5 ▸」→ 右栏切到「概览」tab，看到 5 条检查点卡，第 2 条标「正在做」。
7. 李四把右栏点「全屏」看画面细节，再点回来。整个过程左栏这行的用时一直在走。
8. 李四切去别的面板（比如「图库」）：运行继续；左栏这行状态照常更新；回来点这行，对话停在最新处（dsh 跟随到底）。

### 3b 运行碰到审批规则 → 对话里出审批卡 + 要人办里一件事 → 主管批 → 运行继续

1. agent 调「发邮件」工具。规则「对外发送前要人批准」命中。
2. 运行界面里：这次工具卡显示「⏸ 等审批 · 规则「对外发送前要人批准」」，下面一张审批卡（未处理）：工具名、参数表（密钥字段 `••••`）、规则名、分给谁（任务负责人李四；主管都能批）。运行状态徽章变「等人处理 · 审批」，输入框被审批卡接管——对李四（负责人）显示「批准」「拒绝」两个按钮和「备注（agent 继续时会看到）」框；对没权限的人显示「等李四或主管处理」，没有按钮。
3. 左栏这行变橙点，行尾「待批准」；「要人办」入口角标 +1；李四和主管收到应用级提示「R-1024-3 等你审批：发邮件」（点了 = 打开这件事）；飞书群收到推送，链接是 `#/inbox/ap-12`。
4. 主管王五在手机上点飞书里的链接：登录后直接打开「要人办」面板，选中 ap-12，右边详情就是同一张审批卡，上面多一行「挡着运行 R-1024-3 · 打开运行」。
5. 王五点「批准」。这件事标「涉及金钱」时，先弹确认（dsh `RiskConfirmation` 样式：「这一步会付款 ¥3,200，确定批准？」），点「确定批准」。
6. 卡变结论行「王五 10:32 批准」；要人办角标 -1；运行状态变「执行中」；对话流出现分隔「继续 · 10:32 · 审批通过」，接着一张工具卡「发邮件（审批通过后执行）」带结果；agent 接着做。
7. 拒绝时：点「拒绝」要写原因（可空），卡变「王五 拒绝：……」，agent 收到「被拒绝了，不要换办法绕过去」，继续往下想。
8. 同一步里被挡住的其他调用：工具卡显示「没执行（前面一步在等审批）」，agent 继续后自己决定要不要再调（架构 6.2 的变化，第 6 节第 9 条）。

### 3c 验证码 / 登录接手

1. agent 在浏览器里遇到验证码，自己试过 3 次没过（设置里开着「先自己试」）。
2. 对话流：工具卡「遇到验证码，交给人」带截图；下面一张「登录」卡：截图、「Chrome 保留到 10:45（还剩 28 分钟）」、主按钮「去浏览器里处理」、次按钮「处理不了」。状态「等人处理 · 登录」；左栏橙点「待登录」；通知同 3b。
3. 李四点「去浏览器里处理」：右栏「浏览器」tab 被揭示并闪一下，自动切成「我来操作」，顶部横幅「等你处理：过完验证码、登录好以后点「已处理好了」 · 剩 27:50」。窄屏时右栏直接全屏。
4. 李四在画面里拖滑块、输验证码（键盘、输入法、粘贴都能用）。也可以把这个 tab 拖成浮窗，边看对话边操作。
5. 点横幅上的「已处理好了」（或登录卡上的同名按钮）。横幅消失，tab 回到「只看」，agent 光标重新出现；对话分隔「继续 · 李四处理好了」；agent 在**同一个 Chrome** 里接着做。
6. 保留时间过了才来：登录卡主按钮变「新开 Chrome 处理」→ 右栏浏览器 tab 打开一个登录用的 Chrome（不是这次运行的）；处理好关掉 tab（关 = 保存登录状态）→ 回到卡点「已处理好了」，agent 继续时新起 Chrome。
7. 点「处理不了」：可写一句原因，agent 收到后自己决定（换账号、报没办成等）。
8. 桌面上的扫码登录一样，只是右栏开的是「桌面」tab。

### 3d 运行中途插话

1. 运行在执行中。李四在输入框写「价格统一换成人民币」，回车。
2. 对话流尾部立刻出现一个半透明气泡，标签「插话 · 发送中」；agent 下一步开始前收到时，气泡变实，标签「插话 · 李四 · 10:21」，后面 agent 的思考里能看到它在照做。
3. 如果这时运行刚好挂起（等事件），标签是「插话 · 会在继续时交给 agent」；李四想马上继续，点目标条上的「立即继续」。
4. 多人同时插话按到达顺序排；没权限的人输入框是只读。
5. 停：点输入框右边「停」→ 确认框「取消运行 R-1024-3？取消后不能恢复，在等的事一起作废，已经做完的操作不会撤回」+ 原因（可空）→ 「取消运行」。

### 3h 固化流程：提议 → 审核 → 流程库

1. R-1024-3 办成。任务开着「办成后自动固化」：页头出现后台任务指示「固化中 · 写脚本」（照 `ui-jobs` 的页头后台任务按钮，点开看进度：写脚本 → 试跑第 1 轮 → 没过：找不到按钮 → 第 2 轮 → 过了）。手动的话：收尾卡「固化成流程」→ 小弹窗（勾「不试跑」）→「开始固化」。

3. 李四打开它（要人办面板右侧，内容多时可「在大窗口看」）：步骤一行一条（会改东西的标出来，判断步标「判断」）、输入和交回的结果、试跑结果（每步、停在哪、读到的和原运行的对比，不一样的标黄）、停下时截图、假设、脚本（折叠，用 dsh `CodeCard`）、和 v2 的对比（`DiffBlock`）。

5. 下次运行：开始卡写「按固化流程第 3 版跑」，脚本做的工具卡带「流程」标签，速度明显快；跑不通时分隔「流程停在第 9 步：找不到按钮 · 交给 agent 接着做」。

## 4. 多用户

**登录。** dsh 没有登录页、没有退出，所有浏览器都是同一个 owner（笔记 dsh-host-ui 3.1）。我们要：首次设置管理员页、登录页（邮箱 + 密码）、退出、改密码，都由 `heyagent-ui-shell` 在 dsh 外壳启动前画（未登录时 index 就渲登录页），背后是 better-auth；dsh 的连接层要改成按用户发 Peer（补丁 P-02，提前到第 1 阶段）。

**主管和员工看到的差别**（照手册 3.2 的权限表，搬到新界面）：

| 地方 | 主管 | 员工 |
|---|---|---|
| 面板入口 | 全部 | 没有「导入」；「配置」里只读 |
| 设置分区 | 全部 | 我的账号、外观、模型（只读）、关于 |
| 左栏运行列表默认范围 | 全部 | 我的（我负责的任务的运行 + 我开的 + 有事分给我的）；可切「全部」只看 |
| 起始页任务下拉 | 全部任务 | 全部任务可选，只有自己负责的能点「运行」；临时运行看设置 |
| 运行界面输入框 | 插话、继续、停 | 只在自己负责的任务上能 |
| 处理卡 | 所有事都能处理 | 分给自己的；别人的只看，写「等王五处理」 |
| 远程画面「我来操作」 | 全部 | 自己负责的任务的运行、分给自己的事；「打开 Chrome」能用 |
| 任务面板 | 新建、编辑全部 | 编辑自己负责的；不能新建 |
| 改结果、固化、总结 | 全部 | 自己负责的任务 |
| 手动触发事件 | 能 | 不能 |
| 助手 | 能改配置（按设置里允许的范围） | 只能问、不能出改动卡（或出了不能应用）——第 6 节第 7 条 |

按钮没权限就不画（dsh 的 `useRemoteAccess` / `useSessionAccess` 做法），后端照旧独立判断（`can()`）。

**谁的运行出现在列表里**：见上表。另外：有事分给我的运行，不管是不是我的任务，都在「我的」里，并且排在组的最前；「要人办」面板「待处理」员工默认「分给我」，主管默认「全部」，都能切。

**通知**：

- 站内：「要人办」面板「通知」标签（有事等你处理、运行完成、运行失败、等太久、待办没触发、agent「通知员工」发的）；新通知到达时应用级 toast（点了跳到对应处并标已读）；「要人办」入口角标 = 待处理数；浏览器标签标题「(3) HeyAgent」。
- 外部：飞书 / 企业微信 / webhook 不变，消息里的链接换成 1.10 的深链接。
- 每条通知只推给相关的人（负责人、分给谁、主管），和今天一样。

**并发看同一个运行**：多人同时打开同一运行，对话流都实时；处理卡谁先点谁生效，后点的看到「已被王五处理」；远程画面同一时刻只一个人能操作，另一个人点「我来操作」时提示「张三正在操作」。

## 5. dsh 界面范式不合我们的地方，和解决办法

1. **dsh 的会话是「人和 agent 对话」；我们的运行是「agent 自己跑，人偶尔插手」。** dsh 的输入框默认是「发一条提示词让 agent 跑一轮」；我们的运行在 worker 里跑，api 进程不持有 agent（架构 1.2、第 7 节）。
   - 办法：输入框的发送、停止全部改走我们的接口（插话 → `run_inbox` + 通知 worker；停 → 取消运行；继续 → `resumeNow`），不调 dsh 的 `session/prompt` / `session/cancel`。输入框按状态换行为（1.4 表）。dsh 的「排队」、连按 Esc 停止关掉。dsh 发送时「等 Host 接收再清草稿」的体验保留。要验证能不能在不 fork `ui-conversation` 的前提下接管发送 **[未核实]**；不行就由 api 侧包一个 `session/prompt` 的替身，把提示词转成插话。
2. **我们的业务东西（检查点、要人办、结果、复核、派活状态）不在 dsh 会话日志里**（架构原则 1：dsh 日志只放模型看得到的）。dsh 对话流是按 dsh 事件拼的。
   - 办法：能挂在工具调用上的都挂在工具调用上——检查点、报结果、问人、派活、子 agent、固化流程本来就是工具，`tool.call.toolview` 按工具名渲染，卡里的实时状态（审批批了没、W-57 到哪了）从我们的接口读；审批的那次调用在日志里是带 `HEYAGENT_APPROVAL_PENDING` 的拒绝结果（架构 6.2），工具卡认这个码画审批卡。挂起 / 继续 / 插话是 run_inbox 交给模型的用户消息（来源 `heyagent`），用 `conversation.chat.user.before` 链按来源画成分隔或标签。剩下不挂在任何事件上的（验收轮次、复核、结果、交付物）放在收尾卡，收尾卡挂在最后一轮之后，数据全从我们的接口读。这条决定原型里对话流长什么样，开发前要用真实运行验证节点能否这样排 **[未核实]**。
3. **api 进程要能读 worker 写的会话，并实时跟。** dsh 的 `session/follow` 假定会话就在本进程。
   - 办法（架构侧）：api 挂 dsh 会话控制器，持久层用我们的 Postgres 版 `SessionPersistence`（只读），新事件靠 `NOTIFY` 推给 follow 流；或者干脆不用 dsh 的会话流，运行界面的数据走我们自己的 `@Remote` 流，再喂给 `ui-conversation` 的装配器。哪条路可行要先读源码 **[未核实]**。这条直接影响「逐字流式」能不能做到：架构 14.4 说今天是整份事件重拉。
4. **左栏为个人会话设计，我们一天可能几百个运行（定时、派活）。**
   - 办法：左栏只放「值得看的」（执行中、等人处理、等待中全放，已结束每组最近 3 条），默认只看「我的」；完整列表、筛选、翻页、统计在「运行」面板（表格）。视图选项可以隐藏定时 / 派活开的运行。
5. **dsh 没有表格、下拉、可搜索下拉、表单库、日期选择**（笔记 dsh-host-ui 4.1），我们十几个配置面板全靠这些。
   - 办法：`heyagent-ui-kit` 按 dsh 风格补：表格（虚拟滚动用 dsh 已共享的 `@tanstack/react-virtual`）、下拉、可搜索下拉、多选标签、表单项（label + 说明 + 错误）、日期时间、面板外框、状态 / 结果徽章、缩放画布、字段差异对比。只用 `--dsw-alias-*` token；能用 dsh 原件的（`Button` `Input` `Switch` `Checkbox` `SegmentedTabs` `Menu` `Modal` `RiskConfirmation` `Tooltip` `HoverCard` `Tag` `Pill` `StateDot` `CodeCard` `DiffBlock` `JsonTree` `ImageLightbox` `ZoomControls` `Toast`）就用原件。表单状态可以继续用 react-hook-form + 共享 zod schema（支持 React 18）；数据可以继续用 tRPC + TanStack Query（都支持 React 18），这样 `@heyagent/shared` 和 189 个 procedure 基本不动 **[未核实：dsh 插件打包里私有打包这些库的体积]**。dsh 的 i18n 检查要求文案进词典：我们只做中文词典（dsh 本身有 zh）。
6. **右栏只在运行界面有，全局面板没有。** 助手和远程画面在面板里需要别的位置。
   - 办法：助手 = 面板外框里的右侧列；远程画面 = 面板内弹窗 + `shell.overlay` 小窗（跨面板）。运行界面里两者都是右栏 tab。
7. **dsh 没有 agent 浏览器 / 桌面的实时画面**（笔记 dsh-browser-desktop 1.7）；它的「浏览器」tab 是给用户自己上网的 iframe。
   - 办法：不挂 `ui-sidebar-browser`，我们注册 `browser` / `desktop` 两个右栏 tab 类型（照它的注册方式），画面走现有 WebSocket（要补丁 P-01 前缀升级路由）。canvas、坐标换算、输入法、虚拟光标逻辑从旧 `components/remote-view` 搬，外观换 dsh 风格。
8. **dsh 没有地址路由。** 通知、飞书链接、分享都要直达。
   - 办法：1.10 的 hash 路由。
9. **dsh 只有一个 owner；审批、提问的 dsh 交互只给 owner。**
   - 办法：不用 dsh 的审批、提问（架构已定不挂 `user-approval` / `user-questions`）；我们的处理卡照它们的样子画，数据和权限是我们的。认证改造见第 4 节。
10. **dsh 的「工作区 = 目录」相关功能**（文件树、在本机打开、目录选择、工作区改名删除、会话分叉 / 改名 / 归档、终端）对我们没有意义或不安全。
    - 办法：这些行、tab、菜单项不挂或隐藏（1.3、1.6、1.7 列了）。文件 tab 改看运行空间。
11. **长时间挂起。** dsh 的会话只有「运行中 / 空闲 / 等交互」；我们有 7 种状态、能挂几天。
    - 办法：左栏行、页头徽章、运行面板都画我们的状态（1.3 表）；等待中用时钟图标和「等到 …」，和 dsh 定时任务的时钟标记同一个座位。
12. **dsh 视觉是圆角、发丝线、阴影层次；旧控制台是直角、红色主题。**
    - 办法：全部按 dsh 的来（第 0 节第 1 条）；品牌只换图标和名字。dsh 图表色、语义色够不够（办成 / 没办成、新增 / 删除的颜色）要看 `ui-theme` 的 token，不够的作为我们的扩展 token 登记 **[未核实]**。
13. **面板只有一级。** 「配置」里的五项、设置里的十几项是二级。
    - 办法：「配置」面板内左侧二级导航；设置用 dsh 设置弹窗自带的分区导航。

## 6. 待用户定 / 开放问题

最需要拍板的：

1. **UI 强规则改不改。** 用 dsh 界面就不能再「只用 shadcn `buKEvLs`」。推荐：改写 `docs/ui-rules.md` 为「只用 dsh 设计体系（`ui-primitives` + `--dsw-*` token）+ 我们登记的 `heyagent-ui-kit`」，例外流程照旧。要用户同意后才改 `CLAUDE.md`。
2. **要不要「临时运行」（不选任务直接说）。** dsh 的核心体验就是直接说；HeyAgent 一直是「一切都是任务」。推荐：做，主管默认能用，员工由设置开关决定（默认关），配置（工具、浏览器、模型、上限）由主管在设置里定，结束后可「存成任务」。
3. **左栏按任务分组的实现方式。** 推荐我们自己占 `sidebar.workspaces` 画列表、不注册假工作区；要先确认 `ui-workspace` 提供的导航服务能不能被替换 **[未核实]**。
4. **已结束运行的输入框 = 再跑一次（新运行）。** 推荐这样，而不是让结束的运行接着聊（会打乱结果和复核的语义）。
5. **助手对话要不要也做成 dsh 会话。** 推荐第一期不做（架构 21.9：助手第一期不搬进 dsh），只是界面换皮；以后助手搬进 dsh 再考虑。

其余：

6. 「停」= 取消运行，要二次确认；连按 Esc 停止关掉。我们没有「暂停」，要不要加一个「暂停（挂起，人点继续）」？推荐先不加。
7. 员工能不能用助手出改动卡：推荐只能问、不能应用。
8. 主管在起始页换这次运行的模型：推荐允许，只对这一次有效、开始卡上写明。
9. 架构 6.2 的审批变化（被挡的后续调用不自动执行）在界面上的表现：工具卡写「没执行（前面一步在等审批）」，用户能接受吗。
10. 「过程表」（dsh 轨迹视图）给员工看吗：推荐都给。
11. 「帮助」面板的动画课要不要按新界面重做：推荐先只放手册目录，动画课晚做。
12. 移动端：dsh 窄屏自带抽屉、右栏自动全屏；审批、登录接手在手机上能用就够，配置面板不保证。
13. 这份设计推翻了架构 14.1「第 1 阶段前端不改」：多用户认证、会话读取、静态前端、Typert 或 tRPC 的选择都要在架构里重排，阶段和工作量要重估。

## 7. 给原型的屏幕清单

原型用假数据：3 个用户（主管王五、员工李四、员工赵六），6 个任务（每日比价 T-1042 负责李四、1688 搜品 T-998、月度对账 T-990、周报汇总 T-1101（定时）、查价格（被派任务）T-1050、临时运行），每个任务 2～6 个运行，覆盖 7 种状态和办成 / 没办成 / 复核中。
