# HeyAgent 使用手册

给在控制台里配置 agent 任务的人看。讲清楚怎么从零搭出一个能跑的任务，以及每样配置是什么、在哪配、要注意什么。

可以从头读，也可以按目录查。按钮、页面的名字和控制台界面上的一致。安装、升级、备份见 [运维说明](ops.md)。

> agent：替你干活的 AI 程序。它按任务的要求，调用模型、工具和浏览器去做事。

## 1. 先弄懂几个词

| 词 | 意思 |
|---|---|
| 任务 | 你要 agent 做的一件事：一句话、目标、可选的步骤，以及它能用哪些配置。任务是模板，可以反复运行 |
| session（一次运行） | 任务每运行一次就是一个 session，编号像 `R-1024-3`。界面上「运行」和「session」是一回事 |
| 步骤 | 建议 agent 怎么做的几步。可以不写，让 agent 自己探索 |
| 等待 | 步骤上的一个勾，告诉 agent「这一步可以停下来等」 |
| 挂起和继续 | 要等时，session 挂起：不占模型、不花钱。等到了（到点、来事件、人处理完）就继续**同一个 session**，前面的上下文和检查点都还在 |
| 检查点 | 步骤上「做到什么算数」的一句话。agent 做完一条勾一条，验收时逐条核对 |
| 目标 | 做到什么算整个任务完成。必填，三方验收按它判断 |
| 三方验收 | agent 说做完了以后，交给另一家公司的模型逐条核对检查点。要在任务里选上一条「交给三方验收」的规则才会做 |
| 规则 | agent 必须守的规矩，用一句话写，系统翻译成程序执行，agent 绕不过。例如「对外发送前要人批准」 |
| 记忆 | agent 要记住的经验和偏好。建任务时选了哪几条，每次运行开始就读到哪几条 |
| 技能 | agent 的操作手册（一份 SKILL.md）。agent 平时只看到技能名和一句话，用得上时再读全文 |
| 工具 | agent 能调用的能力：内部接口（HTTP）、MCP 服务器、系统内置的工具、浏览器 |
| 浏览器配置 | 服务器上的一个 Chrome：自己的代理、一份加密保存的登录状态、几个要登录的网站账号 |
| 模型 | agent 背后的大模型。现在通过 OpenRouter（一个能统一调用各家云端模型的服务）使用 |
| 待办 | 看板页。每次运行一张卡，随状态在五列之间移动；要人办的事、人加的待办也各是一张卡 |
| 要人办的事 | 系统或 agent 需要人拍板、动手时生成的卡：审批、登录、验收争议、记忆审核、技能修改 |
| 人加的待办 | 人往看板里插的一件事：到点、按周期或等到某个事件，就让 agent 去做 |
| 主管 / 员工 | 两种账号。主管能改所有配置；员工能看全部，只能操作自己负责的任务和分给自己的事 |

## 2. 控制台长什么样

- **左边侧边栏**
  - 工作：「任务」「待办」「Session」。「待办」上的数字是等你处理的事。
  - 配置：「记忆」「技能」「规则」「工具」「浏览器」「模型」，主管还能看到「用户」「设置」。
  - 帮助：「看懂架构」，用动画讲平台怎么工作。里面是演示数据，不是你的配置。
- **左下角**：你的名字。点开有「修改密码」「退出」。
- **右上角**：通知按钮（铃铛，有未读时显示数字）、浅色 / 暗色切换（也可以按 D 键）。
- **页面标题旁边的「这是什么？」**：跳到「看懂架构」里对应的那一课。
- **配置页的布局**都一样：左边列表，右边详情；新建按钮在右上角，编辑在详情右上角，删除等在「⋯」里。

## 3. 第一次使用

### 3.1 登录、改密码

1. 用浏览器打开控制台地址：开发机上是 `http://<开发机内网 IP>:8080`，正式服务器的地址问管理员。
2. 管理员账号是 `admin@heyagent.local`。初始密码：
   - 开发机上用 `scripts/pod.sh up` 起的那套：在仓库目录的 `.dev/admin-password` 文件里；
   - 正式服务器：见 [运维说明](ops.md) 第 3 节。
3. 登录后点左下角你的名字 →「修改密码」，填现在的密码和两次新密码（至少 8 位）。改完这个浏览器保持登录，其他设备上的登录会失效。

### 3.2 建同事的账号

控制台不开放注册，账号只能由主管建。

1. 左边「用户」→「新建用户」。
2. 填邮箱（登录用，建好后不能改）、名字、职位（可选）、角色、初始密码（已经随机生成了一个，也可以改）。
3. 把地址、邮箱、初始密码告诉同事，让他登录后自己改密码。

忘了密码：主管在「用户」页选中这个人 →「重置密码」。离职：「停用」，他已登录的会话立刻失效，账号和历史记录都留着，随时可以再「启用」。

**主管和员工的区别**

| 能做什么 | 主管 | 员工 |
|---|---|---|
| 看所有页面、任务、session、配置 | 能 | 能 |
| 新建任务 | 能 | 不能 |
| 编辑、开关、运行、取消、删除任务 | 所有任务 | 自己负责的任务 |
| 处理要人办的事 | 所有 | 分给自己的 |
| 给任务加待办 | 所有任务 | 自己负责的任务 |
| 新建、修改记忆、技能、规则、工具、浏览器配置、模型 | 能 | 不能 |
| 「打开 Chrome 登录」 | 能 | 能 |
| 在远程画面里操作 Chrome | 能 | 自己负责的任务、分给自己处理的事 |
| 手动触发事件 | 能 | 不能 |
| 「用户」「设置」页 | 能 | 看不到 |

所以员工的任务要由主管建，建的时候把「负责人」选成他。系统至少要留一位主管，不能停用自己。建议至少有两位主管。

### 3.3 确认模型

左边「模型」。

- 如果安装时填了 OpenRouter 的 key，这里已经有一个「OpenRouter」服务，状态「已连接」。点进去可以「测试连接」「刷新模型列表」。
- 没有的话：「添加模型服务」→ 类型选 OpenRouter → 填 API Key →「连接并添加」。保存前会先连一次，连不上或 key 不对会告诉你原因，不会保存。
- 点左边列表最上面的「默认设置」，看三个默认模型：

| 角色 | 安装后的默认 | 管什么 |
|---|---|---|
| 执行任务 | Claude Sonnet 5.5 | agent 每一步干活、调工具都用它，花费主要在这里。任务可以单独选别的 |
| 规划 | Claude Opus 5.5 | 保存规则时把那句话翻译成程序能执行的结构；长 session 压缩上下文时写摘要 |
| 三方验收 | Gemini 3.8 Flash | agent 说做完了，由它逐条核对检查点。任务可以单独选别的 |

**验收为什么不能和执行同一家**：同一家的模型容易犯同样的错，自己检查自己看不出来，就不算第三方了。所以系统在三个地方拦：保存默认设置时、建任务和改任务时、运行时再查一次。认「家」看模型所属的厂商（Anthropic、Google、OpenAI 等）。

**注意**：
- 列表里只有支持调用工具的模型（agent 每一步都要调工具）。
- Ollama（公司自己机器上跑的开源模型）还没接：类型里有它，但运行时会报「还没有配置」。现在只用 OpenRouter。
- 发给 OpenRouter 的内容（任务、网页内容、截图）会出境。
- 在 OpenRouter 网站上给 key 设一个花费上限。

## 4. 搭一个任务的顺序

按依赖排：后面的要选前面的。下面每一步的细节在第 5 节。

| 顺序 | 配什么 | 在哪 | 什么时候需要 |
|---|---|---|---|
| 1 | 模型 | 「模型」 | 必须。第 3.3 节已经确认过 |
| 2 | 工具 | 「工具」 | 要调内部接口、外部系统时 |
| 3 | 浏览器 | 「浏览器」 | 要 agent 上网、操作网页时 |
| 4 | 技能 | 「技能」 | 有固定做法要 agent 照着做时 |
| 5 | 记忆 | 「记忆」 | 有偏好、注意事项要 agent 每次都知道时 |
| 6 | 规则 | 「规则」 | 要验收、要审批、要自动记录检查点时（建议都配） |
| 7 | 任务 | 「任务」 | 最后。把上面的选进来 |

一个最小可跑的任务只要第 1 步和第 7 步：写一句话任务、一个目标，「创建并启动」。下面是完整的流程。

### 第 1 步：模型

见 3.3。确认「默认设置」里三个模型都有值，执行和验收不是同一家。

### 第 2 步：工具

1. 「工具」→ 右上角「新建工具」→ 来源选「HTTP 接口」或「MCP 服务器」。
2. HTTP 接口：粘贴一条 cURL 命令 →「导入」→ 补「名称」「给模型看的说明」→ 检查「密钥」→ 选「风险」→「接入这个接口」。
3. MCP 服务器：填名称、连接方式、命令或地址、环境变量 →「存好服务器」→ 再点「编辑服务器」→「连接并读取工具」→ 勾选 →「保存勾选的 N 个工具」。

**系统会拦下**：URL、请求头、请求体、MCP 命令或地址里的明文密钥；模板里引用了 `{{名字}}` 但没存过值。

### 第 3 步：浏览器

1. 「浏览器」→「新建 Chrome」→ 填名称、给 agent 的说明、代理，按出口地选好时区和语言 → 保存。
2. 详情里「登录过的网站」→「加账号」→ 选或输入平台、填域名、账号名、并发上限、登录网址 →「加账号」。
3. 点「打开 Chrome 登录」或账号旁的「去登录」→ 在远程画面里登录 → 关掉画面（关就保存）。

不需要登录的网站，只建 Chrome 配置就够了，不用加账号。

### 第 4 步：技能

1. 「技能」→「新建技能」→ 填名称、岗位、什么时候用、用到的工具、操作手册 →「保存」。新建的是**草稿**。
2. 详情右上角「⋯」→「发布」。**发布后建任务时才能选**。

### 第 5 步：记忆

「记忆」→「新建记忆」→ 填内容、适用于 →「保存」。人建的记忆直接生效。

### 第 6 步：规则

1. 「规则」→「新建规则」→ 填名称、触发条件、命中后怎么办、提到的工具（可选）→「保存并翻译」。
2. 等十几秒，看「系统理解为」。对就点「确认生效」；不对就「改文字」再翻译。

**系统会拦下**：翻译不进去的规则标「未生效（v1 还不支持）」，建任务时选不了。没确认的规则也选不了。

建议先配好这几条通用规则（写法见 5.6）：自动记录检查点、三方验收、对外发送前审批、涉及金钱前主管审批、花费提醒。

### 第 7 步：任务

1. 「任务」→「新建任务」。
2. 必填：「任务」（一句话）、「目标」。
3. 可选：步骤（每步可勾「等待」「检查点」）、「用哪些」（记忆、技能、工具、规则）、选了「浏览器」工具后的浏览器三项、模型、三方验收模型、负责人、附件、定时运行。
4. 「创建并启动」马上跑一次；「只创建」先存着。

**系统会拦下**：没填任务或目标；勾了「检查点」没写内容；执行模型和验收模型同一家；选了没生效的规则；cron 写错；白名单里有不合法的域名。

**别漏了这几个工具**（在「用哪些 → 工具」里选）：
- 要交付表格、文档 → 要选「存文件」；
- 要上网 → 要选「浏览器」。

## 5. 每种配置的细节

### 5.1 模型

- **在哪**：「模型」。只有主管能改。
- **模型服务**：一个 OpenRouter 服务就够了。详情里有「测试连接」「刷新模型列表」，以及可用模型的表格（上下文长度、每百万 token 的价格、能不能看图）。token 是模型计费的单位，大致一个汉字一到两个 token。
- **换 key**：选中服务 →「⋯」→「编辑」→ 填新 key →「测试并保存」。key 留空 = 不改。页面上只显示 key 的前后几位。
- **默认设置**：改完点「保存」。新建任务时按它预选，建任务时还能改。
- **删除服务**：有任务在用它的模型时删不了，要先给这些任务换模型。

### 5.2 工具

在「工具」页。左边分组：每个 MCP 服务器一组、「HTTP 接口」、「内置 · 系统提供」。只有主管能新建、编辑、删除。

#### HTTP 接口

用来让 agent 调一个内部接口或外部 API。

| 字段 | 说明 |
|---|---|
| 从 cURL 导入（可选） | 在浏览器开发者工具里对一个请求点「复制为 cURL」，粘贴进来点「导入」，自动填好方法、URL、请求头、请求体。cURL 是一种用命令行发 HTTP 请求的写法。导入后输入框会清空，因为原命令里可能带着密钥 |
| 名称 | 给人看的名字 |
| 给模型看的说明 | **最重要**。模型只靠这段话判断什么时候用、怎么用。写清楚：干什么的、要传什么、返回什么、什么时候不该用 |
| 方法和 URL | GET / POST / PUT / PATCH / DELETE，URL 以 `http://` 或 `https://` 开头 |
| 请求头 | 每行一个，写成「名字: 值」 |
| 请求体模板 | 一般是 JSON |
| 密钥 | 模板里每个 `{{名字}}` 一个值 |
| 风险 | 只读 / 写入内部数据 / 对外发送 / 涉及金钱。规则可以按风险等级拦，见 5.6 |

**`{参数}` 和 `{{密钥名}}` 的区别**

| 写法 | 谁填 | 模型看得到吗 | 例子 |
|---|---|---|---|
| `{参数}`（一层花括号） | 模型每次调用时填 | 看得到，就是它填的 | `https://api.example.com/items/{item_id}` |
| `{{密钥名}}`（两层花括号） | 系统执行请求时，从密钥库取出真值替换 | **看不到**，模型只看到 `{{API_TOKEN}}` | `Authorization: Bearer {{API_TOKEN}}` |

**为什么不能写明文密钥**：模板会给模型看、会写进过程记录。密钥一旦写进去，模型、日志、看页面的人都能看到。所以：
- 页面上发现明文密钥（`?key=…`、`Authorization: Bearer …`、`"api_key": "…"`、`sk-…` 之类）会标红，并给一个按钮「把 N 个明文密钥挪到这里」，自动换成 `{{名字}}`、把值放进「密钥」里。
- 后端保存时还会再查一遍，有明文就拒绝保存。
- 接口返回的内容里如果出现了密钥原文，系统会换成 `[已隐藏]` 再给模型。

**密钥库**：「工具」页右上角「密钥」。可以单独新建（名字用大写字母、数字、下划线，例如 `API_TOKEN`）、「换值」、删除。值只加密存在服务器上，任何页面都看不到原文。还有工具在用的密钥删不了。密钥是全局的，几个工具可以共用一个。

#### MCP 服务器

MCP（Model Context Protocol）是一种给 AI 接工具的通用协议，很多系统提供现成的 MCP 服务器，接上一个就能得到一组工具。

| 字段 | 说明 |
|---|---|
| 名称 | 给人看的 |
| 连接方式 | **stdio 命令**：在 HeyAgent 服务器（容器）里启动这个命令，通过标准输入输出通信。命令里用到的程序要在容器里有（例如 `npx`）。**HTTP 地址**：MCP 服务已经在别处运行，填它的地址 |
| 环境变量 / 请求头（可选） | 每行一个「名字=值」，一般放密钥。值只加密存在服务器上；也可以写 `{{名字}}` 引用密钥库里的值。编辑时已存的显示成 `••••`，不改就留着 |
| 备注（可选） | 给人看的 |

步骤：
1. 填好点「存好服务器」。这时还没有工具。
2. 选中服务器 →「编辑服务器」→「连接并读取工具」。连上会列出服务器提供的工具；连不上会显示原因。
3. 勾选要加入的工具，给每个选风险等级（第一次默认「写入内部数据」，自己改）→「保存勾选的 N 个工具」。
4. 没勾的工具 agent 看不到。勾了的还要在任务里选上才能用。

注意：
- 换了连接方式，之前存的环境变量或请求头会全部删除，要重新填。
- 删服务器会连同它的工具和存的值一起删，不能恢复。它的工具被任务、规则、技能用着时删不了。
- stdio 的命令在读取工具时由 API 进程起，运行任务时由 worker 进程起。

#### 内置工具

系统自带，不能改、不能删。

| 工具 | 做什么 | 要不要选 |
|---|---|---|
| 勾检查点 | 把检查点标成完成或跳过，跳过必须写理由 | 每个任务都自带 |
| 挂起等待 | 等一段时间或等某个事件，挂起 session | 每个任务都自带 |
| 问人 | 向负责人提问或请人拍板，生成一件要人办的事 | 每个任务都自带 |
| 写下步骤 | agent 写下打算怎么做，中途可以改 | 每个任务都自带 |
| 读取技能 | 读某个技能的全文 | 不用选：任务选了技能，系统自动带上 |
| 提议记忆 | 提议一条记忆，等人审核 | 想让 agent 积累经验时选 |
| 提议修改技能 | 对技能提修改建议，等人审核 | 想让 agent 改进手册时选 |
| 通知员工 | 发站内通知，并推到通知渠道 | 要 agent 主动提醒人时选 |
| 存文件 | 产出文本文件（csv、md、json、txt 等），在运行里能看能下载 | **要交付文件就要选它** |
| 读附件 | 读任务或这次运行带的文件，文本读内容，图片交给模型看 | 不用选：任务或这次运行有附件，系统自动带上 |
| 浏览器 | 开放整组浏览器工具，见下面 | 要上网就要选它 |

建任务时「用哪些 → 工具」下面会写「每个任务都自带：…」，那几个不用选；还会写「选了技能会自动带上读取技能；有附件会自动带上读附件」。

#### 「浏览器」工具

任务选了它，agent 就能用服务器上的 Chrome：选用哪个 Chrome 配置、打开网页、看页面结构、查找、点击、输入、选择、上传文件、截图。

- 截图存成这次运行的文件，作为证据，不会发给 agent。每次打开网页后自动截一张。
- 能执行任意代码的那个工具被系统屏蔽了；「在网页里执行脚本」默认关，要在任务里单独打开。
- 遇到验证码或登录页，系统自动截图、转给人处理（见 6.4）。

### 5.3 浏览器

在「浏览器」页。每个「Chrome 配置」是服务器上的一个 Chrome：自己的代理、一份加密保存的登录状态（cookie 等，网站用来记住你登录过的数据）、几个网站账号。所有任务共用。

#### Chrome 配置

「新建 Chrome」（只有主管）：

| 字段 | 说明 |
|---|---|
| 名称 | 给人看的 |
| 给 agent 的说明 | agent 靠这句话自己选用哪个 Chrome。写清楚出口 IP 在哪、用于哪些网站。不写的话 agent 不会主动选它 |
| 代理 | 「不用代理」或「SOCKS5」（一种代理协议）。SOCKS5 填主机、端口、用户名和密码（可选）。密码只加密存，编辑时留空 = 不改；不再需要密码时勾「去掉已存的密码」 |
| 出口地（可选） | 一句话写这个 Chrome 从哪里出网，例如「英国 · 伦敦」。只是给人看的，系统不会去检测 |
| 时区 | 网页看到的本地时间。从列表里搜城市选（例如 Europe/London），默认 Asia/Shanghai |
| 语言 | 浏览器界面和发给网站的语言，例如 zh-CN、en-US。可以从常用选项里选，也可以直接输入，默认 zh-CN |

注意：
- **同一个账号要一直走同一个出口 IP**，和人登录时一致，不容易被网站风控。
- 代理挂了会报错、通知负责人，**不会退回直连**。
- **时区、语言要和出口地一致**（例如英国出口配 Europe/London、en-GB），不容易被网站风控。改了以后，下一次打开的 Chrome 才按新的来。
- Chrome 详情的「代理、时区和登录态」里能看到出口地、时区、语言；出口地没填就显示「没填」。
- 删除 Chrome 会连同登录状态和账号一起删，不能撤销。正有 session 在用时删不了。

#### 平台、域名和账号

需要登录的网站，在 Chrome 详情的「登录过的网站」里「加账号」（只有主管）：

| 字段 | 说明 |
|---|---|
| 平台 | 选已有的，或直接输入新的网站名，保存时一起建好。平台所有 Chrome 配置共用 |
| 新平台的域名（可选） | 每行一个，子域名也算（填 `example.com` 就包含 `www.example.com`）。agent 打开这些域名下的网址时，才算占用这个账号的并发名额。不填就不限并发。以后在账号的「⋯ → 改平台域名」里改 |
| 账号 | 写人能认出来的名字就行，**不用填密码** |
| 这个账号同时最多几个 session | 1～5。同一个账号多处同时登录容易被风控，风控严的网站建议 1。满了以后，要用它的运行挂起排队，有人用完就叫醒最早的那个 |
| 登录网址（可选） | 「去登录」时远程画面先打开这里；系统也用它检查登录还在不在：打开后没跳到登录页、页面上没有密码框，就算还登录着 |
| 连 IndexedDB 一起存 | 有的网站把登录状态存在 IndexedDB（浏览器里的一种本地数据库）里，只存 cookie 会掉登录。不确定就先不勾 |

新加的账号状态是「登录失效」，要有人登录一次。

#### 打开 Chrome 登录

1. Chrome 详情右上角「打开 Chrome 登录」，或账号旁的「去登录」「⋯ → 重新登录」。服务器上会起一个 Chrome，装上这个配置已有的登录状态，弹出远程画面。
2. 在画面里登录。短信码、验证码也在这里完成。
3. 关掉画面就保存：cookie 和本地存储合并进保险箱（版本号加一），你改过的覆盖原来的；两个人或人和 agent 同时改了同一项，以最后关的为准。再检查各账号（配了登录网址的）是不是真的登录着，结果会弹出来。
4. 登录用的 Chrome 空闲 30 分钟会自动关，同样保存。

员工也能「打开 Chrome 登录」。

#### 运行时登录状态怎么用

每次运行第一次用浏览器时，临时起一个 Chrome，装进这份登录状态；用完先用登录网址确认还登录着，再把**这次变了的** cookie 合并回保险箱，然后关掉。确认没通过就不写回，账号标成需要重新登录。agent 拿不到 cookie。

#### 远程画面怎么用

在三个地方会打开：「打开 Chrome 登录」、运行详情里的「看浏览器」、要人办的事里的「去浏览器里处理」。

- 点一下画面就能直接操作：鼠标、打字、回车、滚动都会发到服务器上的 Chrome。
- **中文**用你本机的输入法直接打。**粘贴**用 Ctrl+V，粘的是你本机剪贴板里的文字。
- 看不到 Chrome 自己的地址栏，用画面上方的地址栏，旁边有后退、前进、刷新；标签页也在上方切换和关闭。
- 网页弹出的提示框、确认框会显示成控制台里的对话框，点「确定」或「取消」。
- 谁都能看画面；能操作的只有任务负责人、被分配处理的人、主管（登录用的 Chrome 是打开它的人和主管）。没权限时显示「只读」。
- 文字多的页面每路画面要几 Mbps 带宽，只在有人看时才传。
- 还不支持：网页里原生的文件选择框、浏览器自己的用户名密码弹框（Basic 认证）。

#### 验证码怎么处理

系统只检测，不破解。每次操作网页后，按网址、页面里的框架、关键词判断是不是验证码页或登录页；拿不准时，如果「设置 → 浏览器」里开了「拿不准时让视觉模型看截图」，会再让一个便宜的视觉模型看一眼（每次花一点钱）。

判断是的话：截图 → 在「待办 → 等人处理」生成一张「登录」卡，分给任务负责人 → session 进入「等人处理」→ Chrome 先保留着（默认 30 分钟）。处理方法见 6.4。

### 5.4 技能

在「技能」页。左边按「岗位」分组。只有主管能新建、编辑、发布、停用。

#### 字段

| 字段 | 说明 |
|---|---|
| 名称 | 给人看的 |
| 岗位 | 只用来分组，选已有的或输入新的 |
| 什么时候用 | **agent 平时只看到这一句**，判断用不用得上。写清楚什么情况下该用、什么情况下不用 |
| 用到的工具（可选） | 写进 SKILL.md 头部，告诉 agent 这个技能要用哪些工具。**任务里还要选上这些工具**，agent 才调得到 |
| 操作手册（Markdown） | SKILL.md 的正文。Markdown 是一种用 `#`、`-`、`1.` 标记标题和列表的纯文本写法。可以切到「预览」看效果 |

#### agent 怎么用它

1. 运行开始时，agent 只看到「技能目录」：每个选中技能的名字和「什么时候用」那一句。
2. 用得上时，它调「读取技能」读出全文，照着做。任务选了技能，系统会自动带上「读取技能」工具，不用另选。
3. 技能只有「已发布」的才能在建任务时选。被任务选用着的技能不能停用。

#### SKILL.md 怎么写才好用

新建时会给一个模板：适用场景、步骤、常见坑。写的时候：

- **一个技能管一类事**。太大的拆开，「什么时候用」才写得清楚。
- **步骤写成动作**，一句一步，写清楚用哪个工具、看什么、拿到什么才算这步完成。
- **写判断标准**。例如「列表为空时先换一个关键词再试一次，还是空就问人」。agent 最容易在没写清楚的分支上乱来。
- **写清楚什么时候停下来问人**：拿不准、要对外发送、要花钱时，用「问人」。
- **写常见坑**：网页上容易点错的地方、接口常见的报错和处理办法。
- **写交付格式**：要产出文件的，写清楚文件名、列名、格式，并让 agent 用「存文件」。
- **不要写密钥、账号密码**。密钥放密钥库，登录交给浏览器配置。
- **不要写会变的数据**（价格、名单）。会变的放附件或接口。

每次保存记一个新版本，下一次运行开始用新版，正在跑的不受影响。

#### agent 提的修改怎么审

任务选了「提议修改技能」工具，agent 发现手册不对时会提修改建议（改完的全文加一句说明）。

- 待办「等人处理」里出现一张「技能修改」卡，分给技能的负责人；技能列表上这个技能标「有修改建议」。
- 审核：在待办里点开卡片看改动，或者去技能页看全文。点「通过并合并」（记为新版本）或「拒绝」（可以写原因）。
- 如果建议提出以后你又手动改过这个技能，合并会失败，要拒绝后让 agent 重新提，或手动改。

### 5.5 记忆

在「记忆」页。左边按「适用于」的分类分组。只有主管能新建、编辑、归档、删除。

#### 写什么

- 写**经验和偏好**：某类对象的偏好、某个系统的注意事项、某种情况下的处理习惯。一条一件事，最多 1000 字，可以用 Markdown。
- 不要写订单、报价这类会变的数据，也不要写密钥。
- 记忆会原样放进 agent 的提示里，标明「人审核过的，必须遵守」。写成清楚的要求，不要写成含糊的感想。

#### 适用于

写成「分类 · 对象」，例如「偏好 · 某部门」，或只写分类。它决定记忆在左边放哪一组，建任务时也靠它找。选已有的，或直接输入新的。

注意：「适用于」只是标签，**系统不会按它自动挑记忆**。任务选了哪几条，每次运行就全部读到哪几条。

#### 怎么用

建任务时在「用哪些 → 记忆」里选。只有「生效」的记忆能选。

- **归档**：不想再用但想留着。选用了它的任务下一次运行就读不到了，归档前会提醒。归档后列表里不再显示。
- **删除**：被任务选用着删不了，先在任务里去掉，或者改成归档。

#### agent 提议的记忆要人审

任务选了「提议记忆」工具，agent 发现以后也该知道的事时会提议一条记忆。

- 状态是「待审核」，不能被任务选用，也不能编辑。
- 待办「等人处理」里出现一张「记忆审核」卡，分给任务负责人。记忆页详情里也有「通过」「拒绝」。
- 记忆详情里有「来源」：agent 根据聊天记录、网页内容还是任务结果提议的，附证据。**标「来自网页，可能不实」的要特别小心**：网页里可能藏着写给 AI 的话，想让它记住假信息。

### 5.6 规则

在「规则」页。只有主管能新建、编辑、删除、翻译、确认。

规则**没有全局的**：建任务时选上哪条，那个任务才守哪条。

#### 用一句话写

| 字段 | 说明 |
|---|---|
| 名称 | 给人看的 |
| 触发条件 | 一两句话：调用哪个工具之前或之后、打开不在白名单的网址、花费超过多少、agent 说做完了…… 写得越具体，翻译越准 |
| 命中后怎么办 | 拦下、交给人审批、截图存证、通知某人、自动记录检查点、交给三方验收 |
| 提到的工具（可选） | 文字里提到的工具，选上能帮系统翻译得更准 |

#### 保存后系统翻译，确认才生效

1. 点「保存并翻译」。规则先存好，再用「规划」模型翻译，一般十几秒，每次花几美分。
2. 弹窗显示「系统理解为：……」。这句话**由程序按翻译结果生成，不是模型写的**，程序就照它执行。
3. 对就点「确认生效」。不对就点「改文字」再翻译。也可以「稍后再确认」，之后在规则详情的「系统理解为」里点「确认生效」或「重新翻译」。

规则有四种状态：

| 状态 | 意思 | 建任务能选吗 | 运行时执行吗 |
|---|---|---|---|
| 未翻译 | 还没翻译（例如翻译时没设规划模型） | 不能 | 不执行 |
| 待确认 | 翻译好了，等主管确认 | 不能 | 不执行 |
| 生效 | 确认过了 | 能 | 执行 |
| 未生效（v1 还不支持） | 翻译不进去 | 不能 | 不执行 |

翻译不进去的，**系统不会退回让 agent 自己判断**。

#### v1 支持哪些触发和动作

| 触发 | 能配的动作 |
|---|---|
| 调用某些工具之前（按工具，或按风险等级：对外发送、涉及金钱）。写「浏览器」表示整组浏览器工具 | 拦下、交给人审批、截图、通知 |
| 调用某些工具之后，或「调用任意工具之后」 | 截图、通知、自动记录检查点 |
| 打开的网址不在某几个域名里 | 拦下、交给人审批、截图、通知 |
| 页面上出现验证码或登录页 | 截图、通知（转人工本来就会做，规则只能再加动作） |
| 这次运行的花费超过多少美元 | 交给人决定要不要继续、通知、拦下（直接结束运行） |
| agent 说做完了 | 交给三方验收、通知 |
| agent 提议记忆或修改技能 | 拦下、通知 |

「交给谁」「通知谁」可以是：任务负责人、主管（审批交给第一位主管，通知发给所有主管）、指定的某个人。一条规则里「拦下」和「交给人审批」只能有一个。

各动作做什么：
- **拦下**：工具不执行，把「被拦下：理由」告诉 agent。
- **交给人审批**：工具先不执行，session 进入「等人处理」，待办里出现「审批」卡。批准才执行；拒绝就把理由告诉 agent，它接着往下做。
- **截图**：这次运行开着 Chrome 时截当前页面存证。
- **通知**：发站内通知，并推到通知渠道。
- **自动记录检查点**：见 5.7 检查点。
- **交给三方验收**：见 6.2。

#### 建议先配的几条

下面是写法示例，可以照抄后按自己的情况改。翻译结果以「系统理解为」为准。

| 名称 | 触发条件 | 命中后怎么办 |
|---|---|---|
| 自动记录检查点 | 调用任意工具之后 | 自动记录检查点 |
| 三方验收 | agent 说做完了 | 交给三方验收 |
| 对外发送前审批 | 调用风险等级为「对外发送」的工具之前 | 先拦下，交给任务负责人批准，批准了才执行 |
| 涉及金钱前主管审批 | 调用风险等级为「涉及金钱」的工具之前 | 交给主管审批 |
| 花费提醒 | 这次运行的花费超过 1 美元 | 挂起，交给任务负责人决定要不要继续 |
| 只访问指定网站 | 打开的网址不在 example.com、example.org 里 | 拦下 |
| 遇到验证码通知主管 | 页面上出现验证码或登录页 | 截图，并通知主管 |

**按风险等级拦，会拦到浏览器**：浏览器的每个操作（打开网页、看页面、点击、输入）在系统里都算「对外发送」。所以「调用对外发送的工具之前 → 审批」这条规则，选在用浏览器的任务上，agent 每动一下浏览器都要人批。这类任务改用按工具名写的规则，例如「调用『某某接口』之前，交给任务负责人批准」，只列真正要管的工具。

**三方验收和检查点自动记录都要靠规则**：任务没选「三方验收」那样的规则，agent 说做完了就直接完成，不验收；没选「自动记录检查点」那样的规则，检查点只有 agent 自己写的记录。

#### 改了文字以后会怎样

- 只改名称或提到的工具、文字没变：翻译结果照旧，不用重新确认。
- 改了触发条件或命中后怎么办：
  - 规则标「按旧版本生效」。在新文字翻译并确认之前，选了它的任务**照旧版本执行**；
  - 新文字翻译不进去：旧版本照常执行；
  - 新文字确认后，之后开始的运行按新版本。
- 已经在跑的运行用的是开始时的那一版。

#### 为什么有的规则「未生效」

常见原因：
- 文字里的工具名对不上系统里的工具。改成工具页上的准确名字，或在「提到的工具」里选上；
- 「交给谁」写成了系统里没有的人；
- 想要的触发或动作 v1 不支持，例如「agent 觉得不对劲时」「每周一」这类要模型自己判断或按时间的条件；
- 触发和动作的组合不支持，例如「调用工具之后 → 交给人审批」（调用后已经执行了，审批不了）。

详情里会写出不支持的原因，按原因改文字再翻译。

#### 删除

没被任务选用的规则直接删，弹出的提示里可以「撤销」。被任务选用着的删不了，会告诉你是哪些任务。

### 5.7 任务

在「任务」页。每个任务一张卡，执行中的排最前。点卡片从右边打开详情。只有主管能新建；负责人和主管能编辑、开关、运行、删除。

#### 新建任务的字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 任务 | 是 | 一句话要 agent 做什么，最多 200 字 |
| 任务步骤 | 否 | 见下面 |
| 目标 | 是 | 做到什么算完成，最多 1000 字。三方验收按它判断 |
| 用哪些 → 记忆、技能、工具、规则 | 否 | agent 只能用这里选的。规则没有默认的，要手动选，只能选已生效的 |
| 浏览器（选了「浏览器」工具才出现） | 否 | Chrome 配置、网址白名单、允许在网页里执行脚本，见下面 |
| 模型 | 否 | 不选用默认执行模型 |
| 三方验收模型 | 否 | 不选用默认验收模型。不能和执行模型同一家 |
| 负责人 | 否 | 默认是你。负责人能开关、运行这个任务，要人办的事默认分给他。建好以后只有主管能改负责人 |
| 附件 | 否 | 每次运行都带上，agent 用「读附件」读（有附件时系统自动带上这个工具） |
| 定时运行 | 否 | 勾上填 cron，见下面 |

#### 步骤：可以不写

- **不写**：agent 自己探索。它开始时用「写下步骤」写下打算怎么做，运行详情里会显示「agent 的步骤」。
- **写**：一句一步，最多 50 步。agent 会参考，但不是死板地照做。
- **存为任务步骤**：agent 探索出的步骤觉得好，在运行详情「agent 的步骤」里点「存为任务步骤」，覆盖掉任务现在的步骤。注意：原来步骤上的检查点会一起去掉，之后在编辑任务里重新勾。

#### 等待

步骤上勾「等待」，告诉 agent 这一步可以挂起等。agent 用「挂起等待」工具挂起，可以：
- 等到某个时间；
- 等某个事件（外部系统发来，或主管手动触发，见 6.6）；
- 两个都给，谁先到谁继续。

只等事件、不给时间的，最多等「设置」里的兜底天数（默认 7 天），到期**只提醒负责人，不会自动继续**。

不勾「等待」agent 也能挂起，勾上是明确告诉它这里该等。

#### 检查点

步骤上勾「检查点」，写这一步做到什么算数。一个输入框里可以用「；」写多条。写完会自动认出类型，显示在输入框旁边：

| 类型 | 怎么写会被认成它 | 怎么算完成 | 能自动记录吗 |
|---|---|---|---|
| 访问 | 带数字，有「访问 / 打开 / 浏览 / 搜 / 对比」，例如「访问了 3 个网站」 | 记到 N 个不同的网址 | 能：浏览器打开网页后记下标题和网址 |
| 发送消息 | 带数字，有「发送 / 发…消息」，例如「给 2 个联系人发消息」 | 记到 N 条发出去的消息 | 能：调了风险为「对外发送」的工具（浏览器除外）后记下发给谁和原文 |
| 数量达标 | 带数字，有「至少 / 不少于 / ≥」，例如「整理出至少 5 条」 | agent 填上数量，到 N | agent 每写一条记录累计一次 |
| 产出文件 | 有「保存 / 文件 / 上传 / 已生成」，例如「汇总表已保存」 | 有一个文件 | 能：「存文件」之后记下文件链接 |
| 人工确认 | 有「已审核 / 已确认 / 已批准 / 审批」，例如「负责人已确认」 | agent 问过人、拿到确认后勾上 | 不能 |
| 说明 | 认不出的都算这类 | agent 写一段说明 | 不能 |

- **自动记录**要任务选上一条「调用任意工具之后 → 自动记录检查点」的规则（见 5.6）。自动记的记录标「自动」，agent 改不了。
- **agent 自己勾**：用「勾检查点」标完成并写结果。做不到的可以标「跳过」，**必须写理由**，验收时会看这个理由。
- 没写步骤的任务，agent 也可以边做边加检查点。

#### 浏览器的三项

| 项 | 说明 |
|---|---|
| Chrome 配置 | 不选 = 全部都能用，agent 按每个配置的说明自己选。只选一个时自动用它 |
| 网址白名单（可以不填） | 每行一个域名，子域名也算。不填就不限制；填了，名单外的网页打不开，agent 会收到原因 |
| 允许在网页里执行脚本 | 打开后 agent 可以在页面里运行 JavaScript，读数据更快，但也能改页面、发请求。不确定就别开 |

#### 定时（cron）

勾「定时运行」，填 cron 表达式：五段，用空格隔开，分别是「分 时 日 月 周」，按上海时间。

| cron | 意思 |
|---|---|
| `0 9 * * *` | 每天 09:00 |
| `0 9 * * 1-5` | 每个工作日 09:00 |
| `0 10 * * 1` | 每周一 10:00 |
| `0 */2 * * *` | 每两小时整点 |
| `30 17 1 * *` | 每月 1 日 17:30 |

输入框下面会显示人话翻译。**每次触发是一次新的运行**。停用任务就不会再按定时运行。不勾就只在点「立即运行」时跑。

#### 附件

- **任务附件**：新建或编辑任务时加，或在任务详情「附件」里上传、移除（编辑时马上生效，不用点保存）。每次运行都带。
- **这次的附件**：只想这一次带的，用「⋯ → 带附件运行…」，见 6.1。
- 单个文件最多 20 MB。文本文件 agent 直接读内容，图片会交给能看图的模型。
- agent 用「读附件」工具读。任务或这次运行有附件时，系统会自动带上这个工具，不用另选。

#### 改、停用、删除

- **编辑**：任务详情底部「⋯ → 编辑」。改动从下一次运行开始生效，正在跑的不受影响。
- **开关**：卡片上或详情底部的「已启动 / 已停用」开关。停用后不能运行，也不会按定时运行。
- **删除**：「⋯ → 删除」。**已经运行过的任务不能删**，运行记录要留着查，只能停用。

## 6. 运行起来以后

### 6.1 启动、取消、继续

在任务详情底部（负责人和主管能用）：

| 操作 | 在哪 | 说明 |
|---|---|---|
| 立即运行 | 底部主按钮 | 马上开始一次新的运行，自动打开这次运行的过程。任务停用时点不了 |
| 带附件运行 | 「⋯ → 带附件运行…」 | 上传这次要带的文件，可以写一句「附加说明」，再「立即运行」。任务本身的附件照样带 |
| 创建并启动 | 新建任务弹窗 | 建好马上跑一次 |
| 立即继续 | 底部主按钮（最近一次运行在「等待中」时） | 不等了，让挂起的 session 马上接着做。运行详情、待办卡片里也有 |
| 去待办处理 | 底部主按钮（最近一次运行在「等人处理」时） | 跳到待办里那件事。「等人处理」不能用「立即继续」，要先处理那件事 |
| 取消运行 | 「⋯ → 取消运行 R-…」，或运行详情的「取消运行」 | 要二次确认，可以写原因。取消后标为失败，不能恢复；在等的事、没处理的待办一起作废。**已经做完的操作（发出去的消息、存下的文件）不会撤回** |

最近一次运行还没结束（执行中、等待中、等人处理、验收中）时，不能再点「立即运行」。

### 6.2 看一次运行的过程

在任务详情的「运行记录」里点一行，或在「Session」页点一行，从右边打开运行详情。所有内容实时刷新。

- **头部**：状态、模型、输入和输出 token、花费、开始和结束时间。右上角有「看浏览器」（这次运行开着 Chrome 时）、「立即继续」、「取消运行」。
- **失败原因**：失败的运行顶部有红色提示，写着原因（模型出错、被取消、到了上限后不继续、验收判定失败等）。
- **检查点**：每条一张小卡，有进度、记录（标「自动」的是规则记的）、跳过理由。agent 标了「正在做」的会显示出来。
- **验收**（有三方验收时）：总结论、每条检查点的「通过 / 不通过 / 存疑」和理由、验收问答（验收模型问、执行 agent 答）、负责人怎么处理的。
- **agent 的步骤**：agent 写下的最后一版步骤，可以「存为任务步骤」。
- **附件和产物**：agent 存的文件、截图、这次带的附件，点了下载。图片能直接看；其他文件一律下载，不在控制台里打开。
- **过程**：每一条记录，带时间。工具调用点开看输入和输出；规则命中、写下步骤、上下文压缩、验收各有小标签；挂起和继续用分隔线标出来。

**三方验收的流程**（任务选了「交给三方验收」规则时）：
1. agent 回复一段总结、不再调工具，就是说做完了。session 进入「验收中」。
2. 验收模型拿到目标、步骤、每条检查点和记录、跳过理由、最终答复、产物摘录、最近的过程记录、截图（模型能看图时），逐条给结论。
3. 全部通过 → 完成。
4. 有不通过或存疑 → 把问题交给执行 agent，它可以说明或补做，再验收。最多「设置 → agent」里的轮数（默认 2：反问一次，还不行就交给人）。
5. 最后一轮还说不清 → 待办里出现「验收争议」，交给任务负责人，见 6.4。

验收的花费也算进这次运行。

**Session 页**：全部 session 的列表，可以按状态筛选、按编号或任务名搜索，右上角有「进行中 · 挂起 · 今天花了」。

### 6.3 待办看板

「待办」页，五列横排，放不下可以左右拖动或用方向键平移：

| 列 | 是什么 |
|---|---|
| 执行中 | session 正在跑 |
| 等人处理 | 要你拍板或动手的事。这里放的是「要人办的事」的卡，被它卡住的运行不单独出卡 |
| 等待中 | session 已挂起，在等时间或事件。卡上写着在等什么、什么时候继续 |
| 验收中 | 三方 AI 在核对检查点 |
| 已完成 | 最近完成的运行 |

人加的待办以「人加的」卡片出现。点任何一张卡从右边打开详情。员工能看全部卡片，只能操作分给自己的。

### 6.4 要人办的事

都在「待办 → 等人处理」列。通知里也会提醒。分给谁就由谁处理，主管能处理所有的。处理完，被卡住的 session **继续同一个**，不新开。

| 类型 | 什么时候出现 | 怎么处理 |
|---|---|---|
| 审批（工具调用） | 规则要求某个工具调用前审批 | 看「要调用的工具」：工具名、参数（像密钥的字段已经换成 `••••`）、哪条规则拦的。点「批准」：照这些参数执行；点「拒绝」：可以写原因，不执行，把理由告诉 agent。下面的「备注」agent 继续时会看到 |
| 审批（问人） | agent 用「问人」请示或提问 | 看「agent 的问题」，按按钮回答（按钮文字由 agent 给，默认「批准 / 不批准」），可以写备注。不管选哪个，agent 都会收到你的回答和备注，自己决定下一步 |
| 审批（花费或步数到了上限） | 一次运行花的钱或调模型的次数到了「设置」里的上限，或者规则「花费超过多少 → 交给人决定」命中 | 「继续」：再给一份额度接着跑（花费的要再确认一次）；「不继续」：运行结束，标为失败 |
| 登录 | 浏览器遇到验证码或登录页 | 见下面 |
| 验收争议 | 三方验收到最后一轮还说不清 | 看验收报告。三选一：「算通过」（运行完成）、「算失败」（要确认，运行标失败）、「补充说明后继续」（必须写说明，带着说明回到同一个 session 接着做，agent 再说做完了会重新验收） |
| 记忆审核 | agent 提议了一条记忆 | 点「批准」或「拒绝」；或「去记忆页看」全文和证据再审 |
| 技能修改 | agent 提了技能修改建议 | 看「操作手册的改动」，点「采纳」或「拒绝」；或去技能页审 |

涉及金钱的事卡片上标「涉及金钱」，批准前要再确认一次。

**处理「登录」卡（验证码、登录页）**：
1. 点开卡片，能看到遇到时的截图。
2. Chrome 还保留着（默认 30 分钟内）：点「去浏览器里处理」，在远程画面里过验证码或登录，然后点「已处理好了」。agent 在**同一个 Chrome**里接着做。
3. 过了保留时间，Chrome 已经关了：点「新开 Chrome 处理」，在画面里处理好，关掉画面（关就保存），再回到卡片点「已处理好了」。agent 继续时会新起一个 Chrome。
4. 处理不了：点次按钮，agent 会收到。

保留时间在「设置 → 浏览器 → 遇到验证码时 Chrome 保留多久」里改。

### 6.5 人加的待办

「待办」页右上角「加一条待办」。员工只能给自己负责的任务加。

| 字段 | 说明 |
|---|---|
| 哪个任务 | 选一个任务 |
| 要 agent 做什么 | 一两句话，到点时交给 agent |
| 什么时候 | 四选一，见下表 |

| 方式 | 意思 |
|---|---|
| 定时一次 | 到这个时间做一次（上海时间） |
| 周期（cron） | 按 cron 反复做，下面有常用写法可以点，会显示接下来 3 次的时间。待办一直有效 |
| 等事件 | 事件发生就做。选「最多等」几天，到期还没等到就提醒加待办的人和负责人，待办还在 |
| 先到先继续 | 事件先发生就马上做，最晚到点也会做。适合「等回复，但到某个时间必须跟进」 |

**到点后**：这个任务有挂起中的 session，就用这句话继续它；没有，就开始一次新的运行，这句话作为附加说明。一次性的待办执行后就结束。

待办详情里：「立即执行」（加的人、任务负责人、主管能点）、「⋯ → 编辑 / 删除」（加的人和主管能用）。主管还能对「等事件」的待办点「手动触发事件」。

### 6.6 外部事件

让别的系统叫醒在等某个事件的 session 或待办。

- **在控制台里**：主管在等事件的运行卡或待办卡上点「手动触发事件」。
- **从外部系统发**：
  1. 主管在「设置 → 外部事件令牌」点「生成新令牌」。令牌**只显示这一次**，马上复制交给外部系统。重新生成后旧的立刻失效；「停用」后外部事件一律拒绝。
  2. 外部系统发 `POST http://<控制台地址>/api/events`，请求头 `Authorization: Bearer <令牌>`，内容 `{"event": "事件名", "data": {...}}`。
- 事件名要和 agent 挂起时等的、或待办里填的**完全一样**（区分大小写）。`data` 不参与匹配，只作为文字交给 agent。

### 6.7 通知

- **站内**：右上角铃铛。有事等你处理、运行完成、运行失败、等了很久还没等到、待办没能触发、agent 用「通知员工」发的，都会出现在这里。点一条跳到对应的页面并标成已读；「全部标为已读」。
- **推到外部**：主管在「设置 → 通知渠道」加飞书群机器人、企业微信群机器人或通用 webhook（别的系统接收消息的一个网址）。除了「运行完成」，站内通知都会同时推到所有启用的渠道（有事等人处理、运行失败、等太久、待办没能触发、规则发的通知、agent 用「通知员工」发的）。地址加密存，编辑时留空 = 不改；可以停用、删除。

### 6.8 花费和上限

主管在「设置」页改，对所有任务生效：

| 设置 | 默认 | 说明 |
|---|---|---|
| 运行上限 → 单个 session 花费上限 | 2 美元 | 超过就生成一件「花费到了上限，要不要继续」，session 挂起等人决定 |
| 运行上限 → 单个 session 最多步数 | 100 | 一步 = 调一次模型。超过同样等人决定 |
| 运行上限 → 只等事件时的兜底天数 | 7 天 | 到期只提醒负责人，不自动继续 |
| agent → 三方验收最多几轮 | 2 | 填 1 = 不反问，直接交给人 |
| agent → 上下文超过多少就压缩 | 0 | 0 = 按模型上下文的 60% 算。超过就把较早的大块工具输出换成摘要，全文另存成文件 |
| 浏览器 → 每个 worker 同时最多开几个 Chrome | 4 | 每个 Chrome 大约 1 核 CPU、几百 MB 内存。满了要用浏览器的运行排队。worker 是后台真正跑 agent 的进程 |
| 浏览器 → 遇到验证码时 Chrome 保留多久 | 30 分钟 | 见 6.4 |
| 浏览器 → 拿不准时让视觉模型看截图 | 关 | 见 5.3 |

改了立即对所有运行生效。想给某个任务单独设一个更低的花费门槛，用规则「花费超过多少 → 交给人决定」。

花费在运行详情的头部、任务详情的运行记录、Session 页右上角「今天花了」里看。

## 7. 常见问题

**任务一直「等待浏览器」**

有两种排队，看过程里那条「等待浏览器」的说明：
- **这台 worker 的 Chrome 满了**：同时开着的 Chrome 到了「设置 → 浏览器」里的上限。人开的登录 Chrome 也占名额，用完点「关闭」。可以调高上限（服务器要扛得住）。排 10 分钟还没排上，这次浏览器调用会失败，agent 会收到原因。
- **账号的并发满了**：「浏览器」页对应账号写着「同时最多 N 个 · 现在 N 个在用 · N 个在排队」，旁边是在用的 session。session 会挂起排队，前面的用完就叫醒。卡住不动的话，看在用的那几个 session 是不是停在「等人处理」，处理掉或取消它；也可以调高这个账号的并发上限（风控严的网站不建议）。

**规则「未生效」或建任务时选不了**

- 「未翻译」：多半是翻译时没设规划模型或模型出错。去「模型 → 默认设置」看规划模型，再到规则详情点「翻译」。
- 「待确认」：在规则详情点「确认生效」。
- 「未生效（v1 还不支持）」：看详情里写的原因，按 5.6「为什么有的规则未生效」改文字，再「保存并翻译」。

**验收总是存疑**

- 目标写具体：写可以核对的结果，不要写「做好」「尽量」。
- 检查点写具体、可数：「访问了 3 个网站」比「多看几个网站」好核对。
- 选上「自动记录检查点」规则，让记录由系统写，不只靠 agent 自己说。
- 选上「存文件」，让 agent 把结果存成文件；验收模型能读到产物摘录。
- 用网页的任务，验收模型选一个能看图的，它才能看截图。
- 看验收报告里每条的理由，缺什么就在技能或任务里写清楚要 agent 留下什么证据。
- 碰到验收争议时，用「补充说明后继续」告诉 agent 缺什么。

**agent 卡在验证码**

- 去「待办 → 等人处理」找「登录」卡，按 6.4 处理。
- 想少碰验证码：先用「打开 Chrome 登录」登录好；每个账号并发设 1；配固定出口 IP 的代理；在技能里写明访问别太快。
- 系统不会自动破解验证码。

**agent 说「工具不在本任务允许的范围里」**

任务没选这个工具。编辑任务，在「用哪些 → 工具」里选上。技能里列了工具也一样要在任务里选。

**agent 没按技能做**

- 技能是不是「已发布」、任务里选了没有（选了技能，「读取技能」工具会自动带上）；
- 「什么时候用」那一句有没有写清楚，agent 只看这一句决定读不读。

**agent 读不到附件、交不出文件**

- 附件：「读附件」工具在有附件时自动带上。看运行详情「附件和产物」里有没有这个文件，没有就是没传上。
- 交文件：任务要选「存文件」工具。

**建任务时提示「同一家」**

执行模型和验收模型（任务没选验收模型时用默认的）是同一家厂商。换一个。

**改了任务，正在跑的运行没变**

每次运行开始时会把任务当时的配置冻结下来，之后改任务只影响下一次运行。

**新建的技能、agent 提议的记忆，建任务时选不到**

技能要先「发布」；记忆要审核通过。

**删不掉记忆、规则、工具、技能**

正被任务（或规则、技能）用着。提示里会列出是谁在用，先在那些地方去掉。

**模型调用全部失败**

「模型」页看 OpenRouter 的状态，点「测试连接」。常见原因：key 被停用、余额不足、OpenRouter 上的花费上限到了、服务器连不上外网。

**看不到某个按钮**

员工只能操作自己负责的任务和分给自己的事，配置页只能看。详情顶部会写「负责人是某某，你只能查看」。

## 8. 现在还做不到的

- 桌面软件自动化：推迟了，有具体要操作的软件时再加。
- 一个任务拆给多个 agent 并行：没有，一个 agent 按顺序做。
- Ollama（内网模型）：还没接，只能用 OpenRouter。
- 出口 IP 不会自动检测：「出口地」只是配置里写的一句话。
- 代理只能选不用代理或 SOCKS5。
- 远程画面：网页原生的文件选择框、浏览器的用户名密码弹框还不支持。
- 记忆不会按内容自动挑选，要建任务时手选。
- 「存文件」只能存文本格式（csv、md、json、txt 等）。上传的文件最多 20 MB；文件不能在控制台里删除。
- 外部事件只按事件名匹配，带的数据不参与匹配。
- Session 页一次加载全部记录，运行多了以后会变慢。

## 9. 安全提醒

- **只在内网用**。v1 是 HTTP，账号密码和页面内容在网络上是明文。不要映射到外网。
- **密钥只写在密钥库里**：「工具 → 密钥」、MCP 的环境变量、模型的 API Key、代理密码。不要写进工具说明、技能、记忆、任务、规则里，这些都会给模型看。
- **对外动作配审批规则**：发消息、发邮件、花钱这类工具，风险选「对外发送」或「涉及金钱」，任务里选上对应的审批规则。用浏览器的任务按工具名写审批规则（见 5.6）。
- **网页内容不可信**：网页里可能藏着写给 AI 的话。agent 提议的记忆、尤其是「来自网页，可能不实」的，要仔细审；不需要时别开「允许在网页里执行脚本」；能用网址白名单就用。
- **浏览器账号用专用的**，不要用员工的个人账号，登录状态所有任务共用。
- **数据出境**：发给 OpenRouter 的任务内容、网页内容、截图会出境。特别敏感的任务先别跑。
- **人员变动**：离职的人当天在「用户」页停用；至少留两位主管。
