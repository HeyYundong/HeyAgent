# HeyAgent 使用手册

给在控制台里配置 agent 任务的人看。讲清楚怎么从零搭出一个能跑的任务，以及每样配置是什么、在哪配、要注意什么。

可以从头读，也可以按目录查。按钮、页面的名字和控制台界面上的一致。安装、升级、备份见 [运维说明](ops.md)。

> agent：替你干活的 AI 程序。它按任务的要求，调用模型、工具和浏览器去做事。

## 1. 先弄懂几个词

| 词 | 意思 |
|---|---|
| 任务 | 你要 agent 做的一件事：一句话、目标、可选的步骤，以及它能用哪些配置。任务是模板，可以反复运行 |
| session（一次运行） | 任务每运行一次就是一个 session，编号像 `R-1024-3`。界面上「运行」和「session」是一回事 |
| 步骤 | 建议 agent 怎么做的几步。可以不写，让 agent 自己探索 |
| 等待 | 步骤上的一个勾，告诉 agent「这一步可以停下来等」 |
| 挂起和继续 | 要等时，session 挂起：不占模型、不花钱。等到了（到点、来事件、人处理完）就继续**同一个 session**，前面的上下文和检查点都还在 |
| 检查点 | 步骤上「做到什么算数」的一句话。agent 做完一条勾一条，验收时逐条核对 |
| 目标 | 做到什么算整个任务完成。必填，三方验收按它判断 |
| 三方验收 | agent 说做完了以后，交给另一家公司的模型逐条核对检查点。要在任务里选上一条「交给三方验收」的规则才会做 |
| 状态和结果 | 运行有两列：**状态**只管流程（执行中、等待中、验收中、已结束、出错……），**结果**看事情办没办成，只有办成、没办成两种。只看任务目标要的东西拿没拿到，要找的东西没找到（包括确认「没有」）、只拿到一部分，都是没办成。见 6.2 |
| AI 复核 | 运行结束后，用一个便宜的模型看一遍目标、检查点、agent 的报告和最后几步，判办没办成。一定做（三方验收通过的除外），每个任务都要选复核模型；复核也判办成才算办成 |
| 规则 | agent 必须守的规矩，用一句话写，系统翻译成程序执行，agent 绕不过。例如「对外发送前要人批准」 |
| 记忆 | agent 要记住的经验和偏好。建任务时选了哪几条，每次运行开始就读到哪几条 |
| 任务记忆 | 只属于一个任务的经验，在任务详情里直接写、改。运行结束后也可以让三方 AI 总结那次运行、提取经验，人审核通过的才记进来。每次运行开始全部读到 |
| 技能 | agent 的操作手册（一份 SKILL.md）。agent 平时只看到技能名和一句话，用得上时再读全文 |
| 工具 | agent 能调用的能力：内部接口（HTTP）、MCP 服务器、系统内置的工具、浏览器 |
| 浏览器配置 | 服务器上的一个 Chrome：自己的代理、一份加密保存的登录状态、几个要登录的网站账号 |
| 模型 | agent 背后的大模型。通过 OpenRouter（一个能统一调用各家云端模型的服务）使用，也可以直连 Claude、OpenAI、DeepSeek 的官方接口 |
| 待办 | 看板页。每次运行一张卡，随状态在五列之间移动；要人办的事、人加的待办也各是一张卡 |
| 要人办的事 | 系统或 agent 需要人拍板、动手时生成的卡：审批、登录、验收争议、记忆审核、技能修改 |
| 人加的待办 | 人往看板里插的一件事：到点、按周期或等到某个事件，就让 agent 去做 |
| 派活 / 派活单 | 一个任务的 agent（或人）把一件件事派给另一个任务去办，一件事一张「派活单」，编号像 `W-57`。平台按被派任务的名额一张单开一次运行，办完把结果写回单上；同一件事只办一次 |
| 导入 | 把别的 agent 打的 zip 包交给 AI 读懂，整理成这里的任务、技能、记忆、规则和工具，主管一步步确认后一次导入 |
| 主管 / 员工 | 两种账号。主管能改所有配置；员工能看全部，只能操作自己负责的任务和分给自己的事 |

## 2. 控制台长什么样

- **左边侧边栏**
  - 工作：「任务」「待办」「会话」「派活」。「待办」上的数字是等你处理的事。
  - 资源：「图库」「比物」「浏览器」。
  - 配置：「记忆」「技能」「规则」「工具」「模型」。
  - 管理（只有主管看得见）：「用户」「设置」「导入」。
  - 帮助：「看懂架构」，用动画讲平台怎么工作。里面是演示数据，不是你的配置。
- **左下角**：你的名字。点开有「修改密码」「退出」。
- **右上角**：通知按钮（铃铛，有未读时显示数字）、浅色 / 暗色切换（也可以按 D 键）。
- **页面标题旁边的「这是什么？」**：跳到「看懂架构」里对应的那一课。
- **配置页的布局**都一样：左边列表，右边详情；新建按钮在右上角，编辑在详情右上角，删除等在「⋯」里。

## 3. 第一次使用

### 3.1 设置管理员、登录、改密码

1. 用浏览器打开控制台地址：开发机上是 `http://<开发机内网 IP>:8080`，正式服务器的地址问管理员。
2. 全新的环境第一次打开，看到的是「设置管理员」页：填你的名字、邮箱（登录用，建好后不能改）和两次密码（至少 8 位），点「建好并登录」就进了控制台，你就是主管。没有默认账号和密码。
3. 以后打开是登录页，用自己的邮箱和密码登录。
4. 改密码：点左下角你的名字 →「修改密码」，填现在的密码和两次新密码（至少 8 位）。改完这个浏览器保持登录，其他设备上的登录会失效。

### 3.2 建同事的账号

控制台不开放注册，账号只能由主管建。

1. 左边「用户」→「新建用户」。
2. 填邮箱（登录用，建好后不能改）、名字、职位（可选）、角色、初始密码（已经随机生成了一个，也可以改）。
3. 把地址、邮箱、初始密码告诉同事，让他登录后自己改密码。

忘了密码：主管在「用户」页选中这个人 →「重置密码」。离职：「停用」，他已登录的会话立刻失效，账号和历史记录都留着，随时可以再「启用」。

**主管和员工的区别**

| 能做什么 | 主管 | 员工 |
|---|---|---|
| 看所有页面、任务、session、配置 | 能 | 能 |
| 新建任务 | 能 | 不能 |
| 编辑、开关、运行、取消、删除任务 | 所有任务 | 自己负责的任务 |
| 处理要人办的事 | 所有 | 分给自己的 |
| 给任务加待办 | 所有任务 | 自己负责的任务 |
| 新建、修改记忆、技能、规则、工具、浏览器配置、模型 | 能 | 不能 |
| 「打开 Chrome」 | 能 | 能 |
| 在远程画面里操作 Chrome | 能 | 自己负责的任务、分给自己处理的事 |
| 手动触发事件 | 能 | 不能 |
| 「用户」「设置」页 | 能 | 看不到 |

所以员工的任务要由主管建，建的时候把「负责人」选成他。系统至少要留一位主管，不能停用自己。建议至少有两位主管。

### 3.3 确认模型

左边「模型」。

- 如果安装时填了 OpenRouter 的 key，这里已经有一个「OpenRouter」服务，状态「已连接」。点进去可以「测试连接」「刷新模型列表」。
- 没有的话：「添加模型服务」→ 类型选 OpenRouter → 填 API Key →「连接并添加」。保存前会先连一次，连不上或 key 不对会告诉你原因，不会保存。
- 也可以直连厂商：类型选 Claude、OpenAI 或 DeepSeek，填在厂商官网申请的 API Key。厂商的模型列表里没有价格，系统按模型名到 OpenRouter 的公开目录查（不用 key、不花钱）；查不到的模型价格显示「未知」，用它时花费按 0 算，花费上限管不住，添加时会提醒。
- 点左边列表最上面的「默认设置」，看三个默认模型：

| 角色 | 安装后的默认 | 管什么 |
|---|---|---|
| 执行任务 | Claude Sonnet 5.5 | agent 每一步干活、调工具都用它，花费主要在这里。任务可以单独选别的 |
| 规划 | Claude Opus 5.5 | 保存规则时把那句话翻译成程序能执行的结构；长 session 压缩上下文时写摘要 |
| 三方验收 | Gemini 3.8 Flash | agent 说做完了，由它逐条核对检查点。任务可以单独选别的 |

下面还有几项：「助手」（可以不选）、「复核模型」（新任务默认用的复核模型，便宜、能看图的就够，例如 DeepSeek V4.1 Flash；建议选上，不选的话每个任务都要自己选）和「图库的 embedding 模型」（可以不选）。

**验收为什么不能和执行同一家**：同一家的模型容易犯同样的错，自己检查自己看不出来，就不算第三方了。所以系统在三个地方拦：保存默认设置时、建任务和改任务时、运行时再查一次。认「家」看模型所属的厂商（Anthropic、Google、OpenAI 等）。

**注意**：
- 列表里只有支持调用工具的模型（agent 每一步都要调工具）。
- Ollama（公司自己机器上跑的开源模型）还没接：类型里有它，但运行时会报「还没有配置」。现在只用 OpenRouter。
- 发给 OpenRouter 或直连厂商的内容（任务、网页内容、截图）会出境。
- 在 OpenRouter 或厂商的网站上给 key 设一个花费上限。
- 直连时的花费是按单价估的（缓存命中按厂商的折扣算），和账单会有出入，以厂商后台为准。

## 4. 搭一个任务的顺序

按依赖排：后面的要选前面的。下面每一步的细节在第 5 节。

| 顺序 | 配什么 | 在哪 | 什么时候需要 |
|---|---|---|---|
| 1 | 模型 | 「模型」 | 必须。第 3.3 节已经确认过 |
| 2 | 工具 | 「工具」 | 要调内部接口、外部系统时 |
| 3 | 浏览器 | 「浏览器」 | 要 agent 上网、操作网页时 |
| 4 | 技能 | 「技能」 | 有固定做法要 agent 照着做时 |
| 5 | 记忆 | 「记忆」 | 有偏好、注意事项要 agent 每次都知道时 |
| 6 | 规则 | 「规则」 | 要验收、要审批、要自动记录检查点时（建议都配） |
| 7 | 任务 | 「任务」 | 最后。把上面的选进来 |

一个最小可跑的任务只要第 1 步和第 7 步：写一句话任务、一个目标，「创建并启动」。下面是完整的流程。

### 第 1 步：模型

见 3.3。确认「默认设置」里三个模型都有值，执行和验收不是同一家。

### 第 2 步：工具

1. 「工具」→ 右上角「新建工具」→ 来源选「HTTP 接口」或「MCP 服务器」。
2. HTTP 接口：粘贴一条 cURL 命令 →「导入」→ 补「名称」「给模型看的说明」→ 检查「密钥」→ 选「风险」→「接入这个接口」。
3. MCP 服务器：填名称、连接方式、命令或地址、环境变量 →「存好服务器」→ 再点「编辑服务器」→「连接并读取工具」→ 勾选 →「保存勾选的 N 个工具」。

**系统会拦下**：URL、请求头、请求体、MCP 命令或地址里的明文密钥；模板里引用了 `{{名字}}` 但没存过值。

### 第 3 步：浏览器

1. 「浏览器」→「新建 Chrome」→ 填名称、给 agent 的说明、代理，按出口地选好时区和语言 → 保存。
2. 详情里「登录过的网站」→「加账号」→ 选或输入平台、填域名、账号、密码、登录网址、并发上限 →「加账号」。
3. 存了密码的点账号旁的「立刻登录」，agent 在后台登录好；没存密码的点「人工登录」→ 在远程画面里登录 → 关掉画面（关就保存）。

不需要登录的网站，只建 Chrome 配置就够了，不用加账号。

### 第 4 步：技能

1. 「技能」→「新建技能」→ 填名称、岗位、什么时候用、用到的工具、操作手册 →「保存」。新建的是**草稿**。
2. 详情右上角「⋯」→「发布」。**发布后建任务时才能选**。

### 第 5 步：记忆

「记忆」→「新建记忆」→ 填内容、适用于 →「保存」。人建的记忆直接生效。

### 第 6 步：规则

1. 「规则」→「新建规则」→ 填名称、触发条件、命中后怎么办、提到的工具（可选）→「保存并翻译」。
2. 等十几秒，看「系统理解为」。对就点「确认生效」；不对就「改文字」再翻译。

**系统会拦下**：翻译不进去的规则标「未生效（v1 还不支持）」，建任务时选不了。没确认的规则也选不了。

建议先配好这几条通用规则（写法见 5.6）：自动记录检查点、三方验收、对外发送前审批、涉及金钱前主管审批、花费提醒。

### 第 7 步：任务

1. 「任务」→「新建任务」。
2. 必填：「任务」（一句话）、「目标」。
3. 可选：步骤（每步可勾「等待」「检查点」）、「用哪些」（记忆、技能、工具、规则）、选了「浏览器」工具后的浏览器几项、模型、三方验收模型、负责人、附件、定时运行。
4. 「创建并启动」马上跑一次；「只创建」先存着。

**系统会拦下**：没填任务或目标；勾了「检查点」没写内容；执行模型和验收模型同一家；选了没生效的规则；cron 写错；白名单里有不合法的域名。

**别漏了这几个工具**（在「用哪些 → 工具」里选）：
- 要交付表格、文档 → 要选「存文件」；
- 要上网 → 要选「浏览器」。

## 5. 每种配置的细节

### 5.1 模型

- **在哪**：「模型」。只有主管能改。
- **模型服务**：一个 OpenRouter 服务就够了；想直连厂商就再加 Claude、OpenAI 或 DeepSeek（同一家的模型不管走哪条线路都算同一家，验收照样不许同一家）。详情里有「测试连接」「刷新模型列表」，以及可用模型的表格（上下文长度、每百万 token 的价格、能不能看图）。token 是模型计费的单位，大致一个汉字一到两个 token。
- **换 key**：选中服务 →「⋯」→「编辑」→ 填新 key →「测试并保存」。key 留空 = 不改。页面上只显示 key 的前后几位。
- **默认设置**：改完点「保存」。新建任务时按它预选，建任务时还能改。
- **复核模型**：也在「默认设置」里，是新任务预填的复核模型（见 6.2「状态和结果」），以前没选复核模型的旧任务运行时也用它。用便宜、能看图的模型就够，每次不到 0.001 美元，花费记在那次运行上；不能看图的模型复核时不带截图。清空以后，新任务要自己选复核模型，没选过复核模型的旧任务不能运行（提示「任务没设复核模型，先在任务里选一个」）。
- **图库的 embedding 模型**：也在「默认设置」里，图库的以图搜图、比对、按描述找图用它（默认 Gemini Embedding 2，一张图约 0.0001 美元）。只列能处理图片的 embedding 模型；清空 = 不用（图库照样能传图、按标签和字段找）。换了以后后台用新模型把所有图重算一遍，算完之前检索还用旧模型。模型服务详情里的「embedding 模型」表列出这家所有的 embedding 模型。
- **删除服务**：有任务在用它的模型时删不了，要先给这些任务换模型。

### 5.2 工具

在「工具」页。左边分组：每个 MCP 服务器一组、「HTTP 接口」、「内置 · 系统提供」。只有主管能新建、编辑、删除。

#### HTTP 接口

用来让 agent 调一个内部接口或外部 API。

| 字段 | 说明 |
|---|---|
| 从 cURL 导入（可选） | 在浏览器开发者工具里对一个请求点「复制为 cURL」，粘贴进来点「导入」，自动填好方法、URL、请求头、请求体。cURL 是一种用命令行发 HTTP 请求的写法。导入后输入框会清空，因为原命令里可能带着密钥 |
| 名称 | 给人看的名字 |
| 给模型看的说明 | **最重要**。模型只靠这段话判断什么时候用、怎么用。写清楚：干什么的、要传什么、返回什么、什么时候不该用 |
| 方法和 URL | GET / POST / PUT / PATCH / DELETE，URL 以 `http://` 或 `https://` 开头 |
| 请求头 | 每行一个，写成「名字: 值」 |
| 请求体模板 | 一般是 JSON |
| 密钥 | 模板里每个 `{{名字}}` 一个值 |
| 风险 | 只读 / 写入内部数据 / 对外发送 / 涉及金钱。规则可以按风险等级拦，见 5.6 |

**`{参数}` 和 `{{密钥名}}` 的区别**

| 写法 | 谁填 | 模型看得到吗 | 例子 |
|---|---|---|---|
| `{参数}`（一层花括号） | 模型每次调用时填 | 看得到，就是它填的 | `https://api.example.com/items/{item_id}` |
| `{{密钥名}}`（两层花括号） | 系统执行请求时，从密钥库取出真值替换 | **看不到**，模型只看到 `{{API_TOKEN}}` | `Authorization: Bearer {{API_TOKEN}}` |

**为什么不能写明文密钥**：模板会给模型看、会写进过程记录。密钥一旦写进去，模型、日志、看页面的人都能看到。所以：
- 页面上发现明文密钥（`?key=…`、`Authorization: Bearer …`、`"api_key": "…"`、`sk-…` 之类）会标红，并给一个按钮「把 N 个明文密钥挪到这里」，自动换成 `{{名字}}`、把值放进「密钥」里。
- 后端保存时还会再查一遍，有明文就拒绝保存。
- 接口返回的内容里如果出现了密钥原文，系统会换成 `[已隐藏]` 再给模型。

**密钥库**：「工具」页右上角「密钥」。可以单独新建（名字用大写字母、数字、下划线，例如 `API_TOKEN`）、「换值」、删除。值只加密存在服务器上，任何页面都看不到原文。还有工具在用的密钥删不了。密钥是全局的，几个工具可以共用一个。

#### MCP 服务器

MCP（Model Context Protocol）是一种给 AI 接工具的通用协议，很多系统提供现成的 MCP 服务器，接上一个就能得到一组工具。

| 字段 | 说明 |
|---|---|
| 名称 | 给人看的 |
| 连接方式 | **stdio 命令**：在 HeyAgent 服务器（容器）里启动这个命令，通过标准输入输出通信。命令里用到的程序要在容器里有（例如 `npx`）。**HTTP 地址**：MCP 服务已经在别处运行，填它的地址 |
| 环境变量 / 请求头（可选） | 每行一个「名字=值」，一般放密钥。值只加密存在服务器上；也可以写 `{{名字}}` 引用密钥库里的值。编辑时已存的显示成 `••••`，不改就留着 |
| 备注（可选） | 给人看的 |

步骤：
1. 填好点「存好服务器」。这时还没有工具。
2. 选中服务器 →「编辑服务器」→「连接并读取工具」。连上会列出服务器提供的工具；连不上会显示原因。
3. 勾选要加入的工具，给每个选风险等级（第一次默认「写入内部数据」，自己改）→「保存勾选的 N 个工具」。
4. 没勾的工具 agent 看不到。勾了的还要在任务里选上才能用。

注意：
- 换了连接方式，之前存的环境变量或请求头会全部删除，要重新填。
- 删服务器会连同它的工具和存的值一起删，不能恢复。它的工具被任务、规则、技能用着时删不了。
- stdio 的命令在读取工具时由 API 进程起，运行任务时由 worker 进程起。

系统自带，不能改、不能删。

| 工具 | 做什么 | 要不要选 |

| 勾检查点 | 把检查点标成完成或跳过，跳过必须写理由 | 每个任务都自带 |
| 挂起等待 | 等一段时间或等某个事件，挂起 session | 每个任务都自带 |
| 问人 | 向负责人提问或请人拍板，生成一件要人办的事 | 每个任务都自带 |
| 写下步骤 | agent 写下打算怎么做，中途可以改 | 每个任务都自带 |

#### 「浏览器」工具

任务选了它，agent 就能用服务器上的 Chrome：打开网页、看页面结构、查找、点击、输入、选择、上传文件、截图。

- 用哪个 Chrome 由系统分配：运行第一次用浏览器时，从任务允许的 Chrome 里按顺序挑一个空闲的。**每个 Chrome 同一时间只给一个运行用**，所以任务允许几个 Chrome，最多就有几个运行同时用浏览器；都被占着时，后来的运行挂起「等待浏览器」，有一个空出来就按挂起的先后叫醒。
- **一次运行从头到尾只用一个 Chrome**，分到以后不会换。挂起再继续时这个 Chrome 被别的运行占着，就等它空出来。
- 任务要求用某个特定的 Chrome 时，agent 可以在第一次用浏览器之前用「指定 Chrome」选它（被占着就等它）；已经分到 Chrome 以后再指定别的会被拒绝。

- 截图存成这次运行的文件，作为证据，不会发给 agent（除非任务打开了「允许看画面」、agent 自己要看）。每次打开网页后自动截一张。
- **剪贴板**：agent 能像人一样复制粘贴，在线表格、在线文档（腾讯文档、飞书、WPS、Google Sheets 这类，格子画在画布上，agent 平时「看不见」格子）用得上：
  - 读一大块数据：在名称框里填区域（例如 A1:H200）选中，复制后读剪贴板，按行列拿到整块内容；太长的分段读，完整内容也存成文件。
  - 写一大块数据：点到起始格，把整张表一次粘贴进去，比一格一格输入快得多；写完再选中读回来核对。
  - 复制网页上的图片（相当于「右键 → 复制图片」），再贴进在线文档或表格；取的是原图（经这个 Chrome 的代理和登录态），拿不到就截那块图。复制的图、读到的图片存成这次运行的文件，在「空间文件」里标着「剪贴板」（在 clipboard/ 目录下）。
  - 只能在 https 网页上用（Chrome 的规定）。各平台的具体操作（名称框在哪、快捷键）写在技能里，可以参考 `docs/skills/online-sheets.md` 的草稿。
- 在网页里下载的文件（例如内部系统的「导出 Excel」）自动存成这次运行的文件，不弹「另存为」，不限大小；新标签页里打开的下载、网页自己生成的文件也算。agent 在下一次浏览器操作的结果里会看到「下载了 报表.xlsx（文件 f-…）」，再用「读附件」读。人在远程画面里点的下载也一样存下来。运行详情的「空间文件」里标着「浏览器下载」。
- 能执行任意代码的那个工具被系统屏蔽了；「在网页里执行脚本」默认关，要在任务里单独打开。
- 「允许看画面」默认关：打开后 agent 可以截当前画面发给模型看、按坐标点击拖动（在线表格、画布类网页用得上）。每看一次多花一张图的模型费用，agent 只在快照看不到时才看。
- 遇到简单的验证码，系统先自己试着过；过不了的验证码和登录页，系统自动截图、转给人处理（见 5.3「验证码怎么处理」、6.4）。

#### 「运行代码」工具

任务选了它，agent 就能写一段 Python、Node.js 或 bash 代码，在服务器上的一个隔离沙箱里跑，拿到结果再接着做。适合处理表格、清洗数据、批量改文件、算数、调公开的 HTTP 接口。

- **语言**：Python 3.12、Node.js 24、bash。agent 可以直接给代码，也可以先用「存文件」把脚本存成 `scripts/clean.py` 这样的文件，再让它运行这个文件（要反复改的代码适合这样）。
- **文件在哪**：这次运行的空间文件挂在沙箱里的 `/workspace`，路径和「空间文件」里看到的一样。agent 写的文件可以直接读、改、删、新建，跑完新增、改动、删掉的会同步回空间，在「空间文件」里看得到。`attachments/`（附件）、`downloads/`（浏览器下载）、`screenshots/`（截图）、`tool-outputs/`（工具输出全文）这四个目录是只读的，能读不能改；agent 自己存的文件不能用这几个目录开头的路径。
- **上网**：只能访问公网的 HTTP / HTTPS，而且要经过系统的出网代理；内网地址、本机地址一律被拦。沙箱里没有任何密钥、登录状态，也碰不到浏览器。
- **装包**：可以 `pip install`、`npm install`，但只在这一次运行里有效，下一次运行要重新装（装包要上公网下载，所以也算上网）。
- **限制**：默认最多跑 60 秒，agent 可以要求更长，最多 600 秒，到时间整组进程被杀掉；内存最多 1 GB。
- **风险**：因为能上公网，这个工具的风险算「对外」，选它之前想清楚任务要不要让 agent 写代码联网。

在运行详情的「过程」里，运行代码的那一步点开能看到：语言徽章、代码（带高亮；运行已有文件的显示「运行 scripts/x.py」和参数）、标准输入、退出码徽章（0 是通过，非 0 或超时是红色）、「写回空间」（新建、覆盖、删掉了哪些文件）、「访问了」（连过哪些网站，被拦的也列出）、stdout 和 stderr 各一块。退出码不是 0 不算工具出错，agent 会自己看输出再改。输出太长时只保留最后一部分，全文存成「工具输出全文」。

### 5.3 浏览器

在「浏览器」页。每个「Chrome 配置」是服务器上的一个 Chrome：自己的代理、一份加密保存的登录状态（cookie 等，网站用来记住你登录过的数据）、几个网站账号。所有任务共用。

#### Chrome 配置

「新建 Chrome」（只有主管）：

| 字段 | 说明 |
|---|---|
| 名称 | 给人看的 |
| 给 agent 的说明 | 写清楚出口 IP 在哪、用于哪些网站。任务要求用特定的 Chrome 时，agent 靠这句话指定 |
| 代理 | 「不用代理」或「SOCKS5」（一种代理协议）。SOCKS5 填主机、端口、用户名和密码（可选）。密码只加密存，编辑时留空 = 不改；不再需要密码时勾「去掉已存的密码」 |
| 出口地（可选） | 一句话写这个 Chrome 从哪里出网，例如「英国 · 伦敦」。只是给人看的，系统不会去检测 |
| 时区 | 网页看到的本地时间。从列表里搜城市选（例如 Europe/London），默认 Asia/Shanghai |
| 语言 | 浏览器界面和发给网站的语言，例如 zh-CN、en-US。可以从常用选项里选，也可以直接输入，默认 zh-CN |

注意：
- **同一个账号要一直走同一个出口 IP**，和人登录时一致，不容易被网站风控。
- 代理挂了会报错、通知负责人，**不会退回直连**。
- **时区、语言要和出口地一致**（例如英国出口配 Europe/London、en-GB），不容易被网站风控。改了以后，下一次打开的 Chrome 才按新的来。
- Chrome 详情的「代理、时区和登录态」里能看到出口地、时区、语言；出口地没填就显示「没填」。
- 每个 Chrome 同一时间只给一个运行（session）用，不能改；人「打开 Chrome」开的不算。列表和详情标题旁的「在用」/「空闲」是现在有没有运行在用它。详情的「当前的 session」列出在用的：哪个任务的哪次运行（点了去任务）、现在在哪个页面；「查看」只看画面，不能操作。
- 详情的「操作历史」是 agent 在这个 Chrome 里做过什么：时间、网址、动作（Open、View、Click、Input 等，失败的标红，重复的写次数），同一次运行在同一个网址上连着做的合成一行，留 90 天。
- 删除 Chrome 会连同登录状态和账号一起删，不能撤销。正有 session 在用时删不了。

#### 平台、域名和账号

需要登录的网站，在 Chrome 详情的「登录过的网站」里「加账号」（只有主管）：

| 字段 | 说明 |
|---|---|
| 平台 | 选已有的，或直接输入新的网站名，保存时一起建好。平台所有 Chrome 配置共用 |
| 新平台的域名（可选） | 每行一个，子域名也算（填 `example.com` 就包含 `www.example.com`）。agent 打开这些域名下的网址时，才算占用这个账号的并发名额。不填就不限并发。以后在账号的「⋯ → 改平台域名」里改 |
| 账号 | 登录用的用户名、邮箱或手机号 |
| 密码（可选） | 只加密存，页面、日志和 agent 都看不到原文；编辑时留空 = 不改，勾「去掉已存的密码」才删。存了密码才能「立刻登录」，运行中遇到登录页 agent 也会自己登录 |
| 这个账号同时最多几个 session | 1～5。同一个账号多处同时登录容易被风控，风控严的网站建议 1。满了以后，要用它的运行挂起排队，有人用完就叫醒最早的那个 |
| 登录网址 | 「立刻登录」「人工登录」都先打开这里；系统也用它检查登录还在不在：打开后跳到了登录页（或页面上有密码框）就算掉登录了。登录网址本身就是登录页、打开后没跳走时看不出来，按还登录着算。填一个没登录就会跳去登录页的网址（例如个人中心）检查得最准 |
| 连 IndexedDB 一起存 | 有的网站把登录状态存在 IndexedDB（浏览器里的一种本地数据库）里，只存 cookie 会掉登录。不确定就先不勾 |

账号旁的状态（已登录、登录失效、需要验证码）只是标记。两个按钮：

- **立刻登录**：agent 在后台打开登录网址，用存的账号密码登录，好了就把登录状态存进保险箱。模型只看到 `{{username}}`、`{{password}}` 两个占位符，填进网页时系统才换成真的；密码只会填到这个平台的域名和登录网址所在的网站上。登录表单里的图片验证码（字母、数字），开着「遇到验证码先自己试着过」时它会让视觉模型认出来填上；滑块、短信码这类过不了的，或者密码不对，会把这个 Chrome 留着、弹出远程画面让你接着登录。用的是「模型」页的默认执行模型，每次花一点钱。没存密码时点不了。
- **人工登录**：打开登录网址的远程画面，人自己登录，关掉画面就保存。

主管在账号的「⋯ → 编辑账号」里改账号、密码、登录网址、并发上限。

#### 打开 Chrome

1. Chrome 详情右上角「打开 Chrome」，或账号旁的「人工登录」。服务器上会起一个 Chrome，装上这个配置已有的登录状态，弹出远程画面。
2. 在画面里登录。短信码、验证码也在这里完成。
3. 关掉画面就保存：cookie 和本地存储合并进保险箱（版本号加一），你改过的覆盖原来的；两个人或人和 agent 同时改了同一项，以最后关的为准。再检查各账号（配了登录网址的）是不是真的登录着，结果会弹出来。
4. 登录用的 Chrome 空闲 30 分钟会自动关，同样保存。

员工也能「打开 Chrome」。

#### 运行时登录状态怎么用

每次运行第一次用浏览器时，临时起一个 Chrome，装进这份登录状态；用完先用登录网址确认还登录着，再把**这次变了的** cookie 合并回保险箱，然后关掉。确认没通过就不写回，账号标成需要重新登录。agent 拿不到 cookie，也拿不到密码。

运行中打开网页遇到登录页：这个网站对应的账号存了密码，就先让登录小 agent 用它登录（过程里记一条「用存的密码自动登录了 …」，花费算进这次运行），登好了 agent 接着做（登录表单里的简单验证码它也会先试着填）；没存密码或者登不上，才照下面的验证码流程交给人。

#### 远程画面怎么用

在这几个地方会打开：「打开 Chrome」、运行详情里的「看浏览器」、要人办的事里的「去浏览器里处理」、浏览器页「当前的 session」里的「查看」（只能看）。

- 点一下画面就能直接操作：鼠标、打字、回车、滚动都会发到服务器上的 Chrome。
- **中文**用你本机的输入法直接打。**粘贴**用 Ctrl+V，粘的是你本机剪贴板里的文字。
- 看不到 Chrome 自己的地址栏，用画面上方的地址栏，旁边有后退、前进、刷新；标签页也在上方切换和关闭。agent 在哪个标签页上干活（新开、切过去、打开网址、点、打字），画面就自动跟到哪个标签页；你手动切开去看别的，agent 下一步操作时会被拉回来。
- 网页弹出的提示框、确认框会显示成控制台里的对话框，点「确定」或「取消」。
- 右上角「缩成小窗」：画面缩到页面右上角，不挡页面，可以一边看一边在控制台里干别的，小窗里照样能操作。按住小窗的标题栏能拖到任意位置；点「放大」回到大弹窗，连接不断。打开它的抽屉或页面关掉了，小窗也还在（这时放大后底部的「已处理好了」这类按钮不显示，到原来的地方再点一次「看浏览器」就接回来）。小窗里的关闭和大弹窗的关闭一样（登录用的 Chrome 关掉就保存）。
- 谁都能看画面；能操作的只有任务负责人、被分配处理的人、主管（登录用的 Chrome 是打开它的人和主管）。没权限时显示「只读」。
- 文字多的页面每路画面要几 Mbps 带宽，只在有人看时才传。
- 还不支持：网页里原生的文件选择框、浏览器自己的用户名密码弹框（Basic 认证）。

#### 验证码怎么处理

每次操作网页后，按网址、页面里的框架、关键词判断是不是验证码页或登录页；拿不准时，如果「设置 → 浏览器」里开了「拿不准时让视觉模型看截图」，会再让视觉模型看一眼（每次花一点钱）。

是验证码页时，「设置 → 浏览器」里开着「遇到验证码先自己试着过」（默认开，所有网站都一样），系统先自己试着过：

- **能自己过的**：图片里的字母、数字或简单算式（很多内部系统用的那种），让「设置 → 浏览器 → 视觉模型」认出来、填进验证码框、提交；「我不是机器人」勾选框、「点击验证」这类点一下就行的，直接点。每个页面最多试 3 次，每次在运行的过程里记一条「自动过验证码（第 n 次）」，写着认出的答案和花费（每次大约 0.0005 美元，花费算进这次运行）。过了 agent 接着做。
- **表单里的验证码**（验证码框旁边还有单号、账号这类没填的框）：系统不替它提交，让 agent 先填好别的项，再调「填验证码」工具认出来填上，由 agent 自己点提交。
- **过不了的**：滑块、拼图、按顺序点字、选图、短信或邮箱验证码、扫码，或者试了 3 次还没过，照旧交给人。
- **第三方人机验证**（reCAPTCHA、hCaptcha、Cloudflare Turnstile、GeeTest、Arkose 这类服务嵌在页面里的验证）：不自己试、不花钱，直接交给人，卡片上写着「… 是第三方人机验证，系统不自己试」。

交给人时：截图 → 在「待办 → 等人处理」生成一张「登录」卡（写着自动过验证码试过什么、为什么没过），分给任务负责人 → session 进入「等人处理」→ Chrome 先保留着（默认 30 分钟）。处理方法见 6.4。不想让系统自己过验证码，就把开关关掉，遇到验证码一律直接交给人，agent 也没有「填验证码」工具。

### 5.4 技能

在「技能」页。左边按「岗位」分组。只有主管能新建、编辑、发布、停用。

#### 字段

| 字段 | 说明 |
|---|---|
| 名称 | 给人看的 |
| 岗位 | 只用来分组，选已有的或输入新的 |
| 什么时候用 | **agent 平时只看到这一句**，判断用不用得上。写清楚什么情况下该用、什么情况下不用 |
| 用到的工具（可选） | 写进 SKILL.md 头部，告诉 agent 这个技能要用哪些工具。**任务里还要选上这些工具**，agent 才调得到 |
| 操作手册（Markdown） | SKILL.md 的正文。Markdown 是一种用 `#`、`-`、`1.` 标记标题和列表的纯文本写法。可以切到「预览」看效果 |

#### agent 怎么用它

1. 运行开始时，agent 只看到「技能目录」：每个选中技能的名字和「什么时候用」那一句。
2. 用得上时，它调「读取技能」读出全文，照着做。任务选了技能，系统会自动带上「读取技能」工具，不用另选。
3. 技能只有「已发布」的才能在建任务时选。被任务选用着的技能不能停用。

#### SKILL.md 怎么写才好用

新建时会给一个模板：适用场景、步骤、常见坑。写的时候：

- **一个技能管一类事**。太大的拆开，「什么时候用」才写得清楚。
- **步骤写成动作**，一句一步，写清楚用哪个工具、看什么、拿到什么才算这步完成。
- **写判断标准**。例如「列表为空时先换一个关键词再试一次，还是空就问人」。agent 最容易在没写清楚的分支上乱来。
- **写清楚什么时候停下来问人**：拿不准、要对外发送、要花钱时，用「问人」。
- **写常见坑**：网页上容易点错的地方、接口常见的报错和处理办法。
- **写交付格式**：要产出文件的，写清楚文件名、列名、格式，并让 agent 用「存文件」。要 Excel 就写明「存成 xlsx」（老系统只认 xls 就写 xls），几个工作表各放什么。
- **不要写密钥、账号密码**。密钥放密钥库，登录交给浏览器配置。
- **不要写会变的数据**（价格、名单）。会变的放附件或接口。

每次保存记一个新版本，下一次运行开始用新版，正在跑的不受影响。

#### agent 提的修改怎么审

任务选了「提议修改技能」工具，agent 发现手册不对时会提修改建议（改完的全文加一句说明）。

- 待办「等人处理」里出现一张「技能修改」卡，分给技能的负责人；技能列表上这个技能标「有修改建议」。
- 审核：在待办里点开卡片看改动，或者去技能页看全文。点「通过并合并」（记为新版本）或「拒绝」（可以写原因）。
- 如果建议提出以后你又手动改过这个技能，合并会失败，要拒绝后让 agent 重新提，或手动改。

### 5.5 记忆

在「记忆」页。左边按「适用于」的分类分组。只有主管能新建、编辑、归档、删除。

这里的记忆是公共的，可以给多个任务选用。只跟一个任务有关的经验，写进那个任务自己的「任务记忆」更方便，见 5.7。

#### 写什么

- 写**经验和偏好**：某类对象的偏好、某个系统的注意事项、某种情况下的处理习惯。一条一件事，最多 1000 字，可以用 Markdown。
- 不要写订单、报价这类会变的数据，也不要写密钥。
- 记忆会原样放进 agent 的提示里，标明「人审核过的，必须遵守」。写成清楚的要求，不要写成含糊的感想。

#### 适用于

写成「分类 · 对象」，例如「偏好 · 某部门」，或只写分类。它决定记忆在左边放哪一组，建任务时也靠它找。选已有的，或直接输入新的。

注意：「适用于」只是标签，**系统不会按它自动挑记忆**。任务选了哪几条，每次运行就全部读到哪几条。

#### 怎么用

建任务时在「用哪些 → 记忆」里选。只有「生效」的记忆能选。

- **归档**：不想再用但想留着。选用了它的任务下一次运行就读不到了，归档前会提醒。归档后列表里不再显示。
- **删除**：被任务选用着删不了，先在任务里去掉，或者改成归档。

#### agent 提议的记忆要人审

任务选了「提议记忆」工具，agent 发现以后也该知道的事时会提议一条记忆。

- 状态是「待审核」，不能被任务选用，也不能编辑。
- 待办「等人处理」里出现一张「记忆审核」卡，分给任务负责人。记忆页详情里也有「通过」「拒绝」。
- 记忆详情里有「来源」：agent 根据聊天记录、网页内容还是任务结果提议的，附证据。**标「来自网页，可能不实」的要特别小心**：网页里可能藏着写给 AI 的话，想让它记住假信息。

### 5.6 规则

在「规则」页。只有主管能新建、编辑、删除、翻译、确认。

规则**没有全局的**：建任务时选上哪条，那个任务才守哪条。

#### 用一句话写

| 字段 | 说明 |
|---|---|
| 名称 | 给人看的 |
| 触发条件 | 一两句话：调用哪个工具之前或之后、打开不在白名单的网址、花费超过多少、agent 说做完了…… 写得越具体，翻译越准 |
| 命中后怎么办 | 拦下、交给人审批、截图存证、通知某人、自动记录检查点、交给三方验收 |
| 提到的工具（可选） | 文字里提到的工具，选上能帮系统翻译得更准 |

#### 保存后系统翻译，确认才生效

1. 点「保存并翻译」。规则先存好，再用「规划」模型翻译，一般十几秒，每次花几美分。
2. 弹窗显示「系统理解为：……」。这句话**由程序按翻译结果生成，不是模型写的**，程序就照它执行。
3. 对就点「确认生效」。不对就点「改文字」再翻译。也可以「稍后再确认」，之后在规则详情的「系统理解为」里点「确认生效」或「重新翻译」。

规则有四种状态：

| 状态 | 意思 | 建任务能选吗 | 运行时执行吗 |
|---|---|---|---|
| 未翻译 | 还没翻译（例如翻译时没设规划模型） | 不能 | 不执行 |
| 待确认 | 翻译好了，等主管确认 | 不能 | 不执行 |
| 生效 | 确认过了 | 能 | 执行 |
| 未生效（v1 还不支持） | 翻译不进去 | 不能 | 不执行 |

翻译不进去的，**系统不会退回让 agent 自己判断**。

#### v1 支持哪些触发和动作

| 触发 | 能配的动作 |
|---|---|
| 调用某些工具之前（按工具，或按风险等级：对外发送、涉及金钱）。写「浏览器」表示整组浏览器工具 | 拦下、交给人审批、截图、通知 |
| 调用某些工具之后，或「调用任意工具之后」 | 截图、通知、自动记录检查点 |
| 打开的网址不在某几个域名里 | 拦下、交给人审批、截图、通知 |
| 页面上出现验证码或登录页 | 截图、通知（转人工本来就会做，规则只能再加动作） |
| 这次运行的花费超过多少美元 | 交给人决定要不要继续、通知、拦下（直接结束运行） |
| agent 说做完了 | 交给三方验收、通知 |
| agent 提议记忆或修改技能 | 拦下、通知 |

「交给谁」「通知谁」可以是：任务负责人、主管（审批交给第一位主管，通知发给所有主管）、指定的某个人。一条规则里「拦下」和「交给人审批」只能有一个。

各动作做什么：
- **拦下**：工具不执行，把「被拦下：理由」告诉 agent。
- **交给人审批**：工具先不执行，session 进入「等人处理」，待办里出现「审批」卡。批准才执行；拒绝就把理由告诉 agent，它接着往下做。
- **截图**：这次运行开着 Chrome 时截当前页面存证。
- **通知**：发站内通知，并推到通知渠道。
- **自动记录检查点**：见 5.7 检查点。
- **交给三方验收**：见 6.2。

#### 建议先配的几条

下面是写法示例，可以照抄后按自己的情况改。翻译结果以「系统理解为」为准。

| 名称 | 触发条件 | 命中后怎么办 |
|---|---|---|
| 自动记录检查点 | 调用任意工具之后 | 自动记录检查点 |
| 三方验收 | agent 说做完了 | 交给三方验收 |
| 对外发送前审批 | 调用风险等级为「对外发送」的工具之前 | 先拦下，交给任务负责人批准，批准了才执行 |
| 涉及金钱前主管审批 | 调用风险等级为「涉及金钱」的工具之前 | 交给主管审批 |
| 花费提醒 | 这次运行的花费超过 1 美元 | 挂起，交给任务负责人决定要不要继续 |
| 只访问指定网站 | 打开的网址不在 example.com、example.org 里 | 拦下 |
| 遇到验证码通知主管 | 页面上出现验证码或登录页 | 截图，并通知主管 |

**按风险等级拦，会拦到浏览器**：浏览器的每个操作（打开网页、看页面、点击、输入）在系统里都算「对外发送」。所以「调用对外发送的工具之前 → 审批」这条规则，选在用浏览器的任务上，agent 每动一下浏览器都要人批。这类任务改用按工具名写的规则，例如「调用『某某接口』之前，交给任务负责人批准」，只列真正要管的工具。

**三方验收和检查点自动记录都要靠规则**：任务没选「三方验收」那样的规则，agent 说做完了就直接完成，不验收；没选「自动记录检查点」那样的规则，检查点只有 agent 自己写的记录。

#### 改了文字以后会怎样

- 只改名称或提到的工具、文字没变：翻译结果照旧，不用重新确认。
- 改了触发条件或命中后怎么办：
  - 规则标「按旧版本生效」。在新文字翻译并确认之前，选了它的任务**照旧版本执行**；
  - 新文字翻译不进去：旧版本照常执行；
  - 新文字确认后，之后开始的运行按新版本。
- 已经在跑的运行用的是开始时的那一版。

#### 为什么有的规则「未生效」

常见原因：
- 文字里的工具名对不上系统里的工具。改成工具页上的准确名字，或在「提到的工具」里选上；
- 「交给谁」写成了系统里没有的人；
- 想要的触发或动作 v1 不支持，例如「agent 觉得不对劲时」「每周一」这类要模型自己判断或按时间的条件；
- 触发和动作的组合不支持，例如「调用工具之后 → 交给人审批」（调用后已经执行了，审批不了）。

详情里会写出不支持的原因，按原因改文字再翻译。

#### 删除

没被任务选用的规则直接删，弹出的提示里可以「撤销」。被任务选用着的删不了，会告诉你是哪些任务。

### 5.7 任务

在「任务」页。每个任务一张卡，按创建时间排，新建的在最前。卡片和详情只说明任务：标题、目标、定时、步骤、负责人、开关，不显示运行状态。点卡片从右边打开详情；详情头部的「会话（N）」按钮打开「会话」页，只看这个任务的 session（N 是运行过几次），每次运行的状态和过程在那里看。只有主管能新建；负责人和主管能编辑、开关、运行、删除。

#### 新建任务的字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 任务 | 是 | 一句话要 agent 做什么，最多 200 字 |
| 任务步骤 | 否 | 见下面 |
| 目标 | 是 | 做到什么算完成，最多 1000 字。三方验收按它判断 |
| 用哪些 → 记忆、技能、工具、规则 | 否 | agent 只能用这里选的。规则没有默认的，要手动选，只能选已生效的 |
| 浏览器（选了「浏览器」工具才出现） | 否 | Chrome 配置、网址白名单、允许在网页里执行脚本、允许看画面，见下面 |
| 模型 | 否 | 不选用默认执行模型 |
| 三方验收模型 | 否 | 在「完成」一组。不选用默认验收模型。不能和执行模型同一家 |
| 复核模型 | 是 | 在「完成」一组，先填上「模型」页的默认复核模型，可以换。运行结束后一定用它复核一遍办没办成（三方验收通过的除外），复核也判办成才算办成。以前没选的旧任务，打开编辑时会填上默认的，保存就选上了 |
| 负责人 | 否 | 默认是你。负责人能开关、运行这个任务，要人办的事默认分给他。建好以后只有主管能改负责人 |
| 附件 | 否 | 每次运行都带上，agent 用「读附件」读（有附件时系统自动带上这个工具） |
| 定时运行 | 否 | 勾上填 cron，见下面 |

#### 步骤：可以不写

- **不写**：agent 自己探索。它开始时用「写下步骤」写下打算怎么做，运行详情里会显示「agent 的步骤」。
- **写**：一句一步，最多 50 步。agent 会参考，但不是死板地照做。
- **存为任务步骤**：agent 探索出的步骤觉得好，在运行详情「agent 的步骤」里点「存为任务步骤」，覆盖掉任务现在的步骤。注意：原来步骤上的检查点会一起去掉，之后在编辑任务里重新勾。

#### 等待

步骤上勾「等待」，告诉 agent 这一步可以挂起等。agent 用「挂起等待」工具挂起，可以：
- 等到某个时间；
- 等某个事件（外部系统发来，或主管手动触发，见 6.6）；
- 两个都给，谁先到谁继续。

只等事件、不给时间的，最多等「设置」里的兜底天数（默认 7 天），到期**只提醒负责人，不会自动继续**。

不勾「等待」agent 也能挂起，勾上是明确告诉它这里该等。

#### 检查点

步骤上勾「检查点」，写这一步做到什么算数。一个输入框里可以用「；」写多条。写完会自动认出类型，显示在输入框旁边：

| 类型 | 怎么写会被认成它 | 怎么算完成 | 能自动记录吗 |
|---|---|---|---|
| 访问 | 带数字，有「访问 / 打开 / 浏览 / 搜 / 对比」，例如「访问了 3 个网站」 | 记到 N 个不同的网址 | 能：浏览器打开网页后记下标题和网址 |
| 发送消息 | 带数字，有「发送 / 发…消息」，例如「给 2 个联系人发消息」 | 记到 N 条发出去的消息 | 能：调了风险为「对外发送」的工具（浏览器除外）后记下发给谁和原文 |
| 数量达标 | 带数字，有「至少 / 不少于 / ≥」，例如「整理出至少 5 条」 | agent 填上数量，到 N | agent 每写一条记录累计一次 |
| 产出文件 | 有「保存 / 文件 / 上传 / 已生成」，例如「汇总表已保存」 | 有一个文件 | 能：「存文件」之后记下文件链接 |
| 人工确认 | 有「已审核 / 已确认 / 已批准 / 审批」，例如「负责人已确认」 | agent 问过人、拿到确认后勾上 | 不能 |
| 说明 | 认不出的都算这类 | agent 写一段说明 | 不能 |

- **自动记录**要任务选上一条「调用任意工具之后 → 自动记录检查点」的规则（见 5.6）。自动记的记录标「自动」，agent 改不了。
- **agent 自己勾**：用「勾检查点」标完成并写结果。做不到的可以标「跳过」，**必须写理由**，验收时会看这个理由。
- 没写步骤的任务，agent 也可以边做边加检查点。

#### 浏览器的几项

| 项 | 说明 |
|---|---|
| Chrome 配置 | 不选 = 全部都能用。运行要用浏览器时系统按顺序挑一个空闲的；每个 Chrome 同时只给一个运行用，所以选了几个，最多就有几个运行同时用浏览器 |
| 网址白名单（可以不填） | 每行一个域名，子域名也算。不填就不限制；填了，名单外的网页打不开，agent 会收到原因 |
| 允许在网页里执行脚本 | 打开后 agent 可以在页面里运行 JavaScript，读数据更快，但也能改页面、发请求。不确定就别开 |
| 允许看画面 | 打开后 agent 可以截当前画面给模型看、按坐标点击（在线表格、画布类网页用得上）。每看一次多花一张图的模型费用 |

#### 定时（cron）

勾「定时运行」，填 cron 表达式：五段，用空格隔开，分别是「分 时 日 月 周」，按上海时间。

| cron | 意思 |
|---|---|
| `0 9 * * *` | 每天 09:00 |
| `0 9 * * 1-5` | 每个工作日 09:00 |
| `0 10 * * 1` | 每周一 10:00 |
| `0 */2 * * *` | 每两小时整点 |
| `30 17 1 * *` | 每月 1 日 17:30 |

输入框下面会显示人话翻译。**每次触发是一次新的运行**。停用任务就不会再按定时运行。不勾就只在点「立即运行」时跑。

下面的「上一次还没跑完就跳过」默认勾着：到点时上一次运行还在执行中或验收中，这次就不开（挂起等待的不算没跑完）。想到点照样再开一次，就把勾去掉。

#### 附件

- **任务附件**：新建或编辑任务时加，或在任务详情「附件」里上传、移除（编辑时马上生效，不用点保存）。每次运行都带。
- **这次的附件**：只想这一次带的，用「⋯ → 带附件运行…」，见 6.1。
- 单个文件最多 20 MB。文本文件 agent 直接读内容，图片会交给能看图的模型。
- 表格文件（xlsx、xls、xlsm、xlsb、ods、csv、tsv）agent 先看到概览：每个工作表的名字、范围（例如 A1:H120）、前 20 行；再按工作表和行号一段段读（一次最多 500 行）。只读存着的值，不读公式；日期写成 2026-01-02；合并单元格的值只在左上角那格。国内系统导出的 GBK 编码 csv 也能读。
- agent 用「读附件」工具读。任务或这次运行有附件时，系统会自动带上这个工具，不用另选。

#### 任务记忆

每个任务自己的经验，在任务详情的「任务记忆」卡里。和「记忆」页的公共记忆不同，它只给这一个任务用，不用在建任务时选，每次运行开始全部交给 agent。

- **直接写**：负责人和主管点「加一条」。一条写一件事，一两句话，写成以后能照做的说法（例如「导出按钮要等表格加载完再点」）。每条右边「⋯」里能编辑、删除。一个任务最多 100 条。
- **从运行里提取**：运行结束后（完成或失败），在运行详情的「总结和记忆」卡里点「让三方 AI 总结」，见 6.2。提取出来的只是候选，审核通过的才记进来，并标明「来自运行 R-…」。
- 有运行提取了候选还没审核时，「任务记忆」卡顶上会提示，点「去审核」。
- 改动从下一次运行开始生效，正在跑的不受影响。只对这一次有效的数据、密码和密钥不要写进来。

#### 改、停用、删除

- **编辑**：任务详情底部「⋯ → 编辑」。改动从下一次运行开始生效，正在跑的不受影响。
- **开关**：卡片上或详情底部的「已启动 / 已停用」开关。停用后不会按定时、待办、事件或派活自动运行；手动点「立即运行」（或「带附件运行…」）照样能跑一次，不会把任务重新启用。
- **删除**：「⋯ → 删除」。**已经运行过的任务不能删**，运行记录要留着查，只能停用。

### 5.8 图库

- **在哪**：「图库」。打开就是满屏的图片，最新传的在前，往下滚自动加载。所有人都能看、搜、传；改和删只有上传的人和主管。
- **每张图**：图片 + 标签 + 一段文本。文本必须是 JSON 对象（用 `{ }` 包起来，例如 `{"名称": "保温杯", "价格": 25}`），可以空着；标签可以多个。
- **传图**：右上角「上传」，或者直接把图片拖进页面。一次可以选多张，这一批用同样的标签和文本。一模一样的图已经在图库里时不会重复存，会提示「已经在图库里」。
- **找图**：
  - 「以图搜图」：选一张本地的图，或者按 Ctrl+V 粘贴截图。结果按像不像排，图上标着相似度。
  - 标签框：选几个标签，只看这些标签都有的图。
  - 搜索框：写普通文字，在每张图文本的所有值里找；写 JSON（例如 `{"颜色": "红"}`），找文本里包含这一段的图。
  - 点开一张图，「找相似」找图库里和它像的。
  - 以图搜图和找相似默认只显示相似度不低于 90% 的、最多 50 张（大致是同一张图或改过大小、裁过边的）。旁边两个框能改：「最多 … 张」填 1～200，「相似度 ≥ … %」填 0～100；想找同类的不同图，把相似度调到 80% 左右。
- **比对**：两张图像不像、算不算同一张，给 agent 和外部系统用（见下面）。改大小、重新压缩、裁一点边、调亮这种小改动都能认出是同一张；加了大水印又裁掉一大块的，相似度会掉到同类不同图的水平，这时看排名第一的是不是它。
- **agent 用**：建任务时工具里选「图库」，agent 就能检索、比对、看缩略图、把截图或附件存进图库、改文本和标签（不能删）。
- **外部系统用**：主管在「设置 → API 密钥」点「新建密钥」。密钥**只显示这一次**，弹窗里有 HTTP 接口和 MCP 的用法；用密钥做的事算在建它的人头上，删掉立刻失效。接口说明给开发同事看 `docs/dev/api.md` 第 13 节。

### 5.9 比物

- **是什么**：把两张图交给视觉模型，按「比对标准」逐项打分、写出差异，判断是不是同款（或者你要求的别的「像不像」）。每次比对都存档，谁比的、用的什么要求和模型、花了多少钱都记着。和图库的「比对」不一样：图库的比对只算两张图有多像，便宜、快、不解释；比物是模型看图、按要求打分、说理由。
- **在哪**：「资源 → 比物」。左边是比对记录（新的在前，能按标题、编号搜），右边是一次比对的结果。所有人都能比、都能看；删除记录只有发起的人和主管。
- **新比对**：右上角「新比对」。
  1. 放两张图：第一张是参照，第二张是要判断的。每个位置都可以把图拖进来、按 Ctrl+V 粘贴截图、「上传」本地的图、「从图库选」，或者「填网址」（服务器去下载）。
  2. 选比对标准（默认选中默认的那个）。只想比一次、不想存成标准时选「这次自己写要求」，写清楚比什么、怎么打分，再填合格线。
  3. 模型跟着标准走；要换就点「换模型」，只列能看图的模型。标题可以不写。
  4. 点「开始比对」。一般十几秒，左边先出现「比对中」，比完自动刷新。10 分钟内用同样的两张图、同样的要求、同一个模型再比，直接给上次的结果，不重复花钱。
- **看结果**：
  - 列表上的徽章：「比对中」、「97 分」带勾（到了合格线）、「61 分」（没到）、「证据不足」、「没比成」。
  - 详情：两张图（点了看大图，← → 切换）→ 结论（总分 / 100、把握度、合格线、一句话结论、理由）→ 各项分和看到的差异 → 这次实际用的要求。标准以后改了，旧记录里的要求不变。
  - 「证据不足」：图看不清、两张图根本不是一类东西时，模型不给分，结论里写原因。换清楚的图再比。
  - 「没比成」：红框里写了原因（图下载不了、模型出错等）。点「再比一次」，或者换个模型。
  - 「再比一次」：同样的两张图和要求重新比，生成一条新记录。「⋯」里可以复制结论、删除记录。
  - 来源是 agent 的，点运行编号去看那次运行。
- **比对标准**：在新比对弹窗里点「管理标准」。一个标准 = 名称 + 打分要求 + 合格线（0～100）+ 模型。打分要求里写清楚什么算像、看哪些方面（每一方面会单独打分）、哪些差异不算（例如拍摄角度、背景）。有一个是默认的：没指定标准时就用它；初始自带「同款判断」，合格线 95。新建、修改、删除、设为默认只有主管能做；删掉标准不影响以前的比对记录。
- **agent 用**：建任务时工具里选「比物」，agent 就能比两张图（可以是这次运行的截图、附件、图库里的图或网址）、查某次比对、搜历史。它在参数里写标准名，或者直接写要求。agent 比的也记在这里，标着是哪次运行。
- **外部系统用**：和图库一样用 API 密钥（「设置 → API 密钥」），有 HTTP 接口和 MCP；工具名和原来的 Lens 一样，原来调 Lens 的地方换个地址就能用。导入别的 agent 的包时，包里有这类比物的 MCP，AI 会建议改用内置的「比物」。接口说明给开发同事看 `docs/dev/api.md` 第 15 节。
- **花费**：每次比对的花费写在详情标题下面。默认标准用 Gemini 3.1 Flash Lite，一次约 0.001 美元；换贵的模型（例如 Claude Sonnet）一次一两分钱。图片会发给模型（会出境），不要比含客户资料、个人信息的图。

### 5.10 导入（从别的 agent 搬过来）

- **在哪**：「管理 → 导入」，只有主管能用（导入会建任务和配置）。
- **先打包**：让原 agent 把它的任务、技能、记忆、规矩、接口配置打成一个 zip 包（最大 200 MB、5 万个文件；原 agent 框架自己的源码、日志、依赖打进去也行，AI 会跳过）。包里怎么放都行；想读得更准，在上传弹窗里点「打包说明」，把那段话发给原 agent，让它照着打包。
- **上传**：右上角「上传 zip 包」→ 选文件或拖进来 → 可以补一句说明（例如原来在哪跑、负责人是谁）→ 选读包的模型（默认是「规划」模型）→「开始读包」。
- **读包**：AI 在后台读，小的包一两分钟，几万个文件的大包四五分钟；页面上一行一步显示读到哪了，读完铃铛会通知你。读包只读、只整理，不会建任何东西；包里的脚本不会运行。花费按模型算：小的包几分钱，大的包（几十份说明、上万个文件）用 Opus 一两美元，花费写在这次导入的标题下面。
- **确认**：一共七步，每步都按 AI 的建议勾好了，没问题就一路点「下一步」；信得过 AI，也可以在总览页点「直接去确认」。每一项都写了来自包里哪个文件。
  1. 总览：AI 读懂了什么、要注意的（明文密钥、用不上的脚本、可疑内容）、没用上的文件。
  2. 任务：目标、步骤和检查点、定时、负责人（可以直接换）、模型、浏览器、附件。不对就点「修改」，和「新建任务」是同一个表单。原来两个任务靠本机的待办服务、队列串起来（一个找出要办的事，另一个领一件办一件）的，AI 会直接导成「派活」（见 5.11）：办事的任务卡片上多一行「接受派活：参数 …· 同时最多 N 个 · 来自「…」」，找事的任务多一行「派活给「…」」，导入时给它选上内置工具「派活」。派活关系只连这次包里勾上的任务：找事的那个没勾上，就写「来自：（没有勾上的任务）」。被派活的任务原来有定时的，导入时去掉了（被派来的运行才带着参数，按定时跑出来的不知道该办哪件），「要注意的」里写了原来的定时，要的话在「修改」里加回来。
  3. 技能：新建的导入后直接发布。和已有技能同名的默认「用已有的」；点「看差别」后可以改成「更新成新一版」或「另存为新技能」。
  4. 记忆：按去处分组：每个任务自己的任务记忆、共用的记忆。和已有记忆重复的、像网页里混进来的指令的，默认不勾。「⋯」里可以改文字、挪到别的任务、改成共用。
  5. 规则：新规则读包时已经翻译好，勾上就是确认「系统理解为」，导入后直接生效；改了文字会重新翻译。和已有规则一个意思的直接用已有的。程序判断不了的规则（例如「节假日不干活」）导入不了，写了原因。
  6. 工具：HTTP 接口、MCP 服务器、内置工具。密钥：包里有值的已经取到；缺的可以现在填，也可以导入后在「工具 → 密钥」补。
  7. 确认导入：每类新建几个、用已有的几个、不导入几个，点「导入」。
  改动自动保存，中途可以离开，回来接着确认。
- **导入后**：这次导入的详情里列出「还要你做的」：登录要用的网站、填缺的密钥、连接 MCP 服务器并把工具选进任务、翻译确认规则、试跑任务。每件都有直达按钮，办完自动打勾。被派活的任务没有「立即运行」，换成「派一张试试」：打开派活页的「派一张」，任务已经选好，填一个真实的参数派出去看结果对不对；这个任务名下有过一张单就算办完。导入的定时任务和手动新建的一样，导入后就按定时跑。
- **撤销**：「⋯ → 撤销这次导入」：删掉这次新建的任务、技能、记忆、规则、工具和密钥；用的已有配置不动；已经跑过的任务只停用，运行记录留着。
- **还没导入的**：「⋯ → 重新读包」（可以换模型、补一句说明），或者「放弃这次导入」。
- **注意**：包里的文字会发给读包的模型（会出境）；明文密钥在发送前就换成了 `{{名字}}`，模型看不到原值。客户资料、个人信息先从包里删掉再上传。

### 5.11 派活（一个任务把事派给另一个任务）

**什么时候用**：一件活要分两段时。一个任务负责找出要办的事（例如每 5 分钟巡检一次后台，找出还没处理的单子），另一个任务负责一件一件地办（每张单子开一次运行）。前一个叫派活方，后一个叫被派的任务。比起一个运行里串着办几十件事，派活每件事各自一个运行：互不影响、能并行、哪件没办成一眼就看到，同一件事也不会办两次。

#### 让一个任务能被派活

在被派的任务上「编辑」（新建也行），在「被派活」一组打开「可以被派活」：

- **每件事带的参数**：一行一个，写参数名（例如「单号」）、说明（给派活的 agent 看，填什么）、「必填」「去重」。至少写一个。
  - **去重**：标了的参数决定「是不是同一件事」。同一个任务下，去重参数的值一样就是同一件事，**永远只办一次**：已经办完、没办成或不办了的，再派进来只会返回现状，不会重开（要重开只能人点「重办」）。一个都不标时，派活的 agent 要自己给每件事一个编号。
  - 缺必填参数的单当场被拒。
- **要交回的结果**：一行一个，写结果名（例如「价格」「链接」）、说明（给办事的 agent 看，交什么）、「必填」。可以一个都不写（不要求交）。agent 用「报结果」把这些交回单上；**必填的没交，这张单记「没办成 · 缺要交回的结果」**，不自动重试。没写在这里的名字，agent 报了也照收。
- **同时最多几个在跑**（名额，1～10）：执行中、验收中、等浏览器的运行占名额；agent 自己挂起等待（例如等对方回复一天）、等人处理的**不占**，空出来的位子给下一张单。被叫醒继续的运行不卡名额，所以偶尔会比上限多一个。最好不超过要用的账号能同时登录几个。
- **谁能派活给它**：选派活方任务。不选就只能人在派活页派。别人负责的任务也能选，前提是被派任务的负责人（或主管）在这里点了名。
- **没办成自动重试**：默认「不重试」，最多 5 次；选了次数才出现「间隔」（1、5、10、30、60 分钟，2、6、24 小时，默认 10 分钟）。见下面「没办成自动重试」。

能被派活的任务一般不用定时：有单就开始，没单不跑；新建后也不会马上跑一次。卡片上写「被派活 · 同时最多 N 个」；排队几张、在办几张看任务详情的「派活」区块。关掉「可以被派活」时，已经排队的单留着不动，重新打开后接着办。任务停用时，派进来的单照样收下、先排着，重新启用后自动开始办。

#### 让 agent 派活

在派活方任务的「用哪些 → 工具」里选内置工具「派活」。选上后下面会写能派给谁、要什么参数；还没有任务允许它派活时，会提示去对方任务的「谁能派活给它」里加上它。agent 会在系统提示里看到能派给哪些任务和各自的参数，按要求一件一张地派，返回里写清每张是新建排在第几位、已经有了（现在什么状态）还是被拒（为什么）。

派活方的任务详情里多一块「派出去的活」：派给谁、今天派了几张、一共几张，「去派活页」只看它派的。派过活的运行详情里有「派出去的活」，列出这次新建的单。

#### 等结果、报结果

- **派活方等结果**：多数时候派完就走（例如巡检派完就结束）。要等某一张办完再往下做时，agent 用「挂起等待」等事件 `work.done:<单号>`（例如 `work.done:W-57`），一次等一张。单最终结束（办完、没办成、不办了）时平台叫醒它，叫醒的消息里带着这张单的结果；中间排队等自动重试的不叫醒。要等的单在挂起之前就已经结束了，不会挂起，直接拿到结果。选了「派活」的任务自动带上内置工具「查派过的活」：醒来后用它看自己派过的单还有哪些没结束（只能查这个任务派出去的），再等下一张。
- **被派的运行报结果**：被派来的运行自动带上内置工具「报结果」（任务不用选）：agent 把要交回去的几个「名字 → 值」（数字、是 / 否、编号，最多 20 个）写回单上，可以报好几次，同名的以后一次为准。还在办的时候派活页就显示「已报：…」，办完显示成一张「字段 / 值」的表；派活方被叫醒、用「查派过的活」时也能看到。
- **单的结果跟着运行的结果**（见 6.2「状态和结果」）：运行办成，单记「办完 · 办成」；没办成（agent 用「报结果」收尾报了没办成或者只拿到一部分、检查点没达成或有跳过、缺必交的结果、复核判没办成或没能确认办成），单记「没办成 · 要的东西没拿到」或「没办成 · 缺要交回的结果」，原因写在单上，**不会自动重试**，照常通知负责人。派活方被叫醒、用「查派过的活」时都能看到结果和原因；拿到没办成的单，要自己判断要不要重派或者报给人。2026-10-20 以前「没核实」的旧单还是「办完」，结果改成了没办成（原因前面写「原来记「没核实」」）。

#### 没办成自动重试

在被派任务的「被派活」一组里设「没办成自动重试 N 次，间隔 M」。

- **只对运行出错重试**：模型调用失败、程序出错、验收判失败、运行记录丢了。人取消的运行、花费 / 步数到上限后人选了不继续、人把验收判失败、规则让运行失败、没办成的（agent 报的、检查点、复核判的），都**不重试**。
- **怎么重试**：出错的单不记「没办成」，而是回到排队，到点（出错时间 + 间隔）以后再领，轮到了开一次新的运行。派活页上这张单写「排队 · 16:38 重试」，最上面一条提示写这是第几次运行出错、为什么、什么时候重试；处理记录里每次失败后面跟一行「10 分钟后自动重试（第 1 / 2 次）」。
- **通知**：还会重试的那几次失败**不通知**负责人；重试都用完还没办成，单才记成「没办成 · 运行出错，自动重试了 N 次都没办成」，这时通知一次。等结果的派活方也是这时才被叫醒。
- 人点「重办」后，自动重试的次数重新算。
- **会对外发消息的任务慎用**：重试会从头再办一遍，可能把消息再发一次。

#### 人手动派一张

派活页右上角「派一张」，或者被派任务详情底部的「派一张」（能被派活的任务没有「立即运行」：开出来的运行没有参数，agent 不知道办哪件）。网址 `#/work?task=<任务编号>&new=1` 直接打开「派一张」并选好任务（导入后的「派一张试试」就是它）。选任务（只列能被派活、你负责的；主管能选全部）→ 按这个任务的参数填 → 标题可以不写（默认用「参数名 值」）→ 补充说明可以不写 →「派出去」。填好去重参数时会当场查：同一件事已经有单了，就显示那张单的状态和「去看 W-…」，不能再派。

#### 派活页怎么看

- **在哪**：侧边栏「工作 → 派活」。所有人都能看全部派活单；改参数、重办、不办了只有被派任务的负责人和主管能做。
- **左边**：搜索（单号、标题、参数值）、按状态（排队 / 在办 / 办完 / 没办成，每项带数字；默认看「在办」；「不办了」的单在「没办成」里）、按结果（办成 / 没办成；选了结果就不再按状态分）、按被派的任务筛。选了任务时上面多一行「同时最多 N 个在跑 · 现在占 M 个 · 排队 K 张」。列表分「今天派的」和「更早」，新的在前，**默认只列最近 7 天**，再往前点「再看更早的」；搜索不限天数。
- **列表上的状态**：排队、排队 · 16:38 重试（运行出错、等自动重试）、执行中、挂起等待、等人处理、验收中、办完、没办成、不办了。在办的直接写那次运行此刻的状态。结束了的单下面再有一个结果徽章：办成、没办成（没办成的单状态已经写了就不重复）。
- **右边**：标题、状态和结果（排队的写第几位；结果徽章鼠标放上去看原因）、重办过的写「第 N 次」；派给哪个任务、谁派的（哪个任务的哪次运行，或谁在派活页派的）、派于 / 开始 / 办完的时间。「去看运行」打开这次运行的详情。最上面一条提示写现在卡在哪：排第几位和谁在占名额、等自动重试（第几次出错、什么时候重试）、挂起在等什么、等人处理的「去待办处理」、谁点了不办了。下面是「参数」「结果」（办完的是 agent 最后那段总结、「报结果」写的字段表、验收结论和产物；在办时报过的写「已报：…」；办完、结果却是没办成的旧单（原来「没核实」的）上面有一条红色提示，确认办成了可以到运行详情里「改结果」；没办成的红色提示标题写清是哪种：「运行出错」「运行出错，自动重试了 N 次都没办成」「要的东西没拿到」「缺要交回的结果」「运行被人停了」（旧单还可能是「只办成了一部分」），下面是原因）「处理记录」（派进来、每次运行（写状态和结果，例如「已结束 · 没办成」）、自动重试、重办、改参数、不办了）。
- **被派来的运行**：运行详情的说明行写「派活触发 · W-… · 来自「…」R-…」，检查点上面有「派来的活」（单号、状态、参数）。会话页有「来源」一列，可以按「派活」筛，也能搜派活单号。
- 被派的运行**办完时不发站内通知**（一天可能几十上百次），没办成照常通知负责人、照常推送。

#### 重办、不办了、改参数

都在派活单右上角的「⋯」里：

- **改参数**：只有排队的单能改；去重的参数不能改（改了就是另一件事，要办另一件就「不办了」再派一张）。轮到它时按新的参数办。
- **重办**：办完、没办成、不办了的单能重办，重新排队，轮到了再开一次运行，以前的运行都留着。没办成的单（没配自动重试，或者重试用完了）不会自己重来，处理好原因（例如登录失效）再点；重办后自动重试的次数重新算。办完的重办要先确认：会把已经对外做过的事再做一遍。
- **不办了**：排队、在办的单能点，要确认，可以写原因。在办的会**取消正在跑的运行**；已经对外做过的事（发出去的消息、建好的数据）不会撤回。以后同一件事再派进来也只返回「不办了」。

#### 上限

主管在「设置 → 派活」里改：最多几层（被派来的运行再派活算一层，默认 3）、一次运行最多派几张（默认 100）、一个任务每天最多被派几张（按上海时间，默认 500，当天第一次超时通知被派任务的负责人）、一个任务最多排队几张（默认 1000）。超过的单被拒，派活的 agent 会收到原因。

### 5.12 助手（右下角，用说的来改配置）

每一页右下角有个机器人按钮。点开后用中文说要新建、修改或删除什么，不用自己去一页页填表。例如：

- 「新建一个任务：每天早上 9 点检查昨天的新订单，有异常就通知我」
- 「把这个任务的定时改成每周一 8 点」（在任务页里说「这个任务」，就是你刚才看的那个）
- 「加两条全局记忆：……」「新建一个技能，内容照这段写：……」「建一条规则：发邮件前必须先让我确认」

**能做的**：新建、修改、删除任务、任务记忆、待办、记忆、技能、规则，新建和修改 HTTP / MCP 工具配置。它会先查清楚现在是什么样，再动手。

**先给你看，你点了才改**：要改的东西列成一张「改动确认卡」。修改的内容像 Git 对比一样只标出改了的地方：删掉的红底、前面「-」，加上的绿底、前面「+」，改了的句子里只高亮改了的词；没改的长段落收起来，点「展开」或「看全文」看全部；任务步骤一步一步对，写明第几步改了、加了、删了；电脑上还能点「左右对照」，左边修改前、右边修改后。点「应用」才真的改，点「不要」可以顺便说为什么、要怎么改。有删除的，按钮是红色的，写着「会删除 N 项」。应用后每项显示做成了没有，「去看看」直接跳到那一项。卡没处理又说了新的话，这张卡就作废了。

**发图、看图**：
- 说话时可以带图：点输入框的图片按钮选图，也可以直接粘贴或把图拖进面板，一次最多 6 张（png、jpg、gif、webp）。只发图不说话也行。例如截一张页面的图问「这里报的错是什么意思」，或者发几张样图让它照着写任务的说明。
- 它也能看系统里已有的图：运行过程中的截图和产物（说「看看 R-… 最后那张截图」）、图库里的图（在图库页选中一张说「这张图」，或者说图库编号 img-…）。看过的图在它查东西的那一行下面显示缩略图，点开看大图。
- 想把发的图放进任务的附件（任务每次运行都能读到），直接说「把这几张图加到这个任务的附件里」，和别的改动一样先出确认卡，点「应用」才挂上。
- 要用能看图的模型（「模型」页模型表格里能看图的）。这段对话用的模型看不了图时，发图会提示你到「本对话的设置」里换一个，图和话都还留在输入框里；以前发过的图，换成看不了图的模型后它只知道「这里有张图」，看不到内容。
- 图里的文字它只当成要看的内容，不会照着图里写的去做。

**发文件**：
- 很长的文字（需求说明、网页、导出的表格、日志）不用贴进输入框，放进文件发给它：点输入框左下的回形针「加附件」，选图片或文件都行，也可以粘贴、拖进面板。能发的文件：文本（md、txt、html、csv、json、xml、yaml、log 和常见代码文件，最大 5 MB）、PDF 和 Word（.docx，最大 20 MB），一次最多 6 个文件（另外还能带 6 张图）。只发文件不说话也行，对话标题就是文件名。
- PDF、Word 它读的是抽出来的文字，看不到里面的图和排版。扫描件 PDF 抽不出文字，会提示你截图发图片；旧版 Word（.doc）先另存为 .docx 再发；加密或损坏的打不开。网页文件（html）去掉了脚本、样式后给它看。
- 文件很长时，它先看到开头一部分（一条消息里的文件合起来大约 6 万字），后面的要用到时再一段段去读，所以问得具体一点它读得少、花得少。每说一句它都会重新带上对话里发过的文件，文件多、对话长时花费会涨，到了上限会停下。
- 它也能读运行里的文本文件（例如「看看 R-… 的日志里报了什么错」）。发的文件同样能说「加到这个任务的附件里」。
- 发的文件显示在你那句话的上面，文本文件点开看内容，PDF、Word 点了下载。文件里写的话它只当成要看的内容，不会照着去做。

**不能做的**：跑任务、取消运行、处理要人办的事、看或改密钥（要密钥的工具建好后会提醒你到「工具」页填）、用户和系统设置。

**权限和你一样**：员工通过助手也只能做自己本来能做的（改自己负责的任务、给自己的任务建待办）。新建任务、记忆、技能、规则只有主管能做。审计里能看出哪些改动是通过助手做的。

**模型和花费**：默认用「模型」页「默认设置」里的「助手」模型，那里没选就用「规划」的默认模型。一次请求最多 20 步、$0.20，到了会停下说明，主管在「设置 → 助手」里改。每段对话还能单独设：标题栏「以前的对话」旁边的「本对话的设置」里可以换这段对话用的模型、改一次最多几步、最多花多少美元（1～100 步、0.01～10 美元），空着的跟上面的默认走；新对话在说第一句之前也能先设好。对话按人保存，每人保留最近 50 段，「以前的对话」里能翻到、能删。标题栏的「放大」按钮把面板放大到右边一半宽、上下撑满（长的确认卡、技能正文好看），再点「还原」回到右下角；放大还是还原刷新后保持。

## 6. 运行起来以后

### 6.1 启动、取消、继续

在任务详情底部（负责人和主管能用）：

| 操作 | 在哪 | 说明 |
|---|---|---|
| 立即运行 | 底部主按钮 | 马上开始一次新的运行，自动打开这次运行的过程。任务停用时点不了 |
| 带附件运行 | 「⋯ → 带附件运行…」 | 上传这次要带的文件，可以写一句「附加说明」，再「立即运行」。任务本身的附件照样带 |
| 创建并启动 | 新建任务弹窗 | 建好马上跑一次 |
| 立即继续 | 底部主按钮（最近一次运行在「等待中」时） | 不等了，让挂起的 session 马上接着做。运行详情、待办卡片里也有 |
| 去待办处理 | 底部主按钮（最近一次运行在「等人处理」时） | 跳到待办里那件事。「等人处理」不能用「立即继续」，要先处理那件事 |
| 取消运行 | 「⋯ → 取消运行 R-…」，或运行详情的「取消运行」 | 要二次确认，可以写原因。取消后标为出错、结果记没办成，不能恢复；在等的事、没处理的待办一起作废。**已经做完的操作（发出去的消息、存下的文件）不会撤回** |

最近一次运行还没结束（执行中、等待中、等人处理、验收中）时，不能再点「立即运行」。能被派活的任务底部是「派一张」，没有「立即运行」（见 5.11）。

### 6.2 看一次运行的过程

在任务详情头部点「会话」（打开「会话」页，只看这个任务的 session），或直接在「会话」页点一行，从右边打开运行详情。所有内容实时刷新。

- **头部**：状态、结果（结束后才有，鼠标放上去看原因）、模型、输入和输出 token、花费、开始和结束时间。右上角有「看浏览器」（这次运行开着 Chrome 时）、「立即继续」、「取消运行」。
- **出错原因**：出错的运行顶部有红色提示，写着原因（模型出错、被取消、到了上限后不继续、验收判定失败等）。
- **结果**（运行结束后才有，复核还在跑时写「复核中」）：写结果、原因和是谁定的（agent 自己报的、规则、AI 复核、三方验收、人改的）；跑过复核的，点「复核结论」展开看复核报告（结论、理由、模型、带没带截图、花费，复核出错、超时时写原因；2026-10-20 以前的旧报告结论可能是「部分办成」「说不准」）。见下面「状态和结果」。

**状态和结果**：状态只管流程，正常跑完是「已结束」，出错、被取消是「出错」；事情办没办成看结果，只有两种（2026-10-20 起）：

| 结果 | 什么时候 |
|---|---|
| 办成 | 三方验收通过；或者 agent 报办成、检查点和要交回的结果都没问题、AI 复核也判办成 |
| 没办成 | 其余都是：agent 报没办成（包括只拿到一部分）；检查点有没达成的或者有跳过的；被派的任务缺必交的结果；复核判没办成、证据不足、复核出错（重试一次还出错）；运行出错或被取消 |
| 复核中 | 不是结果：运行已经结束，AI 正在复核，一会儿就出结果 |

- **只看任务目标要的东西拿没拿到**，不看 agent 有多努力：要找一个商品，没找到就是没办成，确认「没有」也一样；只拿到一部分也是没办成，原因里写清拿到了什么、缺什么（例如「只拿到价格，缺链接」）。
- agent 结束时要用自带的「报结果」报办成还是没办成，并对照目标写依据。只回一段文字、不报的，系统提醒一次；还是不报，结果交给规则和复核去定。
- **AI 复核**（一定做，三方验收通过的除外；每个任务都要选复核模型）：运行结束后用复核模型看目标、检查点、agent 的报告、最后几步工具的输入输出、产物清单和最后一张截图，判一次。复核也判办成才算办成；证据不足、拿不准都判没办成。复核出错重试一次，还出错就记没办成（「复核出错，没能确认办成」），运行状态不受影响。花费记在这次运行上，每次不到 0.001 美元。任务没选复核模型、也没有默认复核模型的，不能开始运行。
- **改结果**：已经结束的运行（已结束、出错、取消的都行），负责人和主管在「结果」区块点「改结果」，或者在会话列表那一行最右边的「⋯」里点「改结果」，选办成或没办成、写一句理由（必填），结果记成「人改的」，理由显示在原因里。只改结果，不重开运行；被派来的运行，派活单的结果跟着改，单的状态不变。
- 没办成会通知负责人；要再试就点「立即运行」。
- **检查点**：每条一张小卡，有进度、记录（标「自动」的是规则记的）、跳过理由。agent 标了「正在做」的会显示出来。
- **验收**（有三方验收时）：总结论、每条检查点的「通过 / 不通过 / 存疑」和理由、验收问答（验收模型问、执行 agent 答）、负责人怎么处理的。
- **总结和记忆**（运行结束后才有）：见下面。
- **agent 的步骤**：agent 写下的最后一版步骤，可以「存为任务步骤」。
- **空间文件**：每次运行有自己的文件空间，agent 存的文件、截图、浏览器里下载的文件、工具输出全文、这次带的附件都在这里，点了下载。每个文件有路径：agent 写的是它自己起的路径（例如 `state/progress.json`），其他来源放在固定目录下（`attachments/`、`downloads/`、`screenshots/`、`tool-outputs/`）。agent 写的文件同一路径再存会覆盖，文件还是同一个，旧内容不留；覆盖过的文件标「覆盖过」，时间是最后一次写入的时间。点文件能看：图片看大图，文本和代码（py、js、ts、sh、sql 等）看内容，代码按语言高亮，表格（xlsx、xls、csv 等）看每个工作表的前 200 行（几个工作表用标签切换）；其他文件只能下载。文件多时点详情右上角的「空间文件」按钮：弹窗里按来源（浏览器下载、agent 写的、截图、附件、工具输出全文）分标签、按路径搜，表格列出路径、来源、大小、时间，点路径预览。
- **过程**：每一条记录，带时间。工具调用点开看输入和输出（「运行代码」会拆开显示代码、退出码和 stdout / stderr，见 5.2）；规则命中、写下步骤、上下文压缩、验收各有小标签；挂起和继续用分隔线标出来。

**三方验收的流程**（任务选了「交给三方验收」规则时）：
1. agent 回复一段总结、不再调工具，就是说做完了。session 进入「验收中」。
2. 验收模型拿到目标、步骤、每条检查点和记录、跳过理由、最终答复、产物摘录、最近的过程记录、截图（模型能看图时），逐条给结论。
3. 全部通过 → 运行结束，结果记办成（不再复核）。
4. 有不通过或存疑 → 把问题交给执行 agent，它可以说明或补做，再验收。最多「设置 → agent」里的轮数（默认 2：反问一次，还不行就交给人）。
5. 最后一轮还说不清 → 待办里出现「验收争议」，交给任务负责人，见 6.4。

验收的花费也算进这次运行。

**总结和记忆**（运行结束或出错以后，负责人和主管能用）：
1. 点「让三方 AI 总结」。用任务选的三方验收模型（没选就用默认验收模型），它和这次运行的执行模型不能是同一家。一般要十几秒到一分钟。
2. 三方 AI 读这次运行的全部过程，写一段总结（做了什么、结果、遇到的问题），再提取以后运行这个任务用得上的经验，每条附上依据。只对这一次有效的数据、已经记过的、泛泛的建议不会提。没有值得记的就不提。
3. 有候选时自动弹出审核框：默认全勾上，可以先改字；勾上的记进任务记忆，没勾的标为「没采用」。也可以点「以后再审」，之后在这张卡上点「审核 N 条」。
4. 卡上留着总结和每条候选的状态（待审核 / 已记入 / 没采用）。「重新总结」会换成新的总结和候选，没审核的旧候选作废，已经记进去的不受影响。

总结的花费也算进这次运行。**网页里可能藏着写给 AI 的话**，看着像指令、来路不明的候选别勾。

**会话页**：全部 session 的列表，「状态」后面是「结果」一列（办成 / 没办成，复核还在跑的写「复核中」，还没结束的写「—」，鼠标放上去看原因），每一行最右边「⋯」里能「改结果」（已经结束的运行，负责人和主管才有）。可以按状态、结果、来源筛选，「任务」下拉只看某一个任务的 session（下拉里能按任务名或编号搜；地址带 `?task=T-…` 打开就是筛好的），也可以按编号或任务名搜索，右上角有「进行中 · 挂起 · 今天花了」。

### 6.3 待办看板

「待办」页，五列横排，放不下可以左右拖动或用方向键平移：

| 列 | 是什么 |
|---|---|
| 执行中 | session 正在跑 |
| 等人处理 | 要你拍板或动手的事。这里放的是「要人办的事」的卡，被它卡住的运行不单独出卡 |
| 等待中 | session 已挂起，在等时间或事件。卡上写着在等什么、什么时候继续 |
| 验收中 | 三方 AI 在核对检查点 |
| 已结束 | 最近结束的运行（每个任务只放最近一次），卡上写结束时间和结果 |

人加的待办以「人加的」卡片出现。点任何一张卡从右边打开详情。员工能看全部卡片，只能操作分给自己的。

同一个任务被派来的活（见 5.11）在「等待中」有 2 个及以上时，收成一张卡：标题是任务名，写「派来的活 · 23 个在等」和「最早 … 起等 · 最近一个 … 到点」。点开右边列出这些运行，每行是运行编号、派活单号和标题、在等什么、什么时候继续，点一行去 会话页看那次运行；底部「去派活页看全部」。列头的数字按运行数算，收起的卡算里面的个数。执行中、验收中、等人处理三列不收。

### 6.4 要人办的事

都在「待办 → 等人处理」列。通知里也会提醒。分给谁就由谁处理，主管能处理所有的。处理完，被卡住的 session **继续同一个**，不新开。

| 类型 | 什么时候出现 | 怎么处理 |
|---|---|---|
| 审批（工具调用） | 规则要求某个工具调用前审批 | 看「要调用的工具」：工具名、参数（像密钥的字段已经换成 `••••`）、哪条规则拦的。点「批准」：照这些参数执行；点「拒绝」：可以写原因，不执行，把理由告诉 agent。下面的「备注」agent 继续时会看到 |
| 审批（问人） | agent 用「问人」请示或提问 | 看「agent 的问题」，按按钮回答（按钮文字由 agent 给，默认「批准 / 不批准」），可以写备注。不管选哪个，agent 都会收到你的回答和备注，自己决定下一步 |
| 审批（花费或步数到了上限） | 一次运行花的钱或调模型的次数到了「设置」里的上限，或者规则「花费超过多少 → 交给人决定」命中 | 「继续」：再给一份额度接着跑（花费的要再确认一次）；「不继续」：运行结束，标为出错、结果记没办成 |
| 登录 | 浏览器遇到验证码或登录页 | 见下面 |
| 验收争议 | 三方验收到最后一轮还说不清 | 看验收报告。三选一：「算通过」（运行结束，结果记办成）、「算失败」（要确认，运行标出错、结果记没办成）、「补充说明后继续」（必须写说明，带着说明回到同一个 session 接着做，agent 再说做完了会重新验收） |
| 记忆审核 | agent 提议了一条记忆 | 点「批准」或「拒绝」；或「去记忆页看」全文和证据再审 |
| 技能修改 | agent 提了技能修改建议 | 看「操作手册的改动」，点「采纳」或「拒绝」；或去技能页审 |

涉及金钱的事卡片上标「涉及金钱」，批准前要再确认一次。

**处理「登录」卡（验证码、登录页）**：
1. 点开卡片，能看到遇到时的截图。
2. Chrome 还保留着（默认 30 分钟内）：点「去浏览器里处理」，在远程画面里过验证码或登录，然后点「已处理好了」。agent 在**同一个 Chrome**里接着做。
3. 过了保留时间，Chrome 已经关了：点「新开 Chrome 处理」，在画面里处理好，关掉画面（关就保存），再回到卡片点「已处理好了」。agent 继续时会新起一个 Chrome。
4. 处理不了：点次按钮，agent 会收到。

保留时间在「设置 → 浏览器 → 遇到验证码时 Chrome 保留多久」里改。

### 6.5 人加的待办

「待办」页右上角「加一条待办」。员工只能给自己负责的任务加。

| 字段 | 说明 |
|---|---|
| 哪个任务 | 选一个任务 |
| 要 agent 做什么 | 一两句话，到点时交给 agent |
| 什么时候 | 四选一，见下表 |

| 方式 | 意思 |
|---|---|
| 定时一次 | 到这个时间做一次（上海时间） |
| 周期（cron） | 按 cron 反复做，下面有常用写法可以点，会显示接下来 3 次的时间。待办一直有效 |
| 等事件 | 事件发生就做。选「最多等」几天，到期还没等到就提醒加待办的人和负责人，待办还在 |
| 先到先继续 | 事件先发生就马上做，最晚到点也会做。适合「等回复，但到某个时间必须跟进」 |

**到点后**：这个任务有挂起中的 session，就用这句话继续它；没有，就开始一次新的运行，这句话作为附加说明。一次性的待办执行后就结束。

待办详情里：「立即执行」（加的人、任务负责人、主管能点）、「⋯ → 编辑 / 删除」（加的人和主管能用）。主管还能对「等事件」的待办点「手动触发事件」。

### 6.6 外部事件

让别的系统叫醒在等某个事件的 session 或待办。

- **在控制台里**：主管在等事件的运行卡或待办卡上点「手动触发事件」。
- **从外部系统发**：
  1. 主管在「设置 → 外部事件令牌」点「生成新令牌」。令牌**只显示这一次**，马上复制交给外部系统。重新生成后旧的立刻失效；「停用」后外部事件一律拒绝。
  2. 外部系统发 `POST http://<控制台地址>/api/events`，请求头 `Authorization: Bearer <令牌>`，内容 `{"event": "事件名", "data": {...}}`。
- 事件名要和 agent 挂起时等的、或待办里填的**完全一样**（区分大小写）。`data` 不参与匹配，只作为文字交给 agent。

### 6.7 通知

- **站内**：右上角铃铛。有事等你处理、运行完成、运行失败、等了很久还没等到、待办没能触发、agent 用「通知员工」发的，都会出现在这里。点一条跳到对应的页面并标成已读；「全部标为已读」。
- **推到外部**：主管在「设置 → 通知渠道」加飞书群机器人、企业微信群机器人或通用 webhook（别的系统接收消息的一个网址）。除了「运行完成」，站内通知都会同时推到所有启用的渠道（有事等人处理、运行失败、等太久、待办没能触发、规则发的通知、agent 用「通知员工」发的）。地址加密存，编辑时留空 = 不改；可以停用、删除。

### 6.8 花费和上限

主管在「设置」页改，对所有任务生效：

| 设置 | 默认 | 说明 |
|---|---|---|
| 运行上限 → 单个 session 花费上限 | 2 美元 | 超过就生成一件「花费到了上限，要不要继续」，session 挂起等人决定 |
| 运行上限 → 单个 session 最多步数 | 0（不限） | 一步 = 调一次模型。填大于 0 的数后，超过同样等人决定 |
| 运行上限 → 只等事件时的兜底天数 | 7 天 | 到期只提醒负责人，不自动继续 |
| agent → 三方验收最多几轮 | 2 | 填 1 = 不反问，直接交给人 |
| agent → 上下文超过多少就压缩 | 0 | 0 = 按模型上下文的 60% 算。超过就把较早的大块工具输出换成摘要，全文另存成文件 |
| 浏览器 → 每个 worker 同时最多开几个 Chrome | 4 | 每个 Chrome 大约 1 核 CPU、几百 MB 内存。满了要用浏览器的运行排队。worker 是后台真正跑 agent 的进程 |
| 浏览器 → 遇到验证码时 Chrome 保留多久 | 30 分钟 | 见 6.4 |
| 浏览器 → 视觉模型 | Qwen3.8 Flash | 过验证码、拿不准时看截图都用它。只能选能看图的模型（和比物同一个列表） |
| 浏览器 → 遇到验证码先自己试着过 | 开 | 图片字符、点一下的验证码先自己过，每个页面最多试 3 次，过不了再交给人；reCAPTCHA 这类第三方人机验证不试。见 5.3 |
| 浏览器 → 拿不准时让视觉模型看截图 | 关 | 见 5.3 |

改了立即对所有运行生效。想给某个任务单独设一个更低的花费门槛，用规则「花费超过多少 → 交给人决定」。

花费在运行详情的头部、会话页的列表和右上角「今天花了」里看。三方验收、运行结束后的「总结和记忆」的花费都算在那次运行上。

## 7. 常见问题

**任务一直「等待浏览器」**

有两种排队，看过程里那条「等待浏览器」的说明：
- **任务允许的 Chrome 都被别的运行占着**（或者这次运行分到的那个 Chrome 被占着）：浏览器页这些 Chrome 写着「在用」。每个 Chrome 同一时间只给一个运行用，有一个空出来就按挂起的先后叫醒。想同时多跑几个，就在任务里多允许几个 Chrome。
- **这台 worker 的 Chrome 满了**：同时开着的 Chrome 到了「设置 → 浏览器」里的上限。人开的 Chrome 也占名额，用完关掉画面。可以调高上限（服务器要扛得住）。排 10 分钟还没排上，这次浏览器调用会失败，agent 会收到原因。
- **账号的并发满了**：「浏览器」页对应账号写着「同时最多 N 个 · 现在 N 个在用 · N 个在排队」，旁边是在用的 session。session 会挂起排队，前面的用完就叫醒。卡住不动的话，看在用的那几个 session 是不是停在「等人处理」，处理掉或取消它；也可以调高这个账号的并发上限（风控严的网站不建议）。

**规则「未生效」或建任务时选不了**

- 「未翻译」：多半是翻译时没设规划模型或模型出错。去「模型 → 默认设置」看规划模型，再到规则详情点「翻译」。
- 「待确认」：在规则详情点「确认生效」。
- 「未生效（v1 还不支持）」：看详情里写的原因，按 5.6「为什么有的规则未生效」改文字，再「保存并翻译」。

**验收总是存疑**

- 目标写具体：写可以核对的结果，不要写「做好」「尽量」。
- 检查点写具体、可数：「访问了 3 个网站」比「多看几个网站」好核对。
- 选上「自动记录检查点」规则，让记录由系统写，不只靠 agent 自己说。
- 选上「存文件」，让 agent 把结果存成文件；验收模型能读到产物摘录。
- 用网页的任务，验收模型选一个能看图的，它才能看截图。
- 看验收报告里每条的理由，缺什么就在技能或任务里写清楚要 agent 留下什么证据。
- 碰到验收争议时，用「补充说明后继续」告诉 agent 缺什么。

**agent 卡在验证码**

- 去「待办 → 等人处理」找「登录」卡，按 6.4 处理。
- 想少碰验证码：先用「打开 Chrome」登录好；每个账号并发设 1；配固定出口 IP 的代理；在技能里写明访问别太快。
- 简单的验证码（图片里的字母数字、「我不是机器人」）系统会先自己试着过，看运行过程里的「自动过验证码」几条就知道试了什么；老是认错，可以在「设置 → 浏览器 → 视觉模型」换一个更准的。滑块、短信码这类只能人来。

**agent 说「工具不在本任务允许的范围里」**

任务没选这个工具。编辑任务，在「用哪些 → 工具」里选上。技能里列了工具也一样要在任务里选。

**agent 没按技能做**

- 技能是不是「已发布」、任务里选了没有（选了技能，「读取技能」工具会自动带上）；
- 「什么时候用」那一句有没有写清楚，agent 只看这一句决定读不读。

**agent 读不到附件、交不出文件**

- 附件：「读附件」工具在有附件时自动带上。看运行详情「空间文件」里有没有这个文件，没有就是没传上。
- 交文件：任务要选「存文件」工具。

**建任务时提示「同一家」**

执行模型和验收模型（任务没选验收模型时用默认的）是同一家厂商。换一个。

**改了任务，正在跑的运行没变**

每次运行开始时会把任务当时的配置冻结下来，之后改任务只影响下一次运行。

**新建的技能、agent 提议的记忆，建任务时选不到**

技能要先「发布」；记忆要审核通过。

**删不掉记忆、规则、工具、技能**

正被任务（或规则、技能）用着。提示里会列出是谁在用，先在那些地方去掉。

**模型调用全部失败**

「模型」页看任务所用模型服务（OpenRouter 或直连的厂商）的状态，点「测试连接」。常见原因：key 被停用、余额不足、OpenRouter 或厂商那边的花费上限到了、服务器连不上外网。

**看不到某个按钮**

员工只能操作自己负责的任务和分给自己的事，配置页只能看。详情顶部会写「负责人是某某，你只能查看」。

## 8. 现在还做不到的

- 桌面软件自动化：推迟了，有具体要操作的软件时再加。
- 一个任务拆给多个 agent 并行：没有，一个 agent 按顺序做。
- Ollama（内网模型）：还没接，只能用 OpenRouter 或直连的云端厂商。
- 出口 IP 不会自动检测：「出口地」只是配置里写的一句话。
- 代理只能选不用代理或 SOCKS5。
- 远程画面：网页原生的文件选择框、浏览器的用户名密码弹框还不支持。
- 记忆不会按内容自动挑选，要建任务时手选。
- 「存文件」能存文本格式（csv、md、json、txt、py、js、ts、sh、sql、toml、ini 等）和 Excel（xlsx、xls）。Excel 只有内容和列宽：不能加粗、上色、冻结表头，不写公式；xls 最多 65536 行、256 列。上传的文件最多 20 MB（浏览器下载的不限）；文件不能在控制台里删除。
- 外部事件只按事件名匹配，带的数据不参与匹配。
- 会话页一次加载全部记录，运行多了以后会变慢。

## 9. 安全提醒

- **只在内网用**。v1 是 HTTP，账号密码和页面内容在网络上是明文。不要映射到外网。
- **密钥只写在密钥库里**：「工具 → 密钥」、MCP 的环境变量、模型的 API Key、代理密码。不要写进工具说明、技能、记忆、任务、规则里，这些都会给模型看。
- **对外动作配审批规则**：发消息、发邮件、花钱这类工具，风险选「对外发送」或「涉及金钱」，任务里选上对应的审批规则。用浏览器的任务按工具名写审批规则（见 5.6）。
- **网页内容不可信**：网页里可能藏着写给 AI 的话。agent 提议的记忆、尤其是「来自网页，可能不实」的，要仔细审；三方 AI 从运行里提取的任务记忆候选也一样；不需要时别开「允许在网页里执行脚本」；能用网址白名单就用。
- **浏览器账号用专用的**，不要用员工的个人账号，登录状态所有任务共用。
- **数据出境**：发给 OpenRouter 的任务内容、网页内容、截图会出境。特别敏感的任务先别跑。
- **人员变动**：离职的人当天在「用户」页停用；至少留两位主管。
